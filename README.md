# 郑州工业应用技术学院 · 校园综合服务平台

本科毕业设计工程，Java 后端、Vue 3 前端。学校公开资料与个人业务演示数据分开维护。

**当前进度：统一办理时间线（2026-10-16，V24），工程版本 0.1.0。** 学生在“我的办事”展开请假、证明、报修和调宿进度，核对真实节点、当前状态与下一步；历史分页核对申请版本。详见[时间线验收](docs/统一办理时间线验收-2026-10-16.md)。上一批见[导入验收](docs/初始住宿批量导入与校验验收-2026-10-16.md)。

 已实现官网、登录、本人学习查询、教师资料通知、教务教学维护、账号组织管理、实时权限、官网内容生命周期、教室资源、请假、证明及统一办事。在动态角色、有效指南及角色受限查询基础上，已实现请假和在校证明的可编辑预览、人工确认与本人草稿保存；DeepSeek 适配通过本地模拟契约测试和真实 API、浏览器验证。完整范围见[需求文档](docs/README.md)，模型配置见[Agent 接入](docs/Agent只读查询与DeepSeek接入验收-2026-10-09.md)，已支持本人历史提问、请假／证明暂存预览及原申请恢复，恢复验证见[会话与恢复验收](docs/Agent持久会话与任务恢复验收-2026-10-11.md)，可重复的 40 项固定场景见[回归与评测基线](docs/Agent固定场景回归与评测基线验收-2026-10-11.md)。

## 当前功能

- 官网：九个滚动章节、三图渐变轮播、半透明导航、独立内容详情页。
- 登录：数据库账号、BCrypt 密码、CSRF 校验、会话 ID 更新、退出登录。
- 学生门户：本人资料；我的学习含教学班资料、通知、周课表、已发布成绩与考试。
- 学生请假：本人草稿、提交、补交、撤回、私有材料和完整版本记录；负责行政班的辅导员通过、拒绝或退回，处理结果进入个人消息，通过后生成本人请假日程。
- 学生事务配置：管理员维护同学院辅导员与行政班负责关系，移交后待办、历史及材料访问随当前关系生效；普通教师和管理员不自动获得申请资料阅读权。
- 在校证明：本人登记资料确认、用途、草稿、补交、撤回和完整版本；当前学院学生事务人员核对、退回、拒绝或一次生成受控演示 PDF，关闭记录和生成快照保留。
- 我的办事：统一请假、证明、报修和调宿的本人概况、筛选、分页及业务入口；按需展开真实办理时间线、处理意见与下一步，翻页核对版本。服务入口使用图标、完整名称和说明。
- 个人消息：各岗位查询本人分页消息、已读筛选及全局未读数；请假、证明、报修与调宿通知提供当前仍有权限的申请入口，旧普通消息保留原文。
- 教师：本人授课班级、学生名单、授课课表、资料草稿发布撤下、受控附件下载与班通知。
- 教师编辑保护：按账号与教学班暂存未提交资料和通知，切换及刷新恢复文字；成功提交分别清理，退出登录清除；待上传附件刷新后须重新选择。
- 教务岗位：建立学期课程教学班、维护学院范围内人员关系、单次课程安排、成绩导入预览保存发布、考试草稿发布撤下。
- 内容管理：本人草稿、送审、驳回修改、撤回送审、独立审核发布、已发布内容更正和撤下；公开快照与工作稿分开，保留原因、操作者和版本全文，并保护未保存输入。
- 基础管理：账号筛选建档、资料与既有岗位维护、启停；学院部门、专业与行政班维护；关系约束、版本冲突保护和修改记录查询。
- 教室资源：管理员维护校区、楼栋房间、类型、两种容量和启停状态，查询未来占用及修改记录；教务从目录选择课程教室与考场，容量不足或资源停用时禁止新排，未结束占用保护资源状态及容量。
- 实时权限：停用、角色或归属变更后旧会话失效；禁止管理员停用自己或移除自身管理员身份；保留业务历史。
- Agent 首期：右下角动态角色、与身份及页面有关的提示、紧凑对话与可清除业务上下文；查有效版本指南、本人课表／已发布成绩考试／办事／未读数和当前岗位待办，复用实时权限与业务范围。
- DeepSeek 适配：模型只选择只读工具，本地生成事实卡和来源；本人业务结果及页面提取的申请编号留在本地。未配置时明确使用关键词查询，配置后每个问题由用户确认发送；查询失败不假报成功。
- AI 辅助请假：学生逐次补充明确字段或直接填写预览；复用请假规则核对，编辑后确认失效。用户确认后通过原接口保存本人草稿，再到原页面检查材料和手动提交。未保存预览有离开保护。
- AI 辅助证明：整理实际用途、读取本人登记资料、用户核对确认后保存草稿；编辑使确认失效，保存事务核对登记快照，资料变化需重新确认。原页面继续提交、学院审核及演示 PDF 下载。
- Agent 会话与恢复：本人历史、新建与切换；核对后暂存请假／证明字段，恢复时重新读取权限、指南及登记资料；同一对话内选择早先任务，已关联任务返回原申请最新状态。历史提问须手动重新查询，确认不恢复，重复保存不重复建档。
- Agent 真实评测：固定 40 条合成问法，生产模型规划与本地工具／预览执行；首轮 39 / 40，调整业务查询与指南的选择边界后 40 / 40，两轮安全案例均为 12 / 12。失败记录、Token、耗时和源码指纹保留，详见[真实模型评测验收](docs/Agent真实模型问法评测与提示优化验收-2026-10-12.md)。
- 校园报修：师生本人草稿、提交、补充、撤回及派单后取消；当前范围后勤派单、改派、拒绝、优先级，以及同意或驳回取消；维修接单、进展、交回、结果；本人按结果轮次验收、退回及一次评价。超过 48 小时未验收时提示并发送站内提醒，不自动完成。后勤可查看当前范围统计。私有图片、冻结结果、完整历史、版本与重复保护、通知和实际待办同步运行，教师使用独立本人入口。
- 报修 Agent：有效报修指南；本人、派单范围和当前维修任务只返回数量、状态和业务链接。`prepare_repair_fields` 只接收本次明确写出的类别、标题和现象。地点从当前开放目录选择，联系方式在本地填写。确认后保存本人草稿，恢复时重新鉴权；重复确认不重复建档。模型不派单、不完成维修、不代替验收。
- 报修配置：管理员维护明确关联的开放地点及后勤／维修范围，校验当前来源和人员资格，保留启停与修改记录；岗位人员查询本人职责。
- 住宿基础：管理员维护宿舍楼、房间、床位、维护状态和楼栋负责人，已有记录不能删除；宿管在当前有效楼栋登记初始入住和退宿；学生查看本人床位、负责人和历史，不查看其他住户。
- 调宿：学生提交原因、意向区域和材料说明；学院初审可退回、拒绝或通过；目标楼宿管预留空闲床位 72 小时，确认入住时一次切换床位。取消、到期或原住宿变化不会部分搬迁。未结束的调宿不能退宿。
- Three.js：按路由独立加载，旋转、缩放、建筑选择、高亮、搜索与相机定位。
- 宿舍关联报修：管理员关联宿舍房间；学生从本人当前住宿预选地点，沿用后勤派单、维修、验收与评价。入住变更后停止旧单维修操作；新住户不能读取原住户工单。
- 住宿助手：本人房间、最近调宿进度和当前申请查询；可编辑的调宿预览、逐次模型同意、刷新恢复和人工确认保存，入住或指南变化时要求重新核对。草稿在原调宿页面修改与提交。
- 调宿办事衔接：统一记录与状态统计、固定业务消息入口、当前权限与学院／楼栋复核；已离开待办队列的记录仍可按权限查看详情。
- 调宿材料：PDF、JPEG、PNG 私有上传与下载，草稿及待补交维护，提交冻结材料版本，保留历史附件与说明；宿管不读取附件。
- 初始住宿批量导入：本楼空闲床位 CSV 模板、逐行校验与 15 分钟预览、手动整批确认、重复提交保护、服务器历史回执和住宿来源批次；变更或冲突时整批回滚。
- Flyway 迁移与可持久化本地数据库。

账号、课程、成绩、考试、证明及办理指南均为演示记录，不连接学校业务系统。证明文件不具备学校正式证明效力。预约、Agent 自动提交审批、会话删除和知识管理尚未实现。住宿资源、初始入住、退宿和调宿切换已实现。报修主流程、派单后取消、后勤统计、48 小时待验收提醒，以及受确认约束的报修查询和草稿辅助已实现。

## 本地启动

在两个 PowerShell 终端分别执行。

后端：

```powershell
cd D:\GraduationProject\backend
mvn spring-boot:run
```

前端：

```powershell
cd D:\GraduationProject\frontend
pnpm install --frozen-lockfile
pnpm run dev
```

访问 **http://127.0.0.1:5173/**。后端为 `127.0.0.1:8080`，Vite 代理 `/api` 至后端，在前端地址完成登录。两终端按 Ctrl+C 停止。开发服务器仅绑定本机。

也可使用 `scripts/Start-Backend.ps1`、`scripts/Start-Frontend.ps1`；首次安装前端依赖后再运行启动脚本。后端脚本会读取当前 Windows 用户已保存的 DeepSeek 加密凭据；前端脚本支持 `-Port` 参数，默认 5173。

若 Windows 保留端口范围包含 8080，后端启动终端可先设置 `$env:SERVER_PORT = '18080'`；前端启动终端对应设置 `$env:CAMPUS_API_TARGET = 'http://127.0.0.1:18080'`。默认仍使用 8080，无需更改系统端口保留规则。

若 5173 也被占用，前端执行 `pnpm run dev --port 18090`，或在根目录执行 `./scripts/Start-Frontend.ps1 -Port 18090`。本轮运行地址为 **http://127.0.0.1:18090/**，代理后端 18080；默认配置未改动。

2026-10-16 当前运行使用根目录 `data/campus.mv.db`（V24）。另有较旧的 `backend/data/campus.mv.db`（V14）保留，直接依赖相对工作目录会打开不同库。请按[本次验收的启动说明](docs/初始住宿批量导入与校验验收-2026-10-16.md#5-主库与运行)显式指定数据源。

体验发布：`editor` 新建演示草稿并送审，退出后用 `reviewer` 驳回或审核发布，再点击“查看官网公开页面”。发布后编辑可创建更正稿，重新审核前官网继续显示原版；审核人员可填写原因撤下。管理员也不能审核自己的草稿，历史全文在“操作与版本记录”查看。

体验教学：`teacher1001` 在“我的教学”保存并发布 Java 课程资料与通知，`20260001` 在“我的学习”查看；`20260002` 不属于该 Java 教学班。`academic1001` 在教务维护中校验成绩、保存草稿、发布成绩或考试，普通教师和管理员不能代替该岗位操作。

体验基础管理：`admin` 登录管理员首页，进入“账号与组织管理”，维护人员、组织目录或查看修改记录。角色或归属变更后相关人员需重新登录；初始密码只在建档时输入。组织引用和有效教学关系会限制归属调整，详见[基础管理验收](docs/账号组织与实时权限验收-2026-10-06.md)。

体验教室资源：`admin` 进入“教室资源目录”，核对楼栋、房间、教学容量和考试容量后保存，`academic1001` 在课程或考试安排中选择。原库 6 条旧地点已迁移为待补录记录，不推测真实建筑与容量；空库另提供明确标记的演示教室。详见[教室资源验收](docs/教室资源与教学占用验收-2026-10-08.md)。

体验住宿：`admin` 在“宿舍资源”建立演示宿舍楼、房间和床位，并把楼栋交给 `dorm1001`。宿管在“住宿办理”按完整学号查找学生并登记入住；学生在“我的住宿”只看到本人床位和本楼宿管。退宿后床位释放，历史保留退宿当时的地点名称。主库不自动添加宿舍楼。学生可申请调宿，经学院初审后由宿管预留床位并确认入住。管理员再在“报修配置”关联宿舍房间，学生即可从当前住宿进入报修，详见[宿舍报修验收](docs/宿舍关联报修与入住权限验收-2026-10-15.md)。

体验校园报修：`admin` 在“报修配置”核对并开放地点，配置有效后勤和维修范围。学生或教师在“我的校园报修”保存资料及图片、确认提交；`dispatcher1001` 分诊派单，`technician1001` 接单处理并反馈结果；报修人核对后确认完成、评价。已派单后可申请取消，待处理期间维修和验收暂停。后勤在“报修统计”查看当前范围；待验收超过 48 小时会提示并写入个人消息，状态仍待本人确认。可从消息或学生“我的办事”返回原工单。主库不自动添加地点，演示地点须明确标记；详见[主流程验收](docs/校园报修主流程验收-2026-10-12.md)和[跟进验收](docs/校园报修取消统计与提醒验收-2026-10-12.md)。

体验学生请假：`20260001` 从“我的办事”进入请假，新建未来时间的草稿并提交，`counselor1001` 在“班级请假处理”填写意见退回补交，学生修改后重新提交；辅导员通过后生成学生本人的日程。管理员在“辅导员负责班级”配置同学院负责人员。初始辅导员只负责演示 1 班，初始化不覆盖后续修改；最多 30 天、可选 PDF / TXT 材料是演示设置，真实制度和销假变更尚未接入。详见[请假办理验收](docs/学生请假与辅导员处理验收-2026-10-08.md)。

体验证明与消息：`20260001` 在“我的办事”选择“在校证明申请与下载”，填写用途、确认登记资料，保存后提交；`affairs1001` 在“学院证明申请处理”填写意见退回或生成演示证明。学生从个人消息直达原申请，补交后重新确认并提交，完成后下载带演示标记的 PDF；统一办事列表保留请假和证明的各自状态及历史。审核岗位按学院授权，教师、管理员和通用服务身份不能代替。当前只支持线上下载，详见[证明与办事验收](docs/证明办理与我的办事验收-2026-10-09.md)。

### 切换 MySQL

2026-10-12 已在本机 Docker 的 MySQL 8.4 上完成验证。实例只绑定 127.0.0.1:3307，库名 `campus`，应用用户 `campus_app`。使用 mysql 配置、关闭演示初始化，空库执行 V1–V15，15 个版本均为成功；临时服务在 18082 返回健康检查后已停止，容器可以继续运行。Flyway 11.14.1 提示 MySQL 8.4 新于其已验证的 8.1，迁移仍然完成。第一次启动时，MySQL 8.4 保存的状态检查字面量与 H2 不同，V15 未能识别原约束；修正识别后重建空库再次迁移成功。日常开发仍使用本地 H2。不要把数据库密码写入仓库。

复制 `infra/.env.example` 为 `infra/.env`，填写数据库密码，启动 Docker 引擎，然后在根目录执行：

```powershell
docker compose --env-file infra/.env -f infra/compose.yml up -d
```

在后端终端设置与 `infra/.env` 相同的应用数据库密码：

```powershell
cd D:\GraduationProject\backend
$env:SPRING_PROFILES_ACTIVE = 'mysql'
$env:CAMPUS_DB_PASSWORD = '<你填写的应用数据库密码>'
$env:DEMO_SEED_ENABLED = 'true'
mvn spring-boot:run
```

本机端口 3307，数据库 `campus`，应用用户 `campus_app`。mysql 默认关闭演示初始化，上述开关只用于本地联调。回到 H2 时使用新终端按“本地启动”操作，或移除当前终端的 `SPRING_PROFILES_ACTIVE`。

2026-10-16 本机 3306 (MySQL 8.0) 已在独立验收库 `campus_acceptance` 上完成 Flyway V1–V24 全量迁移及 14 个演示账号播种验证，健康检查正常返回 UP。日常开发仍使用本地 H2 文件库。若切换 MySQL，配置支持 `CAMPUS_DB_URL`、`CAMPUS_DB_USERNAME` 和 `CAMPUS_DB_PASSWORD`。详见[MySQL 验收](docs/MySQL全量迁移与验收-2026-10-16.md)。
