## 当前功能

- 财务与演示缴费：学生 `/portal/payments` 查看和支付本人已发布账单；财务经办与复核在 `/finance/payments` 分工维护项目、价格、宿舍表计及账单；教务、宿管、后勤通过 `/payment-bases` 提交业务依据。支持批量建单预览、作废／减免／退款申请、CSV 导出、演示收据 PDF 和对账差异跟踪。支付支持进程内 IJPay 与独立 pay-service 双通道。财务接口受 `app.demo.enabled` 门控，MySQL 配置默认不开放演示；真实沙箱全链路与生产收款未完成验收。[支付配置](docs/支付宝沙箱演示缴费接入-2026-10-30.md)
- 官网：九个连续滚动章节、双图校园影像、章节目录、阅读进度、减少动态设置，以及保留来源章节的内容详情页。
- 登录：数据库账号、BCrypt 密码、CSRF 校验、会话 ID 更新、退出登录。
- 学生门户：本人资料；我的学习含教学班资料、通知、周课表、已发布成绩与考试。
- 学生请假：本人草稿、提交、补交、撤回、私有材料和完整版本记录；负责行政班的辅导员通过、拒绝或退回，处理结果进入个人消息，通过后生成本人请假日程；学生返校申报、辅导员确认销假或退回核对，确认后按返校时间结束日程。
- 学生事务配置：管理员维护同学院辅导员与行政班负责关系，移交后待办、历史及材料访问随当前关系生效；普通教师和管理员不自动获得申请资料阅读权。
- 在校证明：本人登记资料确认、用途、草稿、补交、撤回和完整版本；当前学院学生事务人员核对、退回、拒绝或一次生成受控演示 PDF，关闭记录和生成快照保留。
- 我的日程：汇总本人课程、已发布考试、已批准及已销假请假、有效预约；按周、类型和日期查看，提示个人时间重叠，链接原业务。来源失败明确报错，不将失败显示成空日程。
- 我的办事：统一请假、证明、报修、调宿和预约的本人概况、筛选、分页及业务入口；按需展开真实办理时间线、处理意见与下一步，翻页核对版本。服务入口使用图标、完整名称和说明。
- 个人消息：各岗位查询本人分页消息、已读筛选及全局未读数；请假、证明、报修与调宿通知提供当前仍有权限的申请入口，旧普通消息保留原文。
- 教师：本人授课班级、学生名单、授课课表、资料草稿发布撤下、受控附件下载与班通知。
- 教师编辑保护：按账号与教学班暂存未提交资料和通知，切换及刷新恢复文字；成功提交分别清理，退出登录清除；待上传附件刷新后须重新选择。
- 教务岗位：建立学期课程教学班、维护学院范围内人员关系、单次课程安排、成绩导入预览保存发布、考试草稿发布撤下。
- 内容管理：本人草稿、送审、驳回修改、撤回送审、独立审核发布、已发布内容更正和撤下；公开快照与工作稿分开，保留原因、操作者和版本全文，并保护未保存输入。
- 基础管理：账号筛选建档、资料与既有岗位维护、启停；学院部门、专业与行政班维护；关系约束、版本冲突保护和修改记录查询。
- 岗位交接：账号列表查看负责范围与独有待办，正常停用及岗位权限移除前保护交接；紧急停用立即撤权并保留历史，责任异常按当前有效人员汇总且按域权限进入配置。
- 教室资源：管理员维护校区、楼栋房间、类型、两种容量和启停状态，查询未来占用及修改记录；教务从目录选择课程教室与考场，容量不足或资源停用时禁止新排，未结束占用保护资源状态及容量。预约场地与教学教室须人工确认后显式关联，关联后共用课程／考试／预约冲突校验与占用列表；未关联资源不自动推断。
- 实时权限：停用、角色或归属变更后旧会话失效；禁止管理员停用自己或移除自身管理员身份；保留业务历史。
- Agent 首期：右下角动态角色、与身份及页面有关的提示、紧凑对话与可清除业务上下文；查有效版本指南、本人课表／已发布成绩考试／办事／未读数和当前岗位待办，复用实时权限与业务范围。
- Agent 日程与预约：学生本人日／周日程、本人预约列表及详情、按校区／人数／日期时段查询空闲场地；复用课程、考试和预约占用校验，检查有效审批负责人及关联教室。结果为查询快照，点击后带入条件并重新检查；不自动创建、提交或审批预约。
- AI 缴费查询：本人账单和待缴金额、收费依据、支付状态、宿舍水电单价与充值报价，以及财务对账待办；复用原业务权限与计价规则，不代付、不退款。
- AI 多事项与连续追问：本地合并至多四类不同查询，条件冲突时要求拆分；补充充值种类、金额或用量，恢复历史账单关联，原始业务结果和历史对话留在本地。
- Agent 默认对话：连接 DeepSeek 并勾选本次发送后，直接说明查询或办理目标。模型选择只读工具或 `start_goal` 开始自主办理，不必先点“自主办理”。本地模式只查询；办理问法会提示改用 DeepSeek。
- Agent 自主办理：支持预约、报修、请假、在校证明的多事项计划、工具选择、缺项追问、原申请核验和提交后跟踪。资料齐全时按本次发送确认自动保存；目标为提交／跟踪时继续提交。联系方式可用账号默认值；报修地点、模糊时间不会猜测。不审批、不支付、不办他人申请。新建账号须具备学院、班级、辅导员或学院事务人员等原业务资格。
- Agent 单项任务：助手中的“单项任务”保留逐步确认的本地草稿流程，正式提交仍可在原页面操作。
- DeepSeek 适配：查询模式选择只读工具；办理时可选 `start_goal` 进入目标循环。本地生成事实卡和来源，登记身份和私人联系方式不自动送入模型。未配置时使用本地查询，模型调用前须确认发送；失败不假报成功。
- AI 辅助请假：学生逐次补充明确字段或直接填写预览；复用请假规则核对，编辑后确认失效。用户确认后通过原接口保存本人草稿，再到原页面检查材料和手动提交。未保存预览有离开保护。
- AI 辅助证明：整理实际用途、读取本人登记资料、用户核对确认后保存草稿；编辑使确认失效，保存事务核对登记快照，资料变化需重新确认。原页面继续提交、学院审核及演示 PDF 下载。
- Agent 会话与恢复：本人历史、新建、切换与删除；删除对话只清除本人对话、历史提问和准备任务，不取消已保存的业务申请；核对后暂存请假／证明字段，恢复时重新读取权限、指南及登记资料；同一对话内选择早先任务，已关联任务返回原申请最新状态。历史提问须手动重新查询，确认不恢复，重复保存不重复建档。
- Agent 真实评测：固定 40 条合成问法，生产模型规划与本地工具／预览执行；首轮 39 / 40，调整业务查询与指南的选择边界后 40 / 40，两轮安全案例均为 12 / 12。失败记录、Token、耗时和源码指纹保留，详见[真实模型评测验收](docs/Agent真实模型问法评测与提示优化验收-2026-10-12.md)。
- 校园报修：师生本人草稿、提交、补充、撤回及派单后取消；当前范围后勤派单、改派、拒绝、优先级，以及同意或驳回取消；维修接单、进展、交回、结果；本人按结果轮次验收、退回及一次评价。超过 48 小时未验收时提示并发送站内提醒，不自动完成。后勤可查看当前范围统计。私有图片、冻结结果、完整历史、版本与重复保护、通知和实际待办同步运行，教师使用独立本人入口。
- 报修 Agent：有效报修指南；本人、派单范围和当前维修任务只返回数量、状态和业务链接。`prepare_repair_fields` 只接收本次明确写出的类别、标题和现象。地点从当前开放目录选择，联系方式在本地填写。确认后保存本人草稿，恢复时重新鉴权；重复确认不重复建档。模型不派单、不完成维修、不代替验收。
- 报修配置：管理员维护明确关联的开放地点及后勤／维修范围，校验当前来源和人员资格，保留启停与修改记录；岗位人员查询本人职责。
- 住宿基础：管理员维护宿舍楼、房间、床位、维护状态和楼栋负责人，已有记录不能删除；宿管在当前有效楼栋登记初始入住和退宿；学生查看本人床位、负责人和历史，不查看其他住户。
- 调宿：学生提交原因、意向区域和材料说明；学院初审可退回、拒绝或通过；目标楼宿管预留空闲床位 72 小时，确认入住时一次切换床位。取消、到期或原住宿变化不会部分搬迁。未结束的调宿不能退宿。
- Three.js：按路由独立加载，旋转、缩放、建筑选择、高亮、搜索与相机定位。
- 宿舍关联报修：管理员关联宿舍房间；学生从本人当前住宿预选地点，沿用后勤派单、维修、验收与评价。入住变更后停止旧单维修操作；新住户不能读取原住户工单。
- 住宿助手：本人房间、最近调宿进度和当前申请查询；可编辑的调宿预览、逐次模型同意、刷新恢复和人工确认保存，入住或指南变化时要求重新核对。草稿在原调宿页面修改与提交。
- 调宿办事衔接：统一记录与状态统计、固定业务消息入口、当前权限与学院／楼栋复核；已离开待办队列的记录仍可按权限查看详情。
- 调宿材料：PDF、JPEG、PNG 私有上传与下载，草稿及待补交维护，提交冻结材料版本，保留历史附件与说明；宿管不读取附件。
- 初始住宿批量导入：本楼空闲床位 CSV 模板、逐行校验与 15 分钟预览、手动整批确认、重复提交保护、服务器历史回执和住宿来源批次；变更或冲突时整批回滚。
- Flyway 迁移与可持久化本地数据库。

账号、课程、成绩、考试、证明及办理指南均为演示记录，不连接学校业务系统。证明文件不具备学校正式证明效力。场地预约的申请、审核、使用登记、结束核销、过期及凭证已实现；多件设备库存领还、Agent 代替审批、代付和知识管理尚未实现。住宿资源、初始入住、退宿和调宿切换已实现。报修主流程、派单后取消、后勤统计、48 小时待验收提醒已实现。Agent 可在资料齐全时保存并提交本人四类申请，不能代替岗位审批。

## 本地启动

在两个 PowerShell 终端分别执行。

后端：

```powershell
cd D:\GraduationProject\backend
mvn spring-boot:run
```

前端：

```powershell
cd D:\GraduationProject\frontend
pnpm install --frozen-lockfile
pnpm run dev
```

访问 **http://127.0.0.1:5173/**。后端默认为 `127.0.0.1:7080`，Vite 代理 `/api` 至该后端，在前端地址完成登录。先等待后端 `/api/health` 返回 `{"status":"UP"}`，再打开需要登录的页面。两终端按 Ctrl+C 停止。开发服务器仅绑定本机。

也可使用 `scripts/Start-Backend.ps1`、`scripts/Start-Frontend.ps1`；首次安装前端依赖后再运行启动脚本。后端脚本会读取当前 Windows 用户已保存的 DeepSeek 加密凭据；前端脚本支持 `-Port` 参数，默认 5173，并等待后端健康检查就绪（默认最多 45 秒，可用 `-BackendWaitSeconds` 调整）。只做前端页面开发时，可显式传入 `-SkipBackendCheck`。服务启动期间进入“服务暂不可用”后，点击“重新连接”即可重新核验会话并恢复原页面。

若默认后端端口 7080 被占用，后端启动终端可先设置 `$env:SERVER_PORT = '18080'`；前端启动终端对应设置 `$env:CAMPUS_API_TARGET = 'http://127.0.0.1:18080'`。两侧端口需一致，无需更改系统端口保留规则。

若 5173 也被占用，前端执行 `pnpm run dev --port 18090`，或在根目录执行 `./scripts/Start-Frontend.ps1 -Port 18090`。此前 18090 → 18080 为临时验收地址；当前默认使用 5173 → 7080。

默认本地配置使用相对路径 `./data/campus`，从仓库根目录和 `backend` 启动会打开不同库。库版本以当前 Flyway 日志为准；10 月 16 日的 V24／V14 是当时记录。10 月 30 日界面预览使用 `artifacts/cinema-preview/campus` 隔离库。新演示请按[显式演示数据源启动说明](docs/答辩演示路线与启动说明-2026-10-30.md)指定路径，避免误用日常库。

### IDEA、支付配置与数据位置

local 环境会自动读取仓库根目录启动时的 `backend/.env.local`，或从 `backend` 启动时的 `.env.local`；实际环境变量优先。独立支付服务需要 `PAYMENT_ENABLED`、`PAYMENT_CHANNEL`、`PAYMENT_REMOTE_URL` 和 `PAYMENT_REMOTE_TOKEN`，具体配置见[支付接入说明](docs/支付宝沙箱演示缴费接入-2026-10-30.md)。修改后重新运行后端。

IDEA 的工作目录应与命令行保持一致。已有数据时，先确认原数据库绝对路径，保持原工作目录或显式设置 `SPRING_DATASOURCE_URL`，避免打开另一份空库。仓库不包含本机演示数据库、密钥或临时验收数据。

IDEA 直接运行不会执行 PowerShell 启动脚本。DeepSeek 模式仍需提供对应环境变量；Windows 加密凭据的自动读取由 `scripts/Start-Backend.ps1` 完成。本地助手查询不需要模型密钥。

### 切换 MySQL

2026-10-12 已在本机 Docker 的 MySQL 8.4 上完成验证。实例只绑定 127.0.0.1:3307，库名 `campus`，应用用户 `campus_app`。使用 mysql 配置、关闭演示初始化，空库执行 V1–V15，15 个版本均为成功；临时服务在 18082 返回健康检查后已停止，容器可以继续运行。Flyway 11.14.1 提示 MySQL 8.4 新于其已验证的 8.1，迁移仍然完成。第一次启动时，MySQL 8.4 保存的状态检查字面量与 H2 不同，V15 未能识别原约束；修正识别后重建空库再次迁移成功。日常开发仍使用本地 H2。不要把数据库密码写入仓库。

复制 `infra/.env.example` 为 `infra/.env`，填写数据库密码，启动 Docker 引擎，然后在根目录执行：

```powershell
docker compose --env-file infra/.env -f infra/compose.yml up -d
```

在后端终端设置与 `infra/.env` 相同的应用数据库密码：

```powershell
cd D:\GraduationProject\backend
$env:SPRING_PROFILES_ACTIVE = 'mysql'
$env:CAMPUS_DB_PASSWORD = '<你填写的应用数据库密码>'
$env:DEMO_SEED_ENABLED = 'true'
mvn spring-boot:run
```

本机端口 3307，数据库 `campus`，应用用户 `campus_app`。mysql 默认关闭演示初始化，上述开关只用于本地联调。回到 H2 时使用新终端按“本地启动”操作，或移除当前终端的 `SPRING_PROFILES_ACTIVE`。

MySQL 8.0.34 隔离环境已完成 V1–V36 空库迁移及后续 V37–V41 分阶段升级，最新升级验证保留原账单和对话数据；这不等于已完成生产迁移或 MySQL 8.4 最新版本验证。MySQL profile 默认 `DEMO_SEED_ENABLED=false`，同时不开放演示财务功能；仅演示环境按需显式开启。数据库密码及支付凭据保存在本地环境配置中，不提交仓库。

## 验证与工程入口

演示前可执行 `./scripts/Test-DemoReadiness.ps1 -FrontendPort 18090 -BackendPort 18080` 检查工具、依赖与当前预览 HTTP；不访问运行服务时加 `-SkipServices`。默认端口为 5173／7080。脚本只读检查并输出本地 JSON，不启动服务、不读取模型凭据或写业务数据；它不代替工程测试与[待完成的浏览器验收](docs/界面统一待验收与证据索引-2026-10-30.md)。

Agent 固定回归可单独执行 `./scripts/Evaluate-Agent.ps1`，不需要开发服务；新目录输出 40 项分类、源码指纹与可读报告，失败返回非零。模型使用受控替身，这一通过率不代表真实模型准确率；定义见 [.Codex/evals/agent-v1.md](.Codex/evals/agent-v1.md)。评分器的 14 项检查已接入 `Verify.ps1`。

真实模型评测单独运行 `./scripts/Evaluate-AgentLive.ps1`，会调用 DeepSeek 并产生用量；使用项目外加密凭据、独立内存数据库与每条一次请求，输出到 `output/agent-live-evals/` 的新目录。案例与标准见 [.Codex/evals/agent-live-v1.md](.Codex/evals/agent-live-v1.md)。报修问法使用独立的 `./scripts/Evaluate-AgentRepairLive.ps1` 和 [.Codex/evals/agent-repair-live-v1.json](.Codex/evals/agent-repair-live-v1.json)，16 条，不并入原来的 40 条，输出到 `output/agent-repair-live-evals/`。`Verify.ps1` 不运行这两个真实模型入口，也不读取模型凭据。

常规检查：后端 `mvn -B package`；前端 `pnpm test`、`pnpm run lint`、`pnpm run build`。也可在根目录执行 `./scripts/Verify.ps1`，依次检查脚本、后端和前端，失败即停止。最近全量结果见本页顶部；各历史验收数字仅代表对应批次。CI 对后端、前端、pay-service 及 PowerShell 脚本分别执行检查。Windows 使用打包 JAR 运行后端时，应先停止该进程再重新打包，避免文件占用。
