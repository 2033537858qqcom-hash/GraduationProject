# Agent 任务执行循环与预约闭环（2026-11-01）

本阶段新增独立的持久任务执行器，将一次性查询扩展为“观察 → 决定下一步 → 执行工具 → 保存观察 → 继续或等待用户”的任务循环。第一条完整业务路径是查找场地并准备本人预约草稿。

## 使用方法

1. 在 IDEA 重新运行 `CampusApplication`，启动时应用 V42，然后刷新前端。
2. 学生打开右下角助手，选择 **Agent任务**。本地任务流程不需要模型密钥；选择 **DeepSeek动态规划** 时，需要模型已配置，并确认本次目标和后续脱敏观察的发送授权。
3. 输入目标，例如“2026-11-08东校区30人09:00-11:00，帮我准备教室预约草稿”。实际测试时使用未来时间。也可只描述“下周二下午找30人的教室”，Agent 会要求补齐校区和明确时段，不默认下午的起止时间。
4. 在本地条件中填写活动主题、类型及按需填写的联系方式。联系方式与候选场地正文不发送给模型；用户自行写入目标的文字按已确认目标发送。
5. Agent 检查本人日程、查找场地。发现冲突或没有候选时，返回可读提示，修改条件后继续规划；有候选时等待用户选择。
6. 选择场地后，Agent 再次核对条件，展示草稿预览；勾选本人确认后保存草稿，再读取原预约记录核验，最后显示任务完成。
7. 通过原预约申请入口补充资料、手动提交，正式预约仍需有效负责人审核。任务完成表示草稿已保存并核验，不表示预约已获批准。

## 执行结构

| 层次 | 职责 |
| --- | --- |
| `AgentMissionService` | 持久任务、执行租约、版本与请求重试、单步规划、人工等待点、执行预算和恢复 |
| `DeepSeekClient.nextMissionStep` | 每次接收目标、允许动作及累计脱敏观察，选择一个下一步工具；实际结果返回后再规划下一步 |
| `AgentMissionTools` | 调用日程、场地、冲突和预约服务；重新核验权限、资源版本、价格无关的预约条件与原申请结果 |
| `AssistantMission.vue` | 目标输入、条件表单、执行记录、候选选择、确认预览、取消、刷新与中断恢复 |
| V42 | 新增 `agent_mission` 与 `agent_mission_step`；原查询、历史对话及业务表保留 |

正常路径为：`check_schedule → find_venues → present_options → prepare_reservation → save_reservation → verify_reservation → finish`。模型可以先查询场地再检查日程；后端根据执行观察和用户授权限制当前允许的动作。缺条件、冲突、无候选、场地变化、模型超时分别产生暂停或重新规划状态。

本地任务流程执行同一状态机，由本地策略选择下一步；DeepSeek模式逐步调用模型。当前支持的是预约业务 Agent，不是能够任意跨模块操作的通用自主 Agent。

## 可靠性与边界

- 所有任务、步骤与原申请关联持久化，可在本人原会话中恢复。模型请求期间不持有数据库写事务。
- 每轮最多 6 步，轮间检查 60 秒执行预算，单次模型请求仍有网络超时；任务总计最多 24 步。到达预算暂停，用户显式继续；执行租约超过 90 秒未更新时显示中断状态，可恢复。预算在步骤边界检查，不代表对任一数据库调用的强制终止。
- 同一创建或操作请求的重试返回已有状态，不能重复取得同一执行租约。历史版本、候选标识和确认摘要防止旧页面覆盖新状态。
- 保存前再次检查日程、场地启停／版本／容量／审批人员、资源可用性和时段冲突。条件变化后清除确认，要求修改并重新规划。
- 只有当前后端允许的无参数动作可执行；模型自行添加身份、资源编号或直接选择未授权写入动作会失败并记录。每一步重新核对当前账号权限。
- 模型观察只包含动作名、状态、数量和缺失字段；不包含日程标题、联系方式、身份资料、场地正文或历史聊天。记录的是可核验的执行步骤，不保存模型隐式推理内容。
- 取消会阻止后续步骤；若草稿已经保存，草稿保留并提供原业务入口。正在执行的任务会保护父会话，删除前需先取消或等待结束。
- 本轮不自动提交预约，不审批、支付或退款；并发占用仍需原预约提交接口最终核验。
