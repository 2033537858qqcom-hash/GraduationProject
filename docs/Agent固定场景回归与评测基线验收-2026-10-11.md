## 实际交付

将已实现的 Agent 行为整理为固定 40 项回归场景，逐项指定验收标准和现有 Java 集成测试方法。定义和通过标准先于执行脚本保存；案例不是从本轮输出自动生成。可用 `./scripts/Evaluate-Agent.ps1` 重复运行，无需启动前后端。

每项复用真实 HTTP、认证、业务服务和独立 H2 数据库中的断言。模型部分使用受控替身，检查合法规划、字段边界、超时和恢复契约；不会读取保存的加密凭据，也不会调用外部模型。40 项是现有 161 项后端测试中的固定子集，不作为新增 40 项测试累计。

## 执行与报告

机器定义位于 `.Codex/evals/agent-v1.json`，说明位于 `.Codex/evals/agent-v1.md`。运行前检查场景数量、唯一编号、唯一判定器及代码方法是否存在。Maven 的 `agent-eval` 配置仅影响本次测试，禁止失败后自动重跑，使用新建的独立 JUnit 目录。普通构建和测试报告目录保持原行为。

每次报告位于 `output/agent-evals/<UTC 时间及随机编号>/`：`report.md` 为可读结果，`report.json` 含分类、每项状态和耗时、案例 SHA-256、源码指纹、运行时间及模式；同目录保留本次 Maven 日志和四份 JUnit XML。自动生成的目录已忽略，案例定义和精简基线保留在源码中。

全部场景必须执行并通过；构建非零、跳过、缺项、重复项、额外结果或 XML 错误均使整体不通过并返回非零退出码。XML 读取禁止 DTD 和外部实体，报告不复制问题、表单、登记内容或密钥。失败详情只留在本次本地测试日志，摘要列出失败场景与判定器。

评分器的 14 项检查覆盖成功、断言失败、跳过、运行异常、无效耗时、缺项、重复结果、构建失败、额外结果、破损 XML、DTD、重复案例编号、数量减少和无结果。`scripts/Verify.ps1` 已接入这些检查；完整项目回归仍包含所有后端和前端测试，固定 Agent 回归单独执行，避免把子集重复累计。

精简首次验收基线见 `.Codex/evals/agent-v1.baseline.json`；对应的完整报告路径和来源指纹也记录其中。仅当前运行结果满足标准才会生成成功，不借用这份基线填补本轮失败或缺项。
