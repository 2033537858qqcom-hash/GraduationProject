# Agent 多业务分流与报修执行（2026-11-01）

V43 将持久任务执行器扩展为预约、报修两类任务。明确目标按业务关键词选择类型，用户也可手动选择；同时要求报修和预约的混合目标会提示分别办理。任务类型在创建时确定，修改条件不会更换任务域。

## 使用

1. 在 IDEA 重新运行 `CampusApplication`，应用 V43，刷新前端。
2. 学生或教师打开助手的 **Agent任务**，输入“帮我准备报修草稿”，页面切换为报修资料；任务类型也可明确选择“报修草稿”。
3. 开始任务后，读取本人当前可用的报修地点目录。补齐故障类别、标题、实际现象、地点和联系方式，再点击“更新条件并重新规划”。地点目录在本面板展示当前首批至多 50 个开放地点，完整业务目录及其他操作仍在原报修页面。
4. Agent 依次核对资料与有效指南、检查当前地点权限、生成预览；缺项或规则不满足时提示修改。
5. 核对预览并勾选本人确认，Agent 保存报修草稿，读取原工单核验字段和状态，然后结束任务。
6. 点击“打开原报修工单”，补充图片并手动提交，后续由后勤分诊处理。任务完成仅表示草稿已保存并核验。

教师拥有 `repair:apply` 时可直接使用报修任务，无需学生 `portal:read` 权限。预约任务仍要求预约与门户权限，管理员不会因管理身份自动获得报修写入能力。

## 执行机制

- 共用 V42 的持久执行循环、步骤记录、租约、版本控制、重试、取消和预算。报修域适配器 `AgentRepairMissionTools` 复用 `AgentRepairDrafts`、`RepairSettingsService` 与 `RepairService`。
- 报修的六步正常路径：`check_repair_requirements → inspect_repair_location → prepare_repair → save_repair → verify_repair → finish`。缺项追问另计一步；多次修订也会追加步骤。
- `check_repair_requirements` 校验类别、描述、联系方式和当前有效指南；`inspect_repair_location` 核对开放状态与本人范围；`prepare_repair` 重新核验并生成确认摘要。
- 确认摘要包含全部报修字段及选定地点资料。修改联系方式、描述或地点等字段会使页面确认失效；保存前再次核对。地点版本或开放状态变化时，要求修改并重新核对，不能沿用旧预览写入。
- `save_repair` 仅在本人明确确认后开放。`verify_repair` 读取本人原工单，逐项核对故障字段、地点、联系方式及 `DRAFT` 状态；不覆盖之后发生的业务修改。
- 模型只接收本次已授权目标、当前允许动作和脱敏观察（动作名、状态、缺失字段及数量）。本地表单内的联系方式、故障正文、地点名称不会作为执行观察发送；用户自行写入目标的内容仍属于发送目标。
- 当前允许动作按任务域生成，预约动作不能混入报修任务；未知动作或额外参数会拒绝执行并保留记录。任务列表按当前岗位权限过滤，详情和每步操作继续检查本人会话及业务权限。
- 本阶段没有自动提交、派单、维修、验收或跨用户写入。原“准备报修”辅助表单与新执行循环并存，原查询功能保持兼容。
