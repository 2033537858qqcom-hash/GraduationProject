# 报修 Agent 查询与草稿确认验收

验收日期：2026-10-13。数据库迁移 V16。对应[报修设计](./校园报修需求与开发设计-v0.1.md)第 11 节。

本批在已完成的报修业务上接入助手。师生可查本人进度，后勤可查当前派单范围，维修人员可查当前分配。结果只含数量、状态、公开地点和业务链接，不返回联系方式、图片或故障说明。字段预览只接收本次文字明确写出的类别、标题和现象。地点必须从当前开放目录选择，联系方式在本地填写。用户核对后只保存普通草稿；提交、派单、维修和验收仍在原页面办理。

## 1. 接入边界

新增上下文 `REPAIR_MINE`、`REPAIR_DISPATCH`、`REPAIR_WORK`，以及任务种类 `REPAIR`。没有把报修塞进原有的请假／证明工具或 `my_affairs`。教师使用 `my_repairs`，不依赖学生的 `portal:read`。后勤和维修岗位沿用 V13 已授予的 `agent:query`。

恢复任务时重新读取当前身份、指南和开放地点。编辑使确认失效。同一任务重复确认返回原草稿，不重复建档。地点停用或指南撤下后，预览不再允许保存。

模型工具 `prepare_repair_fields` 只能返回类别、标题和现象。地点编号、联系方式、状态或其他字段会被拒绝，原预览保留。本地查询遇到“帮我派单”或查询其他同学报修时直接拒绝，不执行工具。

既有 Agent 查询、请假辅助、证明辅助、持久会话和 DeepSeek 契约测试通过。前端 53 项测试通过，变更文件的类型检查和 lint 通过。V16 在这些 H2 测试中成功应用。
