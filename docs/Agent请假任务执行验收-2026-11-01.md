# Agent 请假任务执行（2026-11-01）

V44 将请假接入持久 Agent 执行循环，在预约、报修基础上增加第三类任务。沿用现有请假规则、办理资格和原申请服务，不替代辅导员审核。

## 使用方法

1. 在 IDEA 重新运行 `CampusApplication`，应用 V44 后刷新前端。
2. 学生进入助手的 **Agent任务**，输入“帮我准备请假草稿”；也可手动选择“请假草稿”。同时涉及多种业务的目标需明确选择或分别办理。
3. 在本地表单填写请假类型、实际事由、联系方式，以及明确的开始／结束日期与时间。缺少条件时 Agent 显示待补充字段，不默认“下午”的具体时段。
4. 点击“更新条件并重新规划”，Agent 核对字段、演示时间规则、有效指南和本人班级资格，生成包含时长与办理提示的预览。
5. 亲自核对后勾选确认，保存本人草稿；Agent 再读取原申请逐项核验字段和 `DRAFT` 状态后结束。
6. 从“打开原请假申请”补充材料并手动提交，之后由当前负责班级的辅导员处理。保存草稿不会自动提交或生成已批准日程。

## 执行与权限

- 六步正常路径：`check_leave_requirements → inspect_leave_eligibility → prepare_leave → save_leave → verify_leave → finish`。缺项追问或修订会增加执行步骤。
- 请假任务使用 `leave:apply`，创建、恢复与每步执行检查当前账号权限和本人会话。教师或管理员不能因其他岗位权限创建学生请假草稿。
- `AgentLeaveMissionTools` 复用 `AgentLeaveDrafts`、`LeaveService.eligibility`、`draftIssues` 和 `save`；校验未来开始时间、结束晚于开始、联系方式格式、行政班及有效指南。最长30天为演示规则，不代表学校实际制度。
- 没有有效辅导员但仍有行政班时，沿用原业务规则允许保存草稿，同时提示暂不能提交；没有行政班不能生成有效保存预览。
- 确认摘要包含全部本地请假字段、本人及当前班级／资格信息与指南版本。字段修改使确认失效；资格或指南变化时，保存前要求重新核对确认。
- `verify_leave` 校验原申请本人归属、任务业务键、类型、实际事由、联系方式、起止时间及 `DRAFT` 状态；原申请变化时不覆盖后续编辑。
- 模型只接收本次已授权目标、允许动作和脱敏观察；本地表单的事由、联系方式、班级和身份资料不作为观察发送。用户自行写在目标中的内容仍属于已确认发送目标。
- 共用任务租约、版本、幂等重试、取消、中断恢复和执行预算。请假域不能调用预约或报修写入动作。
- 原“准备请假”辅助表单保留；新的任务执行入口提供完整的逐步执行、确认与核验记录。
