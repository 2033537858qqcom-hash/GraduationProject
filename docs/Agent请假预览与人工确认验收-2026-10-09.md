## 实际交付

学生登录后打开右下角 AI 对话，选择“准备请假”。DeepSeek 从本次补充文字提取明确的类型、日期、时间和事由，服务端在本地合并当前预览，列出缺失项和校验问题。也可选“本地填写”，在同一表单填写并核对。

本次真实联调中，“我下周一到下周三需要请假，帮我准备申请。”转换为 2026-10-12 至 2026-10-14，类型、具体时间、事由和联系方式仍为空；补充事假、上午九点开始、下午五点结束和公开校园活动演示事由后，保留日期并补齐本次字段。联系方式只在本地表单填写。模型不自动填零点或全天、不编写未提供的事由。已验证这些问法，其他问法仍需用户核对，不代表模型正确率评测。

资料补齐后，用户检查可编辑预览，勾选确认，再点击“确认并保存草稿”。修改任何字段后原核对与确认失效；重新核对后才能保存。保存前再次读取指南、权限及业务检查，随后通过既有 `/api/leave/mine` 创建本人 DRAFT / V0。姓名、学号及行政班由服务端读取。原请假页面继续负责材料、人工提交和审批。

成功后显示编号、草稿状态和“打开草稿，检查并提交”链接。后续可用既有“当前申请的处理进度”查询。重复保存使用同一请求键，复用原草稿；网络结果不确定时保留原资料及请求键，允许重试相同资料，并提供原列表入口，不自动重新建档。

## 字段与接口

| 字段 | 收集及检查 |
| --- | --- |
| 类型 | 事假 / 病假 / 其他；未明确时补问，不按事由猜测 |
| 起止日期、时间 | 分开收集；有歧义或未明确时不填默认值；未来开始，结束晚于开始 |
| 时长 | 实际起止时间差，显示天、小时、分钟；演示最多 30 天 |
| 事由 | 用户明确给出的文字，可编辑；1—2000 字 |
| 联系方式 | 本地表单填写手机或邮箱，复用原业务格式校验 |

`POST /api/assistant/leave/prepare` 要求 CSRF、`agent:query` 和 `leave:apply`，准备接口不写申请。与原查询共享每账号一个进行中的操作、每分钟三十次的单实例限制。模型等待期间身份版本变化，会停止预览交付。

DeepSeek 只收到本次补充文字、当前日期和字段提取契约，当前表单、历史补充、身份、联系方式和查询结果不自动外发。用户写进本次文字的内容会发送，发送前有逐次确认。仅接受一个 `collect_leave_fields`；额外身份、联系方式、状态、未知字段、其他工具或无效日期时间被拒绝。失败保留原预览，模型自由文本不作为结论。

普通表单和预览共用 `LeaveService.draftIssues`。指南撤下、未分配行政班或信息不完整时，预览不能确认保存。未配置有效辅导员时沿用原业务：可存草稿，暂不能提交。指南和单次 30 天规则均为演示，不代表学校实际制度。

预览仅保留在当前页面内存，收起窗口、切换查询入口后可继续填写；未保存离开有放弃提示，取消保留字段，确认放弃清空。刷新有未保存提示，退出或身份变化清理预览。保存中禁用关闭和入口切换，并拦截路由导航。补齐后收起文字区，为表单核对留出空间。

沿用 `agent_run` 最小审计，不记录事由、联系方式、补充文字或预览内容。用户确认保存后，资料进入原请假业务及版本记录；没有模型提交或审批工具。
