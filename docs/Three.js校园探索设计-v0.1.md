# Three.js 校园探索设计 v0.4

更新：2026-10-04。首个校区采用用户选定的郑州工业应用技术学院东校区。

## 本轮纠正与当前范围

用户明确要求建筑布局、道路与街区以真实资料为依据。原先 11 个地点的对称创作场景已撤下，其建筑、校门、小桥、喷泉、树阵与道路网不继续复用。现在是以高德标准底图和卫星影像为依据的第一版手工轮廓描摹，不是精确测绘或完成的全校建筑复刻。

场景覆盖北部主校园。南侧酒店等区域的校方归属、用途及范围未核实，暂未纳入。底座只是场景展示裁切和支撑平面，不表示法定校园边界。

地图中的图书馆位于中心环路内，英才广场在西侧，书华楼在北侧，艺术楼与游泳馆在西北侧，信科楼和文华楼分别在图书馆西南与东南侧。西侧可见田径场及成组球场，东侧可见纵向水面。南部保留地图标注的建筑工程学院、医学院对应区域，但不据此认定当前院系名称和楼栋归属。

当前目录包含 18 处地图标注或可见区域，模型包含 39 个描摹对象和 28 条近似道路折线。无名称的可见屋顶保留为未命名体块，不猜测宿舍、食堂或学生事务中心的位置。

本次再次查看 50 米比例尺下的标准图与卫星图，重点修正中央和北侧楼体：

- 图书馆由填满的体块改为南侧开口的环抱轮廓，补入南侧前场。
- 书华楼与其东侧的致远楼分别呈现，保留可辨内院；新增西侧 H8 副楼。
- 原先书华楼南侧的匿名体块重新核对为静逸楼标注附近的相连轮廓，保留两处可辨内院。
- 文华楼按放大图重新描摹斜向围合和两处可辨内院，替换此前三个粗略条形体块。
- 信科楼附近的南侧楼体拆分，新增建工楼；它与更南侧的“建筑工程学院”地图标注分别记录。
- 医务室作为服务点位符号呈现，不创建独立建筑，不认定所属楼栋、楼层或入口。
- 补入北侧横向支路、楼间道路、H8 副楼前连接、静逸楼西侧连接、文华楼北侧接入及横向连接、建工楼前连接，共 7 条近似折线。放大图中新识别的内部支路宽度也只用于展示。

静逸楼附近的餐饮商户与文华楼附近的院系 POI 只作为地图信息，不用于推断整栋楼的现行用途。南部建筑群、西侧运动场细分、未命名楼体及水岸仍延用上一版粗略描摹，并未宣称完成逐楼精细复刻。

## 数据约定与准确度

`eastCampusLayout.ts` 保存原始截图像素点、多边形、内庭孔洞、道路折线、来源链接、查询日期、版本及核验状态。模型原点对应主截图像素 `(310, 330)`，向东为 `+x`，向南为 `+z`，北向为 `-z`。每像素映射到 0.35 个展示单位；这个比例只用于模型取景，不是米制地理坐标转换。

截图中被文字或符号遮挡的边缘、屋檐与道路曲线只能近似描摹。水岸没有正式名称时使用描述性名称。楼名只能关联地图标注附近的轮廓，邻近未确认归属的楼体保持匿名。

新增放大截图通过图书馆、书华楼、文华楼、艺术楼四个手读 POI 锚点与原总览图配准，采用统一缩放和二维平移；各次拖动后的截图平移由同一标注的屏幕位置读取。`detailRegistration` 保留锚点与配准参数，`detailViews` 保留截图和视图平移，新增轮廓与支路记录 `evidenceView`。拟合残差约为放大图 2.59 像素，只描述这四个图片锚点的配准程度，不能作为建筑测绘精度、地理定位精度或底图时效的证明。地图 URL 中的视口参数仍不作为坐标转换依据。

没有取得实测楼高或可靠层数资料。所有楼体采用相同 3.2 展示单位的挤出高度，不添加假定窗格、阳台、坡屋顶、柱廊或楼层。页面明确显示“地图描摹 · 建筑等高展示”；该高度不表达现实楼高。影像拍摄日期未知，不宣称卫星图代表当前最新建设现状。

医务室位置符号抬至 3.6 展示单位，目的是使符号不被相邻等高体块遮盖；它不是楼层、医疗建筑高度或实际服务窗口位置。目录新增“服务”分类，使用同一 Lucide 图标体系的听诊器图标，详情说明点位的限制。

本地像素坐标、模型展示坐标和地理坐标必须分开维护。软件学院高德 POI 的经纬度只证明该点的地图位置，不能扩展为整校边界。尚未建立通行道路图，不输出真实步行路线。

## 工程与交互

- `eastCampusLayout.ts`：来源与轮廓数据；`manifest.ts`：可读目录及地点浏览顺序。
- `buildCampus.ts`：通过多边形和内庭孔洞构造等高楼体，道路按描摹折线生成；按材质和地点合并静态几何。
- `framing.ts`：总览取景；`createCampusScene.ts`：相机、点击、高亮、标签、生命周期。
- `CampusExplore.vue`：东校区页面、目录搜索、分类、来源链接、总览和俯视、标签与日暮切换。

浏览顺序为东门、图书馆、英才广场、艺术楼、西侧体育区，只切换相机，不表示可通行的连续路线。俯视图上方为北，界面显示北向。高亮使用描摹几何并保留内庭孔洞。页面底部和地点详情都标明来源及准确度。

Three.js 仍按探索路由延迟加载。静止时停止帧请求，页面隐藏时暂停；离开页面释放几何、材质、控制器、阴影和 WebGL 资源。无 WebGL 时保留文字目录。未引入地图 SDK、抓取地图瓦片或使用用户账号凭证作为应用配置。

## 验证与后续核验

`pnpm check:campus` 检查来源截图存在、放大截图锚点配准、去除 demo 标识、目录与模型映射、北向和关键相对关系、几何有效性、实际可见屋顶与服务点点击、内庭与图书馆南侧开口不被封闭及多种宽高比的总览取景。测试成功不能证明描摹精度或楼名归属。

构建、lint 和几何检查通过。本轮浏览器检查 1280×900 桌面和 390×844 小屏，验证新增致远楼、H8 副楼、建工楼、静逸楼的搜索定位，以及服务分类与医务室定位。小屏 DOM 宽度与滚动宽度均为 375px，没有横向溢出，场景仅有一个 canvas。截图为 `calibrated-top-v2.jpg`、`calibrated-jingyi-v2.jpg` 与 `calibrated-mobile-v2.jpg`。真实触摸手势和低端设备帧率尚未实机验收。

几何规模为 25 个根网格，约 6,588 个三角面；该数量不是实测帧率。

下一步优先获取并核对官方近期平面图、全景和各重点建筑照片，逐楼补充层数、屋顶和立面；其次校对未命名楼栋、道路曲线及最新用途。南部未确认范围和西校区单独建档。需要地理定位时，另建带明确坐标系统、标定点与精度记录的地理转换，不能直接把本轮像素数据用于导航。
