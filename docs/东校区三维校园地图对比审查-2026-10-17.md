# 东校区三维校园与腾讯、Google 地图对比审查

核查日期：2026-10-17。对象：郑州工业应用技术学院东校区；当前工作区的 `/campus/explore` 页面及对应源代码。本轮只进行对比、证据留存和只读几何检查，没有修改场景或业务数据。

> 后续状态：以上及下文记录的是修复前的审查。用户随后提供了真实校园建筑分布图，已据此实施修复，详见同目录《三维校园分布修复验收-2026-10-17.md》。新资料明确区分锦绣餐厅西翼与静逸楼东翼，并确认了西北红体馆、文华餐厅、行政楼、学术报告厅等身份；补图前“仅作为POI、用途待核实”的处理建议已据此调整。旧交叠面积、统计数量与“场景尚未改动”均属于历史状态，不代表修复后的模型。

## 结论

当前场景具有真实校园的部分平面骨架，但仍属于截图描边后的体块示意。尚不能将它称为“逐楼精确校准”或“精细复刻”。问题不只是缺少贴图：新增体块有空间冲突，一些建筑名称和用途没有逐栋对应证据，屋顶、看台、门洞等关键结构尚未表达。

必须区分三件事：地图上看得到建筑；能确认该建筑的名称和用途；能确认其高度、楼层和室内房间。前一项成立，不代表后两项成立。

## 二、具体问题

### 补查：静逸楼、锦绣楼与锦绣食府混淆（高优先级）

用户指出静逸楼与锦绣餐厅存在重叠后，补查发现此前只计算几何交叠，漏掉了地点身份和建筑归属的错误。这一项应纳入首批修正。

项目 2026-10-04 留存的 `east-campus-amap-central-standard-v2.jpg` 与对应卫星图中，“锦绣食府”餐饮 POI 位于静逸楼所在的连体建筑组团西侧，“静逸楼”楼名位于该组团东侧。两者不是当前模型中相距较远的两个独立地点。截图能支持同一连体组团内的空间关系，不能单凭此确认它们属于完全同一栋、同一楼层，或整组建筑只有餐饮用途。

同时，全局截图 `east-campus-amap-satellite-2026-10-04.jpg` 在文华楼东侧、水系西侧另有“锦绣楼”标注。**“锦绣楼”不能因为同有“锦绣”二字，就直接等同于“锦绣食府”。**

代码历史给出明确的错误引入过程：

| 版本或位置 | 记录 | 问题 |
| --- | --- | --- |
| 提交 `3ff45b2` 的 `manifest.ts` | `east-jinxiu` 名为“锦绣楼”，用途待核实 | 对应东侧楼体，与餐饮 POI 尚未混同 |
| 提交 `26c0db3` 的 `manifest.ts` | 同一 ID 被改为“锦绣食府 (第一学生餐厅)”，补入三层、清真餐线、预约场地等介绍 | 没有相应证据就把原楼体改成了餐厅 |
| 当前 `eastCampusLayout.ts:81` | 将原本未命名的 `jinxiu-south` 也赋给 `east-jinxiu` | 餐厅归属又被扩展到相邻楼体 |
| 当前 `manifest.ts:104` 至 110 行 | 静逸楼被描述为教学综合楼，并附 106、201、305 房间 | 同组团已有餐饮 POI，现行具体功能与这些房间信息仍需独立核实 |

补充计算结果：当前静逸楼与“锦绣食府”两个模型的平面交叠面积为 **0 px²**；这说明不是当前两组网格直接穿插，而是现实地点、楼名与几何体关联错了。将保存的中央截图中两个 POI 图标中心近似读为 `[435,230]`、`[574,230]`，经过项目现有截图配准后，两点均落入 `jingyi-roof` 轮廓内，并不落在当前 `east-jinxiu` 的两个体块中。落点仅用于核对地图标注关系，不是精确入口坐标，也不能证明楼层和排他归属。

处理时应分别建立“建筑轮廓”和“餐饮服务点”：保留地图有依据的建筑形体，解除错误餐厅名称、整栋用途及相邻楼体归属；餐厅先按地图 POI 关联到相应组团，确认实际入口、楼栋关系后再深化。不能简单把两个模型平移到一起，或把静逸楼整组都改成餐厅。

本次实时高德查询触发验证码，未继续操作；这一补查依据是项目已保存的地图、源代码与 Git 历史，不宣称取得了当天新的楼内用途资料。

### 1. 西北宿舍群：位置、轮廓及田径场冲突，需要首先纠正

当前 `eastCampusLayout.ts:96` 至 99 行以四个水平长条表示 H1–H7。两家卫星影像对应位置可辨认出体育场及其屋盖、圆形或近椭圆体育建筑、铺装广场及其他局部建筑，不能支持这四条宿舍楼的排布。

其中 `dorm-block-h7` 范围为 x=95–165、y=184–201，自身面积 1190 px²；它与 `west-track` 外轮廓相交 **508.375 px²，约占宿舍体块自身面积 42.7%**。当前俯视图中也能直接看到白色条状楼压入体育场上沿。

这里的 `west-track` 是整个田径场外轮廓，不是仅指跑道橡胶面；42.7% 不是“占用了全校田径场 42.7%”，也不是真实平方米。确定问题是：独立宿舍体块和体育场范围发生了未说明的重叠，而且缺少逐栋宿舍定位依据。不能由本次结果推断学校没有 H1–H7 宿舍。

### 2. 田径场：最有辨识度的看台与弧形屋盖没有建出来

腾讯与 Google 卫星图都能清楚看到田径场两侧大面积弧形屋盖及外部铺装。当前只用 `track`、`field` 两种低厚度平面表达主体，缺少看台体量、屋盖、出入口和外围平台。

这会使真实校园的重要地标变成普通露天操场。应保留当前大致位置和斜向关系，依据影像重新拆分场地、看台和屋盖；看台高度需另找照片或资料确认。

### 3. 新增“红体馆”：轮廓缺证，且与现有球场发生交叠

`eastCampusLayout.ts:101` 至 103 行用主矩形、南门厅、西侧训练体块拼出体育馆。当前没有逐栋来源证明这三个矩形对应真实场馆的边界与功能，不能仅凭场馆名称选择一个位置并刷成红色。

确定的模型内冲突是：

| 体块 | 与 `west-courts` 重叠面积 |
| --- | ---: |
| `gym-main-arena` | 26.141 px² |
| `gym-west-training` | 206.438 px² |

应先核实场馆确切位置、建成年代和轮廓，再决定是否调整球场；不能为了消除碰撞直接移动真实球场。本次不判定学校不存在该场馆。

### 4. 图书馆：平面大形基本成立，三维层次明显不足

环抱形轮廓、南向开口及与周边教学区的相对关系可以保留。Google 细节图能辨认内侧圆形顶部结构及明显的屋面层次，而当前只有一个 `library-roof` 轮廓挤出，没有独立表达这些结构。

`manifest.ts:25` 将图书馆高度设为 5.8，所有部分同高；文案另称“主体高约 7 层”，没有相应的逐楼证据链接。5.8 是模型单位，不代表真实 5.8 米，也不能由这个值验证七层说法。

问题是外观辨识度和高度依据不足，不是图书馆位置全错。后续应补主体分段、内侧顶部结构、檐口、入口，层数和高度分别核实。

### 5. 游泳馆及其他教学楼：屋顶投影被直接当成完整建筑

游泳馆用一个近椭圆多边形等高挤出，不能表现卫星图可见的曲面屋盖。书华、致远、静逸、文华等保留了部分中庭，但都没有分楼翼、楼层、屋面和入口。

`buildCampus.ts:78` 至 82 行统一调用 `ExtrudeGeometry`，深度只由地点级高度决定。这种方法适合白模示意，不能凭材质和颜色分级认定完成精细建筑复刻。屋顶投影是否等同于地面轮廓也尚未逐栋核实。

### 6. 文华餐厅与高尔夫：两处独立地点的建筑体块互穿

`canteen-wenhua-main` 为 x=426–474、y=395–440，`roof-east-01`（现指定为高尔夫）为 x=471–524、y=410–446。扣除中庭孔洞后仍相交 **90 px²**，对应 x=471–474、y=410–440。

这是独立地点几何重叠的确定问题；真实情况究竟是同一建筑的不同功能、不同楼层、共享部分，还是定位错误，没有证据。应先核实建筑身份再处理几何，不能仅平移一个矩形。

还有一处文字与模型的直接矛盾：高尔夫描述称“秋月塘东岸”，但体块最大 x=524，位于东侧长水体（x=527–590）以西。至少对于这条临近水体，当前“东岸”描述不成立。水系命名和场馆名称仍须逐项确认。

### 7. 行政、事务、机电、食堂与塑像：名称与当前体块未建立可靠对应

| 当前对象 | 当前证据能支持什么 | 尚不能确认什么 |
| --- | --- | --- |
| 学生事务综合服务中心 | 已有学校手册记载这个设施及 211 室 | 该名称是否对应当前 x=266–314、y=380–418 的独立合院体块 |
| 行政管理中心、机电工程学院 | 名称存在性与当前地图几何定位需要分别核实 | 新增规则矩形是否落在正确楼址、是否为独立建筑、当前用途及层数 |
| 文华餐厅、锦绣食府 | 地图可观察周边建筑 | 当前模型给出的正式名称、餐厅编号、楼层和服务内容 |
| 轩辕黄帝塑像、孔子行教圣像 | 模型中分别存在多边形柱体 | 是否确有该塑像、具体位置、朝向、造型、材质；卫星图中的小景观不足以确认人物身份 |

原有南部高德截图还出现酒店 POI，说明该区域的建筑身份必须认真核对，但一个酒店标签同样不能证明整个南部组团都是酒店。本轮没有将“用途待核实”写成“确定是假建筑”。

项目保存的 2018 机电规划是历史局部拟建方案；旧设计文档也明确不把它当成已建成主校园。即使后续采用这张图，也必须重新确认位置、建成现状和时间，不能自动验证当前两个矩形楼块。

### 8. 南门和塑像：几何类型没有表达真实结构

名为 `south-gate-portal-arch` 的对象实际上是 44×10 像素矩形等高挤出，没有门洞；南门出入道路从该实体投影中穿过。入口类对象需要通行开口，不能仅使用一堵矩形体代替门楼。

两个“塑像”同样由普通建筑轮廓挤出，只有柱状体块，没有人物造型。目前只能作为未核实的标记点或占位体，不宜配详细人物、材质和学校立像缘由介绍。

### 9. 道路和范围：可用于示意，尚不具备真实导航依据

路面由截图折线和展示宽度拼装为长方体，未区分车行、人行、广场通道、门禁、跨水连接，也没有真实入口接入点与可通行路网。不能从“看起来连上了”推导出可步行、可驾车或者真实距离。

`campusCoverage` 的注释明确是展示裁切范围，非校园产权边界；底部另有大矩形支撑平面。周边水岸、道路和地形因此被简化。若要展示真实校界，必须额外取得可靠边界资料；不能把展示底板当校园围墙或面积依据。

### 10. 坐标、高度与来源声明不匹配

`eastCampusLayout.ts:53` 至 54 行只执行 `[(px-310)*0.35, (py-330)*0.35]`。0.35 是每截图像素对应的模型单位，没有建立每模型单位等于多少米的依据。四个锚点用于不同截图配准，其残差是图像配准误差，不能等同于实地精度。

当前没有逐栋经纬度控制点、地图坐标系记录、卫星拍摄日期、高度证据或独立核验点。每个地点却统一标为 `verification: 'map-observed'`，并且 `sourceUrl` 都指向同一个高德搜索页（`manifest.ts:322` 至 324 行）。仅新增腾讯链接和“Google 卫星校正”文字，不能证明逐栋交叉核验已经完成。

此外，事务中心元数据高度为 3.6，而渲染为 4；南门元数据高度为 0.2，而渲染为 3.6。地点标签和相机取景会读取该元数据，需统一真实的几何包围范围与展示标签高度，不能混用入口类别默认值。

### 11. 室内预约信息超出了地图能支持的范围

例如“图书馆一楼报告厅 300 座”“书华楼 101 报告厅 240 座”“致远楼 401 微机房 120 机位”等已写入地点详情。卫星图不能证实房间号、设备量、座位数和是否开放预约。

这些内容可以作为明确标记的毕业设计演示数据，但目前具体名称和容量的真实性缺少依据。不能用室内业务文案反向证明建筑复刻准确，也不应把演示资源当成校方真实开放资源。

## 四、建议处理顺序

1. **纠正空间与身份**：首先拆清静逸楼、锦绣楼与锦绣食府的名称及归属；重新描出西北区域，处理宿舍/田径场、体育馆/球场、餐厅/高尔夫冲突；逐栋记录建筑照片、地图位置、正式名称和可信度。对无法确认的对象保留匿名轮廓或待核实标记。
2. **建立一致的坐标依据**：选定一张底图为几何基准，记录图像来源、可见比例尺、坐标系及控制点；其他来源只在配准后辅助核对。另留独立检查点评估误差。
3. **优先还原标志建筑**：先补体育场屋盖与看台、图书馆顶部及主体分段、游泳馆曲面屋盖、南门门洞。取得高度与立面证据后再深化其他教学楼。
4. **验证道路和入口**：区分车行、人行和门禁，补建筑入口，检查道路穿楼、穿水、断点与通行关系；此前不提供真实距离和到达时间。
5. **修正描述与验收**：把几何、名称、用途、层高、室内资源分别标记为已核实、推断或演示；补充多边形重叠检查；更新文档统计与页面真实性声明。

可保留现有图书馆位置及环抱大形、若干教学组团的相对方位与中庭、校园东侧长水面的大致分布。应在这些已有依据的部分上校正，而不是继续增加没有定位证据的装饰性建筑。
