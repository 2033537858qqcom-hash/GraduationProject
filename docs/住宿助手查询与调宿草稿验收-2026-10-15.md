# 住宿助手查询与调宿草稿验收

日期：2026-10-15。迁移 V20，工程版本仍为 0.1.0。本批在已有住宿、调宿及宿舍关联报修基础上，接入学生本人查询与调宿草稿准备，不替代学院初审或宿管办理。

## 1. 实际功能

- `my_housing` 查询本人当前房间；床位与负责人在“我的住宿”核对。无入住记录时明确提示，不推测房源。
- `my_housing_transfers` 读取本人最近至多 8 条调宿状态，`housing_transfer_status` 按当前页面上下文或明确编号读取本人申请。结果提供状态、版本、预留期限及取消待处理标记，不带原因、材料正文或完整审核意见。
- 住宿页面出现相关提示与快捷提问。只有同时具备 `agent:query` 和 `housing:read` 的学生可准备调宿；教师、管理员和宿管不会因此取得学生住宿权限。
- “准备调宿”提供原因、意向区域、材料说明的编辑、核对暂存、会话恢复及人工确认保存。保存只生成 `DRAFT`，通过原调宿页面继续修改并亲自提交。
- 原调宿页补齐“修改草稿”“保存草稿修改”“核对后提交”。从助手打开同一路径下的申请链接时，页面重新读取申请并标记当前编号，不沿用创建前的空列表。

## 2. 数据与确认边界

当前住宿通过服务端关联读取。预览含不透明的 `stayToken`，绑定本人、入住记录、版本、显示位置与当前指南版本。用户确认后，前端先重新读取预览；保存事务内再按当前状态核对令牌，并与住宿业务共用写锁。

预览后退宿、再次入住同一床位、住宿信息修改或指南版本变化，都要求重新核对；已有未结束调宿出现时禁止另建。撤下指南或撤销学生权限后，恢复与保存重新受限。原入住、目标床位和审核状态均不能由模型字段指定。

任务新增 `HOUSING` 类型，沿用本人会话、任务版本、固定业务请求标识和 `LINKED` 关联状态。相同保存重试、并发重试只创建一份草稿。历史恢复不直接复用旧业务结论，按当前权限、入住关系、指南与原申请状态重新读取。

新指南 `housing` 为“住宿与调宿办理指南”V1，明确当前工程的演示流程。既有 V1–V19 迁移未修改，V20 扩展任务类型并添加指南。

## 3. DeepSeek 范围

自然语言查询通过现有只读规划器选择三个住宿工具，业务数据在本地执行和展示。调宿提取工具 `prepare_housing_fields` 只接受 `reason`、`preferredArea`、`materialNote` 三个文字字段，未明确提到的字段不补写。意向区域不转换成床位，材料说明不代表材料已审核。

只有本次补充文字在用户逐次同意后发送；既有表单、当前住宿、入住令牌和历史不发送。后端拒绝未知工具、目标床位、身份、状态等越界字段。日志仅记录工具、结果、耗时和用量，保存的本人会话与预览仍在本地数据库。

本轮没有调用真实 DeepSeek。新增 HTTP 契约测试使用本地模拟服务，验证请求体、字段工具范围和忽略模型自由文本；此前真实模型评测仅为历史证据，不据此推断新增住宿问法的真实准确率。

1. 查询本人房间，显示本人业务链接。
2. 编辑调宿预览并暂存；刷新、重新打开后恢复原字段，确认勾选不恢复。
3. 亲自勾选后保存草稿，原页面显示 `DRAFT`。
4. 打开原申请，修改草稿并保存，再点击“核对后提交”。
5. 助手从页面上下文读取提交后的最新状态。
