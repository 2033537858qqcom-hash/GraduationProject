# 住宿基础与初始入住验收

验收日期：2026-10-13。数据库迁移 V17。对应需求 DOR-01、DOR-02，以及 DOR-04、DOR-05 中的初始入住和退宿。调宿申请不在本批。

管理员维护宿舍楼、房间、床位和楼栋负责人。宿管只在当前有效负责楼栋登记初始入住和退宿。学生查看本人当前床位、楼栋负责人和已结束记录，不查看其他住户。已有资源不提供删除。在住或已预留的床位不能停用或直接改为维护。

## 1. 边界

新增岗位 `DORM_MANAGER` 和权限 `housing:read`、`housing:assign`、`housing:configure`。学生获得本人查询，管理员获得资源配置，宿管获得办理权限和工作台入口。管理员不能代替宿管入住或退宿。

一名学生同时只有一条当前住宿，一张床位同时只有一条当前住宿。结束的记录把当前指针清空，因此可以再次入住。相同操作标识和相同内容返回原结果；标识相同但学生、床位或退宿原因不同则拒绝。楼栋编号、校区、房间所属楼栋和床位所属房间建档后不能修改。

退宿时把当时的楼栋、房间、楼层和床位名称写入记录。之后再改名称，历史仍保持退宿时的名称；在住期间页面显示当前名称。停用楼栋、撤销范围或移除宿管岗位后，不能继续办理该楼。

演示账号 `dorm1001` 只在演示初始化开启且账号不存在时创建。迁移不写入宿舍楼、房间、床位或入住记录。

## 2. 验证

[HousingIntegrationTest](../backend/src/test/java/cn/zzuit/campus/HousingIntegrationTest.java) 覆盖登录和 CSRF、权限分离、重复编号、校区不可变、无删除接口、在住资源不能停用、维护床位不能入住、本人与跨楼隔离、重复入住、幂等确认、退宿后改名不改写历史、并发入住和退宿只有一个成功、撤岗后范围失效，以及搜索转义和无效分页不写记录。H2 内存库应用 V1–V17。

前端 55 项测试通过，变更文件的类型检查和 lint 通过。不支持的 HTTP 方法返回 405，不再记成服务器内部错误。

隔离页面 `http://127.0.0.1:18090` 使用内存库，本机 Chrome 走完管理员建档、指定宿管、宿管入住、学生查看和退宿。390 宽学生页没有横向溢出。截图在 `artifacts/housing-2026-10-13/`。这次没有改主库；正在运行的 8080 服务仍是旧进程，重启后才会执行 V17。
