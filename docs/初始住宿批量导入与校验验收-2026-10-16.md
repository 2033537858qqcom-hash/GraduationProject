# 初始住宿批量导入与校验验收

日期：2026-10-16。工程版本：0.1.0；数据库：V23。

## 1. 本轮结果

宿管可在当前有效负责楼栋下载空闲床位模板、上传或粘贴名单，逐行校验后手动确认整批初始入住。每批最多 200 人、CSV UTF-8 最多 100 KB。导入完成生成服务器回执，住宿记录标明批次，学生收到原有入住通知并在“我的住宿”查看本人床位。

该流程沿用现有账号与住宿资源，不自动创建学生、楼栋、房间或床位。已有在住记录的学生使用调宿流程。验收数据均明确标记为演示，不代表学校实际住宿安排。

## 2. 操作和异常处理

1. 管理员在“宿舍资源”配置楼栋、房间、床位和有效宿管范围。
2. 宿管进入 `/housing/assignments`，选择负责楼栋，展开“批量登记入住”。无有效楼栋时显示联系管理员的空态。
3. 下载本楼模板。仅包含当前可入住的前 200 个床位编号，不含学生或其他住户资料；模板带 UTF-8 BOM，危险起始字符按 CSV 单元格规则转义。
4. 填写学号和入住说明。学号设为文本以保留前导零；房间编号、床位编号使用系统配置值。上传 CSV，或在页面粘贴内容。未填写模板行与空白行跳过。
5. 点击“校验并预览”，显示原 CSV 物理行号、匹配学生、目标位置和具体错误。同一学生或床位重复时所有相关行均标错。任何错误都不会生成可确认批次或入住记录。
6. 全部通过后产生 15 分钟有效的预览。修改名单、文件来源或负责楼栋后，旧预览不能直接确认。离开页面或刷新存在未完成输入时提示保护；输入不会写入浏览器持久存储。
7. 核对后点击“确认导入 N 条”。成功后收起准备表单，显示批次、逐条入住记录编号与最近回执，可刷新页面重新查看；可继续准备下一批。

预览存储仅包含标准化后的有效行、来源摘要与资源指纹，不保存原 CSV 文件。预览不占用床位、不产生入住通知。未完成的预览在过期一天后随下一次有效预览清理；完成回执和入住历史保留。

## 3. 接口、权限与一致性

| 接口 | 用途 |
| --- | --- |
| `GET /api/housing/imports/template?buildingId=...` | 下载当前楼栋空闲床位模板 |
| `POST /api/housing/imports/preview` | 校验 `{buildingId,csv,sourceName}`，通过时保存预览 |
| `POST /api/housing/imports/{token}/confirm` | 仅按服务器保存的批次确认；忽略客户端附加行数据 |
| `GET /api/housing/imports/{token}` | 当前创建人读取批次与回执 |
| `GET /api/housing/imports?buildingId=...` | 当前创建人在本楼最近 10 份完成回执 |

所有接口核对当前 `housing:assign` 权限、账号安全版本和有效楼栋范围；知道 token 也不能读取其他宿管的批次。学生、教师和管理员没有宿管导入权限。管理员仍可在既有住宿记录中看到来源批次编号，不读取其他人的导入预览。

确认时取得与住宿配置、手动入住及调宿共用的写锁，重新检查当前学生资格、已有住宿、床位状态、房间／楼栋启停、相关版本及管理范围。预览后资源变化要求重新校验。先核对整批再复用原有入住服务，入住、床位更新、逐条通知、审计和回执位于同一事务；任何一步失败均回滚。重复确认同一已完成批次返回原回执，不重复登记或发通知。网络不确定时保留 token，可对同一批重试。

V23 新增 `housing_import_batch`、`housing_import_row`，以唯一 token、批次学生唯一、批次床位唯一和关联入住编号约束数据。现有每名学生／每个床位仅一条当前住宿的唯一约束继续生效。

可按以下方式启动同一主库，Java 21 必须在 PATH 前面：


mysql 配置已支持 `CAMPUS_DB_URL`、`CAMPUS_DB_USERNAME` 覆盖，默认仍指向既有 Docker 3307 的 campus／campus_app。以后获得有效本机凭据时，以环境变量设置连接到独立空验收库，再验证 V1–V23 和住宿导入，避免直接改动已有业务库。`infra/.env` 不会由 Spring Boot 自动读取，凭据需在本地加载为环境变量，不放入命令参数或聊天。

此前真实 MySQL 8.4 证据仅覆盖 V1–V15；V16–V23 当前仍待 MySQL 实测，不宣称已通过。
