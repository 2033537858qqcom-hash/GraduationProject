# 备份恢复说明（2026-10-31）

日期：2026-10-31（Asia/Shanghai）。本说明对应需求 OPS-03（独立环境备份恢复）的工程入口。

> **定位**：本轮只提供**离线停服备份/恢复脚本与演练说明**，并已用临时目录自测校验链路；**没有做真实生产环境恢复演练**，不代表已达到生产级灾备能力。数据库为本地 H2 演示库，材料与私有附件以 BLOB 存在库内，备份单个数据文件即可覆盖业务数据与附件；腾讯 COS 头像等外部对象存储不在本脚本范围。

## 适用范围与前置条件

- 适用：本地 H2 演示库（`campus.mv.db`，可选 `*.trace.db`）。不适用 MySQL、Docker 卷、腾讯 COS 或其他外部存储。
- **备份必须离线**：先停止后端服务（Ctrl+C 或关闭对应终端），确认没有进程占用数据库文件后再执行。脚本不会结束进程；若后端仍在写库，复制校验可能失败或得到不一致文件。
- 确认要备份的**实际库路径**：`application-local.yml` 使用相对路径 `./data/campus`，在仓库根目录启动与在 `backend` 目录启动会打开不同库；界面预览、答辩演示也可能使用 `artifacts/\*/campus` 隔离库。默认源目录是 `backend/data`，其他库必须显式传 `-SourceDirectory`。
- 备份产物默认写入 `artifacts/backups/`（已被 `.gitignore` 忽略）。备份包含演示账号与业务数据，应仅保存在本机，不要提交仓库或外发。

## 备份：scripts/Backup-DemoData.ps1

脚本参数：

| 参数 | 说明 |
| --- | --- |
| `-SourceDirectory` | 可选。包含 `campus.mv.db` 的目录；默认 `<仓库>/backend/data`。目录不存在或缺少主库时直接失败 |
| `-OutputDirectory` | 可选。备份输出目录；省略时自动创建 `artifacts/backups/<yyyyMMddTHHmmssZ>`（UTC，冲突时追加随机后缀）。显式指定且目录**非空**时拒绝覆盖 |
| `-IncludeTrace` | 可选开关。一并备份同目录的 `*.trace.db`（H2 跟踪文件，通常排查用；默认不备份） |

示例（仓库根目录执行）：

```powershell
# 默认备份 backend/data，输出到带 UTC 时间戳的新目录
pwsh -NoProfile -File scripts/Backup-DemoData.ps1

# 备份从仓库根目录启动时使用的 ./data，并包含 trace 文件
pwsh -NoProfile -File scripts/Backup-DemoData.ps1 -SourceDirectory ./data -IncludeTrace

# 指定输出目录（必须不存在或为空目录）
pwsh -NoProfile -File scripts/Backup-DemoData.ps1 -OutputDirectory artifacts/backups/before-defense
```

输出结构：

```text
artifacts/backups/<UTC时间戳>/
  campus.mv.db                     # 数据库副本
  manifest.json                    # 机器可读清单（schemaVersion=1）
  manifest.md                      # 人读清单，含文件表与恢复步骤
```

`manifest.json` / `manifest.md` 记录：生成时间（UTC）、脚本名与版本、源目录、是否含 trace、Git HEAD（可用时）、文件数、总字节数，以及每个文件的 `name` / `kind` / `sizeBytes` / **`sha256`** / `lastWriteTimeUtc`。清单与输出**不包含数据库内容和任何凭据**。

脚本在复制后会重新计算目标文件 SHA256 与大小并与源文件比对，不一致即失败，避免留下"看起来备份成功"的坏副本。

## 恢复：scripts/Restore-DemoData.ps1

脚本参数：

| 参数 | 说明 |
| --- | --- |
| `-BackupDirectory` | **必填**。`Backup-DemoData.ps1` 生成的备份目录（含 `manifest.json`） |
| `-TargetDirectory` | 可选。恢复目标目录；默认 `<仓库>/backend/data` |
| `-Force` | 可选开关。目标目录已存在同名库文件时必须显式指定；**仍会先创建安全副本** |

恢复前置检查与保护：

1. 备份目录必须存在且含可解析的 `manifest.json`，`schemaVersion` 必须为 1，文件列表不能为空、文件名不得非法或重复，且必须包含 `campus.mv.db`。
2. 逐文件校验清单 SHA256 与大小；任何缺失、哈希不符或格式非法都拒绝恢复。
3. 拒绝危险目标：文件系统根目录、与备份目录相同的目标、目标是已存在文件等。
4. 目标目录已有同名文件时默认拒绝覆盖；加 `-Force` 后仍先为每个被覆盖文件创建 `<文件名>.before-restore-<UTC时间戳>` 安全副本并校验其哈希，再写入。
5. 恢复完成后重新计算目标文件 SHA256 并与清单比对一致，作为恢复成功的判据；全部失败均保留原有安全副本。
6. 脚本**不会停止进程，也不会启动服务**。

示例：

```powershell
# 恢复到独立目录做校验（推荐先恢复到这里，不动日常库）
pwsh -NoProfile -File scripts/Restore-DemoData.ps1 -BackupDirectory artifacts/backups/<时间戳> -TargetDirectory artifacts/restore-check/campus

# 回滚日常库：确认后端已停止后，显式加 -Force（会生成 .before-restore-* 安全副本）
pwsh -NoProfile -File scripts/Restore-DemoData.ps1 -BackupDirectory artifacts/backups/<时间戳> -TargetDirectory backend/data -Force
```

## 独立环境校验（演练建议步骤）

1. 停止当前后端服务，按上文完成一次备份，确认输出目录出现 `campus.mv.db`、`manifest.json`、`manifest.md`，且清单中 SHA256 与文件一致。
2. 用 `Restore-DemoData.ps1` 恢复到**独立目录**（例如 `artifacts/restore-check/campus`），不要先覆盖日常库。
3. 用一个独立端口和恢复出的库启动后端（可参照[答辩演示路线与启动说明](./答辩演示路线与启动说明-2026-10-30.md)的 `SPRING_DATASOURCE_URL` 写法，指向 `artifacts/restore-check/campus`），检查启动日志的 Flyway 迁移版本与数据源路径，访问 `/api/health` 返回 UP。
4. 抽查业务：登录演示学生与岗位账号，确认请假/证明/报修/住宿/缴费等列表可读、记录数量与备份前一致；抽查一条附件或证明 PDF 下载，核对"数据与私有文件关联"未断裂。
5. 校验完成后停止该临时服务，再决定是否回滚正式演示库；回滚前保留当时库文件的安全副本。
6. 记录演练结果（备份目录、时间、校验结论、未通过项），不要只写"脚本可运行"。
