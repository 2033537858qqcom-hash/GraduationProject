# 学生工作台首页设计 v0.1

日期：2026-10-03。状态：原布局已被用户否定，视觉基线重新评估；新的三种方向见《校园系统布局方向重选 v0.1》。本文件保留业务关系与交互规则供后续整合，原型使用本地示例数据，不代表业务系统或模型已接入。

## 页面目标与身份

学生登录后进入自己的工作台，能直接找到需要处理的事项、已提交事务的进度和下一项安排，通过服务中心开始新的办理。学校官网与工作台使用独立页面壳，共用校园品牌；官网不展示个人信息或 Agent。

本页只展示当前登录学生的资料和记录。学生、教师与岗位身份由授权确定，不允许通过切换界面自行获得权限。默认不提供全校统计、审批任务或管理功能。

工作台使用统一导航；不叠加“首页 / 工作台”等重复面包屑，不在正文设置“返回 XX”按钮。用户通过栏目手动切换，详情保留业务标题与当前状态。

导航视觉规范：桌面侧栏统一宽 184px，不随桌面断点缩窄；文字、图标、栏目顺序与选中标记保持一致。宽度小于 768px 时使用同宽的单列抽屉，由页头菜单按钮打开，不改为双列宫格。抽屉展开时遮罩覆盖业务区，业务区暂不可交互；选择栏目、点击遮罩或按 Escape 关闭，焦点返回菜单。跨越断点时关闭抽屉并恢复正文交互。正式页面的侧栏铺满页面壳高度，不随正文内容长短截断。

按钮视觉规范：桌面主要与次要按钮高 32px、文字 12px、小圆角，只有提交或确认保留校园绿色填充；待办行使用轻量文字操作。常用服务改为紧凑的“图标＋名称”横排入口，减少大块底色。触屏保留足够的点击区域，不将文字与图标一并放大。

## 首页信息布局

| 区域 | 展示内容与数量建议 | 点击结果 | 需求 |
| --- | --- | --- | --- |
| 个人页头 | 称呼、学院或行政班、消息入口 | 我的资料或消息中心 | IAM-03、HOME-01 |
| 需要处理 | 默认最多 3 项；展示要求、截止时间、状态与动作 | 对应补交、维修确认或归还详情 | MSG-02、SVC、FIX、RES |
| 办事进度 | 最近更新的 3 项；事项、状态、当前步骤与更新时间 | 原业务详情 | HOME-02、CAT-04 |
| 常用服务 | 最多 6 项收藏或最近使用；全部服务入口固定可见 | 服务指南或办理页 | CAT-01/02/03 |
| 近期安排 | 最多 3 项课表、报名或预约安排；显示日期地点 | 日程及来源业务 | CAL-01/04 |
| 未读通知 | 最多 2 项；主题、发布者与时间 | 通知正文，阅读状态更新 | MSG-01/05 |
| AI 助手入口 | 仅保留右下角虚拟角色 | 当前页面展开非模态对话面板，显示可清除的页面上下文 | AGT-01/02/05/08；P-U15 |

待办由当前业务状态生成；待处理审批只在进度区显示，不能算成学生需要处理的待办。历史消息不等于待办。截止时间与当前状态必须来自业务记录。

## 两种待选布局

- **待办优先（建议）**：主区域先显示需要处理和办事进度，右侧放近期安排与通知，常用服务放在下方。适合学生每日登录处理个人事务。
- **服务优先**：主区域先显示服务查找与常用事项，接着显示需要处理和进度；右侧仍保留安排与通知。适合以主动办理为主要目的的访问。

两种布局共用导航、数据与业务规则，选定后保留一种作为正式实现基线。

## Agent 与普通页面的关系

首页不默认铺开完整聊天窗口。右下角展示校园 AI 虚拟角色，点击后在当前页面展开局部对话面板，不改变当前栏目，不使用遮罩或自动展开完整对话。去掉顶部“问一问”、侧边栏“校园助手”和首页大面积助手卡片，统一由角色进入。此轮先用于登录后的工作台，官网仍遵循既定公开内容边界。

面板支持自由输入、任务示例、Enter 发送及 Shift + Enter 换行。展开、收起或关闭面板不清空本次会话，切换业务页面保留对话与未提交草稿；关闭面板不取消已提交业务。当前页面上下文明确显示且可清除，页面上下文不等于授权，不自动读取或发送整页个人信息。正式实现须对个人查询与每次提交重新验证身份、权限和资源条件。

正式 Vue3 页面采用右下角悬浮入口，并避开底部操作条；移动端改为适配屏幕宽度的局部面板。对话原型中的角色锚定在模拟页面右下角，避免跨越对话宿主的边界。

角色动效：待机为轻微上下浮动，打开对话时短暂摇摆招呼，收到消息后短暂弹动回应。动效仅作用于角色，不移动对话框或业务操作。尊重系统减少动态效果设置。当前原型使用二维角色图片的变换动画，后续如采用 Three.js 骨骼角色，可拓展独立挥手、眨眼和口型动作。

增加页面切换时的侧身观察、页面建议出现时的轻跳提醒、聊天展开时的轻微倾听，以及本人操作成功后的庆祝反馈。当前原型仍为图片变换，未实现骨骼、独立手部或口型动画。

页面建议在进入页面约 1.2 秒后，以角色旁的小气泡展示；不会自动展开完整对话，也不会将示例推断当成用户指令。工作台根据真实待办状态提示补充或确认；服务目录提示寻找事项；服务指南解释所需材料；预约页提示准备草稿；事务页提示查询进度；教学班、活动、住宿、日程与消息页提供对应入口。当前原型从本地示例状态生成建议，正式系统需要来自授权业务数据。

同一页面在本次会话内最多主动提示一次，快速切换页面取消旧提示，已打开对话时不再弹建议。提示可关闭，也可暂停所有页面提示；暂停后可从对话顶部的铃铛按钮恢复。关闭与暂停均不影响业务记录。点击建议仅打开对应页面或开始辅助对话，不自动提交、确认维修或替代用户作出决定。

2026-10-03 交互细化：角色入口仅保留图像，移除“校园助手”文字标签。对话面板桌面宽度 320px、高度 360px，移动端在可用宽度内显示；聊天与预约内容在面板内部浏览，输入区固定在底部。输入框单行起始，随内容扩展至 72px，取消手动拖拽，使用框内发送箭头；空白内容不可发送。快捷键保留但不常驻显示说明。

常用服务统一采用 Lucide 线性图标，校园绿色、24px、统一线宽：学习空间预约用 calendar-clock，在读证明用 file-badge，学生请假用 calendar-minus，报修用 wrench，活动报名用 ticket，住宿调整用 bed-double。含义分别对应时间预约、证明文件、请假时间、维修工具、活动凭证与住宿床位。图标只辅助识别，服务名称始终保留。

1. 查询本人报修：返回同一工单的真实状态、当前步骤和详情入口。
2. 辅助预约：收集场地、日期、时段和用途；查询可用条件后生成可编辑草稿。
3. 在对话面板内展示确认卡；标明草稿尚未提交，允许修改。用户确认后重新校验权限、状态与资源。
4. 提交成功展示业务编号和记录入口；失败保留草稿并提供重试，不能显示虚假的成功结果。
5. 清除会话不会取消业务记录；查询、确认和取消沿用 AGT-01 至 AGT-09 的权限、来源和恢复规则。

原型中的查询回复、可用场地和提交动作均为可识别的本地演示，不调用真实模型，不占用资源，不提交学校业务。

## 状态与验收要点

| 场景 | 页面行为 |
| --- | --- |
| 无待办 | 显示“目前没有需要处理的事项”，仍可打开服务中心 |
| 无事务 | 显示空态并提供服务入口，不伪造历史 |
| 部分加载失败 | 保留已加载区域，仅对失败区域提示重试 |
| 无适用服务或未开放 | 显示适用对象和开放说明，不伪装成可提交 |
| 事项已处理 | 更新详情及首页摘要，关闭对应待办，保留事务历史 |
| 服务条件变更 | 提交前重验；冲突后保留草稿并重新选择 |
| 移动端 | 同一导航以单列抽屉展开，主内容单列，右侧信息进入正文下方，无横向溢出 |
| 权限或会话失效 | 停止私有查询和提交，由统一身份流程处理；不能只隐藏菜单 |

首轮原型验证：导航进入完整内容区域；待办可定位到原事项；预览确认更新待办与进度；服务查找支持无结果；助手查询与事务详情一致；草稿确认后生成一条示例事务；桌面、手机和深色外观可阅读。
