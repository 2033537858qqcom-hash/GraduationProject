# 学生端教学查询补充 v0.1

日期：2026-10-03。状态：用户同意学生门户功能校正；本补充纳入设计基线，与需求规格说明书 v0.2 配套阅读。

2026-10-05 更新：工程已实现本人成绩、考试查询与首批教务维护，包括成绩校验导入、草稿发布更正、考试手工维护。完整批次考试导入等尚未实现，实际范围见[教学功能迭代验收](./教学功能迭代验收-v0.1.md)。下文原型描述为历史演示，不表示请假、报修或 Agent 已有业务后端。

## 范围

保留“校园门户”横向布局。学生首页以近期课表、教学班通知、课程资料、需要本人处理的事项和本人办理进度为主。六个栏目为我的校园、我的学习、学生办事、活动预约、校园生活、我的事务。

课程表与教学班资料沿用 CAL、TCH 等原有需求。新增本人已发布成绩查询、本人已发布考试安排查询及支撑它们的数据维护。选课、排课优化、补考、学籍和收费流程仍待独立评估。原 v0.2 的 106 项目录与 61 个核心验收案例保留，本补充不把新增项伪计为已经覆盖。

## 新增功能与职责

| 编号 | 功能 | 设计要求 |
| --- | --- | --- |
| EDU-Q01 | 本人成绩查询 | 按学期查询已发布且归属本人的成绩；显示课程、学分、结果及数据更新时间；没有已发布成绩时显示空状态；不推算尚未确定规则的绩点 |
| EDU-Q02 | 本人考试查询 | 按学期查看已发布的本人考试安排；显示课程、时间、地点及座位等有来源的字段；未发布时明确说明，改期或撤销发布同步更新个人查询与相关提醒 |
| EDU-Q03 | 学习信息受控维护 | 授权教务信息维护岗位按所属学院、学期与课程范围导入、检查、发布或更正数据；导入错误不得直接发布；学生和学生 Agent 没有录入、改分或发布权限 |

教务信息维护是服务人员的专门岗位，系统管理员、普通教师和普通服务人员不因身份自动取得此权限。具体字段、导入格式、发布版本及更正规则在接口与数据设计阶段细化。不得采用学生在查询页面直接编辑成绩的方式生成演示闭环。

## 页面与数据范围

| 页面标识 | 页面 | 需求与关系 |
| --- | --- | --- |
| STU-LEARN | 我的学习 | 本人课表、教学班资料与通知，连接以下学习查询页 |
| STU-GRADE | 成绩查询 | EDU-Q01；学期筛选、只读结果与空状态 |
| STU-EXAM | 考试安排 | EDU-Q02；学期筛选、本人安排与未发布状态 |
| OPS-EDU | 教务信息维护 | EDU-Q03；岗位范围、导入预览、错误校验、发布、更正与审计；尚未制作岗位端原型 |

查询必须在后端以认证学生身份限制数据归属，不能接受任意学生 ID 并直接返回记录。敏感查询由学生主动发起；首页和 Agent 的自动建议不弹出成绩明细。具体学生和课程关联不通过文本姓名匹配。

## 新增验收设计

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| EDU-AC01 | 查询本人某学期成绩 | 只显示本人且已发布的结果；切换学期后结果与学期一致 |
| EDU-AC02 | 跨学生查询成绩或考试 | 拒绝越权；页面隐藏和 Agent 提示不能代替接口校验 |
| EDU-AC03 | 数据尚未发布 | 普通学生与其 Agent 不读取草稿；空状态不把成绩标记为零分 |
| EDU-AC04 | 导入存在错误或重复 | 给出明确错误；不产生重复记录，不发布未确认数据 |
| EDU-AC05 | 考试改期或撤销发布 | 个人查询与提醒一致，保留授权维护审计 |
| EDU-AC06 | 学生成绩变更请求 | 学生不能写入或发布成绩；由授权维护流程处理，记录变更来源 |

这些是待实现的验收要求。原型只验证本地学期筛选、空状态、页面跳转和学生操作呈现，不验证真实后端权限、数据导入、审批或审计。

## 历史原型

学生门户使用同一套虚构个人记录。证明补充、维修确认、学生请假、空间预约、活动报名与申请撤回可演示；申请需要学生核对并手动确认，提交不表示已经审核通过。住宿调整与社团加入提供本人申请入口，没有宿舍分配和社团管理操作。

AI 保持右下角单一角色入口，支持局部示例对话、页面建议关闭/暂停及若干动作。回复读取原型内本人示例状态，不连接真实模型或学校业务系统。聊天不会自行提交申请。

业务规则完整实现仍以 v0.2 与后续接口设计为依据；原型中的固定示例日期、空间时段和课程不是正式校园制度。
