# 学生请假与辅导员处理验收

验收日期：2026-10-08，Asia/Shanghai。对象为 Java / Vue 工程的 V9 迭代。业务记录、账号和规则均为毕业设计演示，不代表郑州工业应用技术学院实际请假制度。

后续进展：2026-10-09 已完成证明事项、统一本人办事与消息分页，入口调整为从“我的办事”进入请假，并为新消息增加受当前权限控制的申请跳转。见[V10 证明与办事验收](./证明办理与我的办事验收-2026-10-09.md)。下方保留 V9 交付时的范围、验证及后续建议。

本轮完成学生请假与辅导员办理闭环：学生保存草稿、提交、补交或撤回；负责行政班的辅导员记录意见并通过、拒绝或退回；通过后生成本人请假日程。管理员维护负责关系，普通任课教师和管理员不会因此获得申请资料阅读权。

## 1. 入口与演示

当前本地前端为 `http://127.0.0.1:18090/`，后端 18080。默认启动方式和端口配置见[工程 README](../README.md)。

| --- | --- | --- |

| 辅导员 | `counselor1001` | `/workbench`：当前请假待办数量；`/student-affairs/leave`：负责班级的申请 |

本地初始演示密码 `Demo@2026`。首次启用演示初始化时新增 `counselor1001`，叠加教师和辅导员身份，在符合条件时负责信息工程学院的 `2026级演示1班`。其他班级须显式配置。初始化不覆盖已有账号密码、角色或负责关系；清空关系后重启也不会自动恢复。

体验流程：学生新建未来时间的事假草稿，保存后提交；退出并切换辅导员，填写意见退回补交；学生修改并重新提交；辅导员通过后，学生查看本人日程和办理记录。正式规则和材料要求须在真实制度确认后配置。

## 2. 状态、字段与一致性

| 当前状态 | 学生可执行 | 辅导员可执行 |
| --- | --- | --- |
| 草稿 `DRAFT` | 编辑、补充材料、提交、撤回 | 不可查看未提交草稿 |
| 待审核 `SUBMITTED` | 查看、撤回 | 查看、通过、拒绝、退回补交 |
| 待补交 `RETURNED` | 编辑、补充材料、重新提交、撤回 | 查看资料和历史，等待重新提交 |
| 已通过 `APPROVED` | 只读查看和本人日程 | 只读查看 |
| 已拒绝 `REJECTED` / 已撤回 `WITHDRAWN` | 只读查看；需要办理时新建申请 | 按当前负责关系只读查看 |

- 必填类型（事假、病假、其他）、起止时间、事由和联系手机或邮箱。服务端确定学生身份与行政班，申请人不能指定审核人。
- 结束时间晚于开始时间；单次最多 30 天是明确标注的演示参数。草稿允许保存过去时间，提交及重新提交须开始时间在未来；结束时间已到的待审核申请不能通过。
- 未分配行政班不能建档；有行政班但没有有效辅导员时可保存草稿，禁止提交。本人不能审核自己的申请。
- 待审核、待补交、已通过记录占用本人时间区间，重叠申请不能提交，待补交编辑和通过时也复查。相邻区间允许；拒绝或撤回释放这项占用。这里的占用仅限制请假申请，不调整教学安排。
- 创建草稿使用本人范围内唯一的请求标识。初次请求重试且内容一致时返回原草稿，不生成重复申请或历史；内容不同或原申请已更新时返回冲突。
- 所有修改、材料、提交、撤回和处理检查版本；成功操作递增版本并保存当时完整资料。旧请求不能覆盖新状态。申请批准和日程生成在同一事务中，来源申请 ID 唯一，重复通过不重复生成日程。
- 请假和账号组织修改使用同一个基础管理写锁，串行核对当前身份、班级和负责关系，避免移交或停用时仍按旧关系写入。本地并发测试覆盖通过与撤回竞态、重叠申请同时提交。

最近处理意见独立保留。学生编辑或补充材料后仍能看到补交要求；历史中保留旧事由、联系方式、时间、意见及当时附件。

## 3. 权限与负责关系

| 操作 | 服务端范围 |
| --- | --- |
| 学生查询、修改、历史及附件 | 当前有效学生权限，且申请所有者是本人 |
| 辅导员查询、历史、附件与处理 | 当前启用账号，同时具备教师和辅导员身份；与负责行政班同学院；申请已提交过且不是本人申请 |
| 管理员维护负责关系 | 基础管理权限；候选人员来自同学院有效教师兼辅导员；版本和原因必填 |
| 普通教师、教务、编辑、服务人员 | 岗位本身不授予请假阅读或审核权限 |

角色权限与负责班级分别校验。只具备辅导员身份但未负责班级的账号没有他人申请。教师授课关系不参与请假审批。越权申请对象返回 404；无功能权限返回 403；旧会话仍执行既有实时身份校验。

负责人员移交后，新人员按当前关系获取该班已提交过的记录，旧人员立即失去当前资料、历史和附件访问权；待办由当前申请状态与负责关系计算，不保留旧审核人的可处理副本。有待审核或待补交申请时不能清空负责关系，也不能移交给正在办理本人申请的人员。行政班修改记录留存移交原因、人员和版本，不复制请假隐私。

已分配负责班级的辅导员不能直接停用、移除教师或辅导员身份、调离学院，须先移交或清空负责关系。存在未完成申请的学生不能直接变更行政班或移除学生身份；学生草稿可在归属变化后重新保存为当前班级。行政班专业变更继续检查人员引用，并补充负责关系约束。

## 4. 材料、消息与页面保护

- 私有材料支持 PDF 或 UTF-8 `.txt`，大小 1 字节至 2 MB。PDF 检查文件头，文本检查 UTF-8 编码和扩展名，清理文件名中的路径分隔符与控制字符。文件头校验不等于完整安全检测。
- 仅草稿或待补交状态可上传；每次上传生成独立文件版本，旧附件仍与当时历史绑定。下载逐次校验本人或当前负责关系，使用附件下载、`no-store` 和 `nosniff` 响应。
- 本轮附件为可选资料，辅导员可通过退回意见要求补充；尚未实现按假别或天数配置必需材料，因此需求基线中的“缺必需材料不进入审批”尚未完整落地。
- 提交、撤回和处理产生个人消息；消息只含申请编号和状态提示，不复制原因、联系方式或材料。学生通过结果生成本人日程，辅导员工作台显示实时待审核总数。
- 列表、历史分页并校验参数；状态、页码、申请 ID 和当前栏目写入 URL，刷新恢复已保存记录。查询某月日程采用结束日期不包含的区间；跨月申请按相交范围查询。
- 未保存表单、审核意见或待上传材料在切换页面、记录、栏目、刷新列表或取消编辑时提示；选择继续编辑保留输入，浏览器刷新提示由 `beforeunload` 保护。请假隐私文字未写入本地存储，保存草稿才可在服务器恢复。
- 管理员负责关系表单也有离开和取消保护；失败后保留输入，防止版本冲突导致文字丢失。上传材料失败时保留文件选择，成功后清理。
- 桌面沿用校园门户主题、完整业务名称和说明；390px 下表单改单列，表格内部横向滚动，确认框保持在视口内。

## 5. 接口与数据库

| 接口 | 用途 |
| --- | --- |
| `GET /api/leave/mine/eligibility` | 本人行政班、当前负责辅导员及是否可提交 |
| `GET /api/leave/{mine\|review}` | 本人或负责班级列表，状态及分页 |
| `GET /api/leave/{mine\|review}/{id}`、`/{id}/history` | 受控详情与版本历史 |
| `POST /api/leave/mine`、`PUT /api/leave/mine/{id}` | 建档或编辑 |
| `POST /api/leave/mine/{id}/{submit\|withdraw}` | 提交及撤回 |
| `POST /api/leave/review/{id}/decision` | 通过、退回补交或拒绝 |
| `POST /api/leave/mine/{id}/file?version=...` | 上传材料 |
| `GET /api/leave/files/{id}?view=mine\|review` | 下载受控材料 |
| `GET /api/leave/mine/calendar?from=...&to=...` | 本人已通过日程 |
| `GET /api/admin/counselors`、`PUT /api/admin/counselors/{classId}` | 负责关系查询维护 |

## 7. 尚未完成

本轮在 H2 完成验证，MySQL 配置及 V9 方言尚未联调。正式校内登录、真实学籍或考勤、按学校制度的材料与多级审批、销假与已通过申请变更、在校证明结果文件、批量处理、催办转交、完整消息分页、统一跨业务日历、Agent 均未接入。私有附件当前存数据库，尚无对象存储与病毒扫描；负责关系目录尚未分页，规模扩大时需补齐查询。
