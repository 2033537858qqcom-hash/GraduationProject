# 学生门户功能校正与高校调研 v0.1

日期：2026-10-03。

用户已选择“校园门户”作为学生端的布局方向，并同意功能校正。本文校正登录后的学生功能与首页优先级。新增教学查询通过[学生端教学查询补充](./学生端教学查询补充-v0.1.md)纳入设计，使用独立功能、页面与验收编号；未自动计入原 v0.2 的目录数量，不能视作已经开发完成。

## 官方资料依据

- [上海科技大学本科教务管理系统常用问题](https://it.shanghaitech.edu.cn/2021/0419/c8344a62924/page.htm)：官方说明列出学生登录、我的课表、我的考试、我的成绩、选课及教室借用。考试信息须在排考结果发布后向学生展示，学生成绩支持按学期查询。此资料用于辨认学生任务，不直接采用其选课或审核规则。
- [北京大学网络服务：新生指南与校内信息门户](https://its.pku.edu.cn/about_8.jsp)：官方说明把校内公告、个人课表、成绩、课程评估、常用功能、个人信息与待办归入门户服务，并列出图书馆、教学网和校园卡等入口。说明真实门户可汇聚多个业务系统，功能入口不表示门户自身实现全部业务。
- [中央民族大学智慧门户说明](https://yx.muc.edu.cn/shuzixiaoyuan/xinximenhu/)：官方页面列出面向学生的请假、住宿、学生证补办、空间预约等事项，并描述学生查看本人课表、接收课程资料和教师通知的使用方式。学生提交申请，具体审核与处理由相应岗位承担。
- [东华大学一站式学生服务大厅业务公告](https://www.dhu.edu.cn/2024/0227/c5974a420523/pagem.htm)：学生服务涉及证明、学生证、勤工助学、奖助及生活服务。公告描述线上线下综合服务，不能据此声称全部事项均可在线完成。

各校业务与系统边界不同。以上资料支持学生任务分类；不照搬某一高校全部模块、审批链、时间限制、收费或初始密码规则。

## 原方案需要校正的地方

证明、请假、报修、活动报名和预约本身符合学生身份。问题是原首页过于突出低频办事，学习查询与课程资料入口不足，通用的“服务”与“事务”表达没有充分体现学生使用场景。

首页不要求学生执行部门管理工作。学生看到的是本人申请、等待本人补充的材料、本人维修结果确认；等待工作人员审核的申请只能查看进度。成绩发布、审批、派单、宿舍分配和资源维护属于不同岗位。

## 学生端功能结构

| 栏目 | 学生实际操作 | 本项目范围处理 |
| --- | --- | --- |
| 我的校园 | 看近期课表、个人提醒、班级通知、本人办理进度及常用入口 | 沿用个人概览，重新安排首页内容优先级 |
| 我的学习 | 查询课表与课程信息、阅读本人教学班资料和通知；查询本人考试安排与已发布成绩 | 课表、资料和班级通知沿用 v0.2；考试与成绩查询为本轮新增核心建议 |
| 学生办事 | 发起请假或证明申请、补充材料、在规则允许时撤回、查看结果 | 请假和证明为已有范围；学生证补办、奖助与其他学籍事项为后续候选 |
| 活动预约 | 浏览开放活动、本人报名/取消/签到、申请加入社团、预约允许学生使用的资源、查询自己的记录 | 沿用活动、社团、资源及日程能力；普通学生没有活动发布或社团成员管理权 |
| 校园生活 | 查询本人住宿、提交宿舍报修、看维修进度、确认本人维修结果、提交住宿调整申请 | 沿用 v0.2；调整申请提交后按岗位处理，学生不能自行分配床位 |
| 我的事务 | 集中查本人发起、待本人处理、处理中和已结束的申请、预约与报名 | 沿用个人记录，状态标签明确区分学生动作与工作人员动作 |

通知和个人资料放在页头。图书借阅、校园卡、缴费等有真实学校参考价值，但当前没有对应系统与完整数据链路，不添加不可用入口或伪造账户余额。毕业就业、奖助及评教等可在学生办事或我的学习中继续评估，不全部堆入首页。

## 首页信息顺序

1. 学校品牌与简短的学生身份欢迎区，校园图片作为辅助。
2. 常用入口优先考虑我的课表、成绩查询、考试安排、学生请假、在读证明、宿舍报修。正式原型只开放已有可演示内容的入口。
3. 近期课程与本人教学班通知占主要阅读区域。课程显示日期、节次或时间、教室、教师；通知显示发布人、所属教学班和更新时间。
4. “需要我处理”显示补充材料、结果确认、待完成的个人动作。“办理进度”显示等待其他岗位处理的本人记录。
5. 活动与生活信息按相关性少量呈现，更多内容进入各栏目。

不添加审核统计、全校工单数量、资源运营数据、人员管理或学生名单。首页不显示完整成绩表、敏感证明材料和身份证信息。横向导航保留所选门户方向，窄屏重新排列，不重新加入长侧栏。

## 教学查询的范围修正建议

v0.2 原始版本排除了成绩业务，考试安排也没有独立功能要求。本轮已通过教学查询补充纳入考试与已发布成绩的本人查询；合并升版时继续细化以下条件：

- 学期、课程、教学班和学生的关联可追溯；课表、考试和成绩各自有数据来源与更新时间。
- 数据可采用受控导入与授权岗位维护，正式查询只返回已发布且属于当前学生的数据。
- 未发布与确无安排分别提示；尚无成绩不显示为零分，也不推算未经确定的绩点。
- 学生及其 Agent 均无录入、改分或发布权限；取消、改期、更正和撤销发布需要处理同步与审计。
- 合并到正式基线时补齐功能编号、页面映射、接口和验收，至少覆盖本人访问、跨学生访问、未发布数据、重复导入与结果更正。

完整选课、排课、补考、学籍异动及收费流程另行评估。新增查询视图不会自动包含这些业务。

## 学生 Agent 职责

入口仍是右下角会动的角色。对话及建议使用当前学生的身份、当前页面与本人业务记录，例如查询下一次上课位置、解释证明所需材料、查本人报修进度或帮助填写预约申请。

角色不得看到其他学生的成绩或申请材料，不处理岗位审批。查询敏感学习结果由学生主动发起，页面建议不自动展示成绩或身份信息。发起、修改或撤回业务先展示操作内容，由学生明确确认，结果写入本人记录并与相关提醒一致。

## 后续原型核对

- 登录后的主体明确为学生门户；教师和工作人员使用各自的业务入口与权限。
- 首页课程、通知、个人动作和本人进度分别清楚，不用“待办”混合全部状态。
- 所有学生入口进入实际栏目页，继续保持无弹窗导航、无重复面包屑、无“返回 XX”。
- 服务入口使用同一套功能匹配的图标，控件紧凑并可在窄屏使用。
- 所有示例数据标明虚构；界面演示、功能需求与实际开发完成状态分开记录。
