# 宿舍关联报修与入住权限验收

日期：2026-10-15。迁移 V19，对应 DOR-06，并复用 FIX 报修流程。工程仍为 0.1.0。

学生在“我的住宿”进入“宿舍设施报修”，预选本人当前房间。地点必须先由管理员关联已建档的宿舍房间；不按房间名称匹配，也不自动创建学校宿舍资料。房间未配置、已停用或学生尚未入住时，页面显示原因。

后续补充：V20 已接入住宿助手查询与调宿预览，见[住宿助手验收](./住宿助手查询与调宿草稿验收-2026-10-15.md)。本篇保留 V19 当时的范围和结果。

## 1. 地点与权限

- `repair_location.kind` 新增 `DORM_ROOM`，`dorm_room_id` 唯一关联房间；不能混用教室或公共楼栋来源。来源校区必须一致且楼栋、房间启用，建档后不能更换来源。
- 学生目录只返回公共地点和本人当前房间；教师没有住宿本人权限时只能选择原公共地点。宿管岗位本身不授予报修工单阅读权。
- `/api/repairs/my-dorm` 返回本人房间是否可报修及最小地点信息，不返回床位、住宿记录 ID 或其他住户。`/api/repairs/locations/{id}` 在预选前重新验证权限。修改 URL 不会获得他人房间权限。
- 新建、编辑、提交与助手保存均经过同一个服务端地点校验。前端预选仅接受正的安全整数；后端仍是最终权限依据。
- 管理员来源目录最多提供前 1000 个房间；学生地点目录按页查询，每页最多 100 条。更多来源的搜索分页仍需后续扩展。

## 2. 调宿、退宿与历史

草稿由服务端绑定发起时的 `housing_assignment_id`，不接受客户端指定入住记录。报修与住宿写操作共用 `foundation_write_lock`，入住切换和工单状态变更串行校验。

调宿预留期间原入住仍有效，原房间报修可以办理；正式确认入住或退宿后原关系结束。旧工单保留给原报修人及当前有工单权限的人员查看，新住户不会获得旧报修人的工单和联系方式。

原入住结束后，禁止继续提交、重新提交、派单、改派、接单、更新进展、交回维修、提交结果、上传移除图片、确认或退回维修结果。取消等待和幂等重试规则沿用原流程：

- 未派单可撤回，后勤仍可要求补充或拒绝以结束旧单。
- 已派单由本人申请取消，后勤同意后关闭；不同意或撤销取消也不会恢复已结束的入住资格。
- 未提交草稿可编辑为当前有效地点并重新保存；已提交记录不能通过再次入住同一房间恢复旧办理资格。
- 已完成的历史工单仍允许本人补交一次服务评价。
- 已结束入住的旧工单不计入本人待补充、待验收及维修人员可办待办，也不再发送待验收提醒。后勤保留待分诊和取消队列以处理收尾。

## 3. 助手与指南

复用已有报修助手的本地预览、人工确认与草稿保存，未新增住宿查询工具或让模型选择宿舍。预览有效后若退宿，保存时再次校验并拒绝旧房间。

V19 对仍含原始“私人宿舍房间暂不开放”段落的报修指南替换该段，版本加一，保留其他内容与发布／撤下状态。已有预览按当前指南版本重新核对。本批没有调用真实模型，不改变之前真实 DeepSeek 评测结论。
