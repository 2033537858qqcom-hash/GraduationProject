# 岗位交接与教学预约共享占用验收

日期：2026-10-25（Asia/Shanghai）。版本：0.1.0，新增 Flyway V33。

## 交付范围

本批接续功能完整性复评，补上服务岗位交接和教学、预约对同一物理房间的占用校验。仍是毕业设计演示系统，不连接学校正式业务库。工作区原有住宿初始化与开题报告相关修改完整保留；未提交这些用户改动。

### 岗位交接

- 账号列表增加“交接检查”，展示行政班、预约资源、后勤派工／维修范围、宿舍楼栋，以及学院最后一名有效审核人员的独有待办数量。范围与事项分开计数；交叉负责的业务数量不能直接相加作为事项总数。
- 普通停用要求先移交或清空负责范围，并处理独有在办维修、学院审核事项。移除对应办理权限或学院归属前也会校验。原有学生在途申请、辅导员分班和有效教学关系保护继续保留。
- “紧急停用”须在停用对话框明确勾选并填写原因，立即递增安全版本、撤销旧会话；保留业务历史与配置关系，单独记录 `USER_EMERGENCY_DISABLE`。不能借此停用当前管理员或绕过最后一名管理员保护。可选参数未传或为 null 时使用普通启停语义，兼容既有调用。
- “责任异常”按当前有效账号、岗位、负责范围及非本人审核条件汇总：开放资源无人办理、未结束预约无人办理、请假辅导员失效、证明／调宿初审无人处理、报修派工／维修人失效、调宿分配／入住确认无人处理。
- 异常页与交接检查只返回数量和固定配置入口，不返回事由、电话或材料。访问要求 `foundation:manage`；跳转入口按原有域权限显示，不自动授予管理员预约审批或其他业务权限。
- 接任流程：先核实新人员岗位，再在对应配置页移交范围；在办维修还须由有效派工人员改派。接任后刷新异常检查。系统没有新增一键复制角色或自动替人审批。

### 教学与预约共用物理房间

- V33 在预约资源增加可选 `classroom_resource_id`、外键和唯一约束。只允许同一校区的场地关联已补齐资料且有效的教学教室，设备不可关联。每间教室至多关联一个预约资源。
- 新增资源和既有资源配置页均提供关联入口、当前教室和变更原因。既有资源变更关联须核对版本，有使用中或未结束待审／已批准预约时禁止换绑或解绑。
- 不按名称或地图地点猜测同一教室，不回填现有关系。未关联资源仍只使用自身预约规则，页面明确提示这一边界。
- 课程和已发布考试阻止重叠预约；待审、已批准、使用中预约阻止重叠课程和考试发布。考试草稿不占用，撤回／取消释放预约时段；前后相邻时段可正常安排。
- 超时但尚未结束核销的使用继续阻止新排课／考试，直到实际交接完成。预约排期加入最少必要的教学占用信息，不暴露教学班、教师或学生信息。
- 预约提交与使用登记复核关联教室启用、完整资料和人数容量。教室停用与容量下调检查关联预约；教学引用与预约关联均保护已确定的物理位置。
- 教室占用列表合并课程、考试、预约与使用中记录。教学写入和预约写入复用数据库行锁，按 `foundation_write_lock` → `teaching_write_lock` 顺序，避免并发双方同时通过检查。

- 没有修改日常数据库、infra/.env 或密钥，没有调用真实 DeepSeek／COS 服务。

## 部署与使用

后端重启后由 Flyway 自动应用 V33；请先按既有流程备份实际使用的库。本次 H2 全量验证不能替代目标 MySQL 上的最新迁移、并发及回滚恢复验收。历史 MySQL 验证仅到 V24，本批不提升这一结论。

管理员从“账号与组织管理 → 交接检查／责任异常”进入。预约资源配置人员从“场地与设备 → 资源配置 → 关联教学教室”进入，必须实际确认房间后绑定。配置前请先补齐教学教室的校区、楼栋、房间和容量。

## 保留的缺口

- 尚未实现全校人员入校、毕业、离岗的统一编排；教师未来授课与批量换师、内容审核队列交接等不在本批完成范围。
- 责任异常是按需读取和刷新检查，没有新增定时派送的全域预警。各业务负责范围配置本身仍沿用原有规则，不等于所有范围变更均已实现强制交接。
- 未关联的预约资源不能与教学共享占用；多场地组合、可拆分大空间、多件设备库存领还、结构化维护停用窗口未实现。
- 尚需推进个人统一日程、业务结果更正、Agent 知识维护及最新 MySQL／备份恢复／自动浏览器回归等交付能力。
