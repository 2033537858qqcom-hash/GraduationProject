# 报修地点与岗位范围基础验收

日期：2026-10-12，Asia/Shanghai。工程版本 0.1.0，数据库 V13。配套 [报修需求与开发设计](./校园报修需求与开发设计-v0.1.md)。

本批完成报修模块的地点、岗位和负责范围基础，尚未完成报修工单闭环。已有教学、请假、证明及 Agent 的功能保留；本批未调用付费模型。

## 1. 实际交付

| 能力 | 已实现行为 |
| --- | --- |
| 开放报修地点 | 管理员按校区添加、编辑、启停、搜索和分页；支持教室、楼栋公共部位、校园公共区域 |
| 资源关联 | 按明确教室或楼栋 ID 配置，同校区校验；不按房间的楼栋文字猜测建筑 ID；私人宿舍不开放 |
| 来源有效性 | 来源教室停用、资料不完整或校区发生变化时，不再进入师生可用目录；重新开放再次检查当前来源 |
| 地点资料 | 展示名称、位置提示、明确的演示或管理员配置标记；配置标记不代表学校真实性核验；建档后位置身份及来源 ID 不允许直接替换 |
| 新岗位 | `REPAIR_DISPATCHER` 后勤派单岗位、`REPAIR_TECHNICIAN` 维修岗位；分别授予派单或维修能力和既有工作台、Agent 查询能力 |
| 负责范围 | 管理员按人员、能力、校区、故障类别配置，可限定具体地点；同一范围不能重复建档，停用记录可重新启用 |
| 当前资格 | 每次读取或匹配核对当前账号、能力和范围状态；撤销岗位或停用范围立即使对应范围失效 |
| 本人职责 | 后勤、维修人员仅查看自己的范围及失效说明，不能维护管理配置；尚无工单任务入口或模拟待办数量 |
| 编辑保护 | 未保存内容在切换分类、刷新、离开时有提示；取消离开保留文本，保存时防重复点击；版本冲突不覆盖正在编辑的内容 |
| 修改记录 | 建档、编辑、启停需说明；显示操作者、动作及时间，也进入通用管理审计筛选；失败不追加半份记录 |

管理员配置权限不自动获得未来私有报修资料访问权。学生、教师只能使用最小字段地点目录接口；教师没有因此获得学生请假、证明或学生门户权限。

故障类别为毕业设计演示配置：给排水、电气照明、网络、家具、门窗、设备、其他。原有教室目录包含待补录资源，不能仅凭历史房间名称开放为有效报修地点。

## 2. 页面、接口与迁移

实际页面：

- `/admin/repair-settings`：管理员“报修配置”，开放地点与人员负责范围两类内容。
- `/logistics/repair-responsibilities`：当前后勤或维修人员“我的负责范围”。

两条路由已加入受限的登录回跳清单，匿名访问登录后回到原页面；未知路径不会通过开放跳转规则绕过校验。门户与工作台使用图标、完整功能名称及简短说明，沿用深蓝校园主题和顶部导航。

| 实际接口 | 用途 |
| --- | --- |
| `GET /api/repairs/catalog` | 师生校区与类别目录 |
| `GET /api/repairs/locations` | 当前有效开放地点的最小字段分页目录 |
| `GET /api/repairs/responsibilities` | 当前人员本人的负责范围 |
| `GET /api/admin/repair-settings/catalog` | 管理配置所需校区、类别、来源资源和岗位人员 |
| `/api/admin/repair-settings/locations` | GET 分页搜索；POST 建档；`/{id}` PUT 修改；`/{id}/state` POST 启停 |
| `/api/admin/repair-settings/scopes` | GET 分页；POST 建档；`/{id}` PUT 修改；`/{id}/state` POST 启停 |
| `GET /api/admin/repair-settings/history` | 按 `LOCATION／SCOPE`、对象编号分页读取配置历史 |
| `GET /api/admin/foundation/audit` | 原通用管理审计新增 `REPAIR_LOCATION／REPAIR_SCOPE` 类型筛选 |

[V13 迁移](../backend/src/main/resources/db/migration/V13__repair_foundation.sql)只新增 `repair_location`、`repair_staff_scope` 两张表及相关角色、权限、约束和索引。配置写入沿用管理事务锁和版本校验，建档重复约束与状态变更失败均回滚。未来工单的请求键、附件、取消、消息扩展尚未加入本次迁移。

## 3. 本地体验

本轮前端为 `http://127.0.0.1:18090/`，后端 18080。使用默认本地演示密码 `Demo@2026`：

| 账号 | 本批入口与初始范围 |
| --- | --- |
| `admin` | “报修配置”，维护地点与人员范围 |
| `dispatcher1001` | “我的负责范围”，东校区七类派单范围 |
| `technician1001` | “我的负责范围”，东校区七类维修范围 |

仅演示初始化启用时创建两个新账号及“后勤服务部门（演示）”。已存在的同名账号不会被覆盖，重启不恢复已撤销岗位、已调整范围或密码。新账号的初始范围不表示学校实际后勤人员职责。

主库没有自动添加报修地点。管理员可在核对资料后建档；若试用演示地点，应明确选择“演示”来源标记。校园公共区域不需要伪造楼栋关联，教室与楼栋公共部位必须选择正确来源资源。
