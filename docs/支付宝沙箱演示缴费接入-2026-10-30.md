# 支付宝沙箱演示缴费接入

日期：2026-10-30。当前为本地开发版本，仅使用支付宝沙箱网关，不使用真实资金。

## 使用流程

管理员登录后，在“演示账单管理”为启用的演示学生创建账单；学生从“演示缴费”查看本人账单，核对名称和金额后发起支付宝沙箱支付。重复发起使用同一个商户订单号；支付完成后回到页面刷新状态。创建账单需要 `foundation:manage`，学生访问需要 `portal:read` 并检查账单归属。演示数据开关 `app.demo.enabled` 关闭时，整个演示缴费流程关闭。

异步通知仅对指定 POST 地址免登录和 CSRF；服务端验 RSA2 签名并核对应用 ID、商户 ID、订单号、金额、交易号和成功状态，重复通知只记账一次。网页返回并不会直接标记已付款。

## 沙箱配置

默认 `PAYMENT_ENABLED=false`。取得同一个支付宝沙箱应用的配置后，在后端进程环境中设置：

```powershell
$env:PAYMENT_ENABLED = 'true'
$env:PAYMENT_APP_ID = '<沙箱应用 ID>'
$env:PAYMENT_SELLER_ID = '<沙箱卖家 ID>'
$env:PAYMENT_PRIVATE_KEY = '<应用私钥，PKCS8 格式>'
$env:PAYMENT_ALIPAY_PUBLIC_KEY = '<沙箱支付宝公钥>'
$env:PAYMENT_NOTIFY_URL = 'https://<可公开访问的域名>/api/payments/alipay/notify'
$env:PAYMENT_RETURN_URL = 'http://127.0.0.1:5173/portal/payments'
```

后端默认只监听本机，平台通知需要一个可访问的测试 HTTPS 地址转发到后端。不要把真实密钥放入仓库或聊天记录。当前实现固定使用 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`，实际联调时应核对沙箱控制台提供的网关是否一致。

## 验证边界

已使用本地生成的 RSA 密钥覆盖正常及篡改的通知、重复通知、不同学生的账单隔离、重复创建、重复支付和已付账单保护；使用真实 Spring Boot HTTP 服务检查回调匿名访问范围。此前的 IJPay 兼容性测试还覆盖本地模拟网关和请求签名。所有测试均不调用支付平台。

2026-10-30 全量检查：后端 `mvn -B test` 共 522 项，521 通过、0 失败、0 错误、1 项外部 COS 条件测试跳过；前端 205 项测试及构建通过，lint 有 1 条既有格式警告。支付页面浏览器实机验收未完成；尝试时电脑操作工具无法可靠确认浏览器 URL，操作已停止。

当前没有支付宝沙箱账号，因此尚未验证平台侧真实下单、用户收银体验和外部通知。尚未实现主动查单补偿、退款、对账、正式收费规则、业务收费关联和生产收款；如果通知丢失，账单会保持待支付，不能凭前端跳转显示已支付。上线真实收费前需要补齐上述流程并完成平台联调。
