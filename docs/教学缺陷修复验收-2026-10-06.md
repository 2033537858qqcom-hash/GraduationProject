# 教学缺陷修复验收

日期：2026-10-06。对应[项目不足检查](./项目不足检查-2026-10-06.md)的 F01—F03，是推荐顺序中的第一批交付。

## 已完成的修复

| 问题 | 修复后的行为 | 边界 |
| --- | --- | --- |
| F01 学生关系后加／恢复绕过冲突 | 新增或重新启用学生关联前，比较该班已有课程、已发布考试与学生其他有效教学班安排；有重叠返回 409，关系、审计与通知均不写入 | 原有有效关系的重复启用保持可用；停用关系不需冲突校验 |
| F02 课程与考试彼此不查 | 共用占用校验同时读取课程与已发布考试，检查教学班、教师、校区与教室、有效学生；课程新增与考试发布两种顺序均受保护 | 考试草稿不占时间；相邻区间允许；教师约束用于课程，考试尚未建监考岗位 |
| F03 教师未保存文字丢失 | 资料与通知按账号、教学班分别暂存，切换教学班、内部页面和刷新可恢复；保存资料保留通知，发布通知保留资料 | 文字在当前标签页 sessionStorage 保留 24 小时，退出／会话失效清除；附件仅留在运行内存，刷新后提示重新选择 |

放弃资料修改前显示确认，可继续编辑。提交失败保留输入；写入过程中阻止普通页面跳转，退出或会话失效仍可回到登录页。浏览器禁用存储或空间不足时使用内存暂存，显示提示，并在关闭或刷新时请求浏览器离开提示。草稿恢复保留原资料版本号，服务端版本冲突仍返回 409，防止覆盖别人已更新的版本。

课程记录在教师关联停用后仍保留占用；撤下考试会释放考试占用。所有相关写操作继续使用同一事务内的数据库锁，冲突检查和写入不会被并发操作拆开。教室仍以校区 ID＋教室文本匹配，稳定教室目录属于下一阶段；本轮没有建立教室资源表。

实现入口：[共用安排校验](../backend/src/main/java/cn/zzuit/campus/teaching/TeachingScheduleService.java)、[教学写入](../backend/src/main/java/cn/zzuit/campus/teaching/AcademicService.java)、[教师页面](../frontend/src/pages/LearningPage.vue)、[草稿暂存](../frontend/src/lib/teachingDrafts.ts)。

## 接下来的实施顺序

用户已同意按检查建议推进；以下为下一阶段范围，尚未实现。

1. **基础管理**：学院、行政班、账号启停与角色／岗位范围维护；将内容接口的会话权限快照改为实时校验，验证停用与撤权后旧会话失效；建立可重复的 MySQL 联调环境。
2. **内容管理闭环**：驳回、撤回、更正、撤下与版本记录，把官网可维护栏目逐步接入后台。
3. **请假与审批闭环**：学生申请、对应岗位待办、补交／撤回、审批结果、本人事务与消息记录，先完成一条跨角色流程。
4. **Agent**：先接学校／办事规则检索及本人课表等只读工具，再加入申请草稿和确认提交；复用服务端权限及业务校验。

下一次开发先完成账号／组织管理及实时权限校验；不将全量平台范围算作本次修复完成。
