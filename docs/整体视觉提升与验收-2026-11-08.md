# 整体视觉提升与验收

日期：2026-11-08。目标：整体有记忆点，同时保持校园服务应有的清楚、从容与协调。

## 设计落地

沿用校园实景、纸白、墨绿、宋体标题。官网承担校园气氛，门户承担个人日常，业务页强调阅读和操作，三维页承担探索；各场景共享字体、圆角、品牌与状态规则。

| 场景 | 本轮落地 |
| --- | --- |
| 学生门户 | 欢迎区增加墨绿日程入口，直接展示真实接口返回的下一堂课、时间、教室及教师；无课程时显示日程入口。常用服务提前至欢迎区下方，消息和办事作为次级线索。手机保留短幅校园影像，并在第一屏呈现常用服务。 |
| 校园助手 | 默认从目标和示例提问开始，突出“帮我办一件事”；原有七类服务方式收进原生可展开区域。查询结果、输入区和主操作拉开层次；所有原有权限、模型选择、同意发送及任务组件继续保留。示例提问仅填入输入框，实际发送仍由用户操作。 |
| 岗位工作台 | 用墨绿待办数字块建立焦点，欢迎区与任务区回归纸白，强化任务标题和辅助文字的区分，减少空状态的框套框。 |
| 办事页面 | 加深正文、字段值和说明的对比；统一表格和筛选区域的层次，当前办理步骤使用实色标识。业务状态色继续表达各自含义。 |
| 三维校园 | 降低曝光和环境光，采用暖日光和灰绿环境；修正颜色纹理的色彩空间并启用远景过滤。底板不再使用窗格立面纹理，屋顶使用纯色石材纹理坐标，立面保留窗格。保留原有地理数据、建筑轮廓、选择和相机控制。 |
| 动效 | 门户进入只做短距离淡入，服务入口使用轻微反馈；助手自主动作间隔由 6–11 秒延长至 18–28 秒。遵循系统和页面的减少动态设置。 |

## 当前证据

本轮浏览器检查使用当前生产构建与真实 Spring Boot 接口，后端为独立内存 H2 演示库；学生、管理员、财务经办均通过真实登录接口进入。没有连接日常数据库，没有调用付费模型或实际付款。

- 桌面 1440px、平板 768px、手机 390px、窄屏 320px。
- 检查门户、办事总览、请假、证明、报修、预约、住宿、缴费、学习、资料、校园探索、岗位台、基础管理和财务页面。
- 助手实际执行：展开服务方式、进入目标办理表单、示例填入、本地查询及结果呈现。
- 三维实际执行：总览、暮色切换、目录选择图书馆及相机定位。
- 额外检查减少动态设置；无课程分支使用仅拦截课程数组的受控数据，独立标记为 `portal-empty-controlled-small.png`。
- `checks.json` 累计 111 条记录，按名称、路径和宽度去重为 88 项；重复项来自材质修复后的复验。未发现横向溢出、越界助手面板、可见业务错误、运行异常或页面 console error。
- 官网九个章节、两张首屏影像与登录在 1440 / 390 / 320px 下复查，共 33 项，未发现横向溢出或浏览器运行错误。记录另存 `public-checks.json`，与业务页记录分开。

检查通过：`pnpm build`、`pnpm test`（261/261）、`pnpm lint`、`pnpm check:design`、`pnpm check:campus`、`git diff --check`。

校园专项保持 30 个可选择地点、46 个描摹要素、39 个根网格、8,116 个三角形。新增回归直接检查东、西校区屋顶纹理坐标，以及东校区网格预算。

颜色字面量从 1,376 减至 1,338，预算同步收紧；`!important` 116、小字号声明 100 均未增加。
