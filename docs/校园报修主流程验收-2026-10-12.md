# 校园报修主流程验收

日期：2026-10-12，Asia/Shanghai。工程版本 0.1.0，数据库 V14。配套 [报修设计](./校园报修需求与开发设计-v0.1.md)和 [V13 地点与岗位基础](./报修地点与岗位范围基础验收-2026-10-12.md)。

本批完成师生报修、后勤派单、维修处理、本人验收与一次评价的主流程，接入私有图片、历史、消息、实际待办和学生“我的办事”。同时支持补充、拒绝、撤回、改派、无法维修交回和验收退回。派单后取消、统计、自动提醒及报修 Agent 尚未实现，完整设计中的全部验收标准仍未完成。

## 1. 实际流程

师生填写故障并保存草稿；草稿允许缺地点、类别、联系方式等提交必填项，全空资料不建档，非空字段仍校验形状和长度。保存后可上传故障图片，确认后才提交。

提交重新核对开放地点、当前来源及有效后勤范围。缺有效后勤时保留草稿并说明原因；提交后的地点和类别固定，名称使用当时快照。后勤在当前校区、类别及具体地点范围内分诊，可以要求补充、拒绝，或选择具当前资格和范围的维修人员。后勤、维修人员都不能办理自己的报修。

维修人员接单后进入处理中，可记录进展、上传图片、说明无法处理并交回后勤，或提交结果。结果只进入待本人验收；报修人核对结果轮次，可说明未解决继续处理，也可确认完成。确认后只允许报修人评价一次，不生成默认评价，不覆盖旧维修轮次。

| 状态 | 主要可执行行为 |
| --- | --- |
| 草稿 | 本人编辑、图片维护、提交或撤回 |
| 待后勤分诊 | 后勤要求补充、拒绝、派单及设置优先级；本人可撤回 |
| 待补充资料 | 本人修改说明、联系信息、图片，重新提交或撤回 |
| 待维修接单 | 当前维修人员接单；后勤可改派及设置优先级 |
| 维修处理中 | 当前人员记录进展、交回、提交结果；后勤可改派 |
| 待本人验收 | 报修人确认解决或说明未解决；其他人员不能代为验收 |
| 已完成 | 保留结果及历史，报修人可进行一次 1—5 星评价 |
| 已拒绝／已撤回 | 原记录只读，重新办理须新建 |

改派保留旧分配及处理历史，不能改派给当前同一人员；旧维修人员立即失去工单、历史及图片读取权限，旧消息仍保留文字但没有可访问链接。负责范围停用、岗位撤销等也按当前配置生效。地点停用不删除已提交历史，阻止新的提交。

## 2. 图片、历史与重复操作

图片为受控 JPEG／PNG，每张不超过 2 MB；核对实际读取格式，解码前检查尺寸，最多 8000×8000 且总像素不超过 2000 万。故障最多 6 张，当前进展和每轮结果各最多 3 张。尚无图片压缩、缩略图或病毒扫描，当前通过认证接口下载查看。

故障图片在草稿或待补充时维护；维修人员只在处理中上传进展或本轮结果。移除当前图片只改变当前资料引用，历史继续保留；完成结果通过独立关联表冻结当时选用图片，已移除的结果图片不会重新混入完成反馈。结果提交后不再普通编辑其说明和图片。

列表和消息只包含必要摘要，不返回联系方式、完整故障或历史全文。详情、历史及图片下载都重新核对本人归属、后勤当前范围或当前维修分配；管理员配置权限不取得这些资料阅读权。图片不使用静态公开路径，下载响应 `no-store`、附件处置与 `nosniff`。

每个写动作携带当前版本和操作请求键。服务端在重新鉴权后识别重复请求，再验证状态及版本；相同键与内容返回原操作关联工单的当前结果，相同键不同内容冲突。前端失败重试保留同一键，字段、版本或接口变化后使用新键。输入摘要只保存 SHA-256，私有资料快照位于受控历史中，不写入管理审计或普通日志。

状态、分配、维修结果、图片引用、历史与站内消息在同一事务内执行。沿用管理事务锁，使范围调整与工单操作使用一致锁顺序；并发不同请求派单仅一个成功，失败不留下半份历史或消息。当前锁为单体实现，尚未做高并发性能验证。

## 3. 页面与平台整合

| 页面 | 路由与职责 |
| --- | --- |
| 师生我的报修 | `/repairs/mine`，新建、筛选、本人详情、资料编辑、图片、验收与评价 |
| 后勤分诊派单 | `/logistics/repairs/dispatch`，当前范围分诊、补充拒绝、派单改派与优先级 |
| 我的维修任务 | `/logistics/repairs/tasks`，默认全部本人任务，可按状态筛选、接单及反馈 |
| 既有配置 | `/admin/repair-settings`、`/logistics/repair-responsibilities` 继续使用 |

工单采用真实页面详情和办理记录栏目，查询参数保留选择和历史页码；短动作通过确认对话框核对。未保存编辑、处理说明、人员选择和待上传文件有离开保护；取消离开保留文本。服务端草稿刷新可恢复，不把联系方式或图片长期存入浏览器存储；未上传文件刷新后需要重新选择。

学生常用服务和“我的办事”新增完整业务名称、说明与 Wrench 图标；教师在本人工作台和顶部导航进入独立报修，未获得学生请假、证明或门户权限。后勤、维修工作台显示当前授权范围及分配计算的待办数量。处理后待办数变化，未读消息不充当待办。

站内通知涵盖提交、补充拒绝、派单改派、接单进展、无法处理、结果、验收退回与完成、撤回。`REPAIR` 视图区分 `MINE／DISPATCH／WORK`，既有请假与证明仍只允许原视图组合；消息目标链接在每次读取时重新鉴权。学生统一办事新增报修种类及维修状态，“正在办理”统计包括分诊、待接单、处理中和待验收。

本轮本地前端 `http://127.0.0.1:18090/`，后端 18080。演示账号 `20260001／20260002`、`teacher1001／teacher1002`、`dispatcher1001`、`technician1001`，默认密码 `Demo@2026`。主库不自动新增地点，试用前由管理员核对并配置开放地点和有效人员范围。
