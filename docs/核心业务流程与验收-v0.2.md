| 调宿并行申请 | 每名学生至多 1 份未结束申请 | 申请人须有当前住宿；初次分配通过宿管维护或导入 |

首期设备采用数量管理；不细化单件设备的序列号调度。设备预留、已领用、损坏、维修均减少对应时段的可用数量，不能只计算单条预约。

## 2. 活动与资源联合申请

对应需求：ACT-01—08、RES-01—07、CAL-03/04、MSG-01/02、AGT-04。

### 2.1 参与人及前置条件

- 发起人：有效社团负责人、获授权的教师或校级活动组织人员。
- 资源审核人：负责所选场地与设备的服务人员。
- 活动审核人：负责主办方所属活动的教师或服务人员。
- 主办资格、社团状态、资源开放状态有效；审核人不能是发起人。
- 建议一份活动申请包含一个场地及若干种设备，不支持多场地联合分配。
- 若场地和设备由多个岗位管理，资源阶段需要所有必需审核项通过。

### 2.2 关键业务字段

| 对象 | 必需字段 |
| --- | --- |
| 活动草稿 | 标题、类型、主办方、负责人、内容、活动开始与结束、准备/清理时间、工作人员数、报名名额、报名开始与截止 |
| 场地需求 | 场地标识、用途、参与人数、占用开始与结束 |
| 设备需求 | 设备类型或资源标识、数量、用途、领用及归还时段 |
| 申请 | 发起人、提交时间、草稿版本、材料版本、关联资源申请、审核期限 |
| 审核记录 | 步骤、审核主体、意见、结果、处理时间、处理时看到的申请版本 |
| 报名 | 活动、用户、报名状态、报名时间、签到状态 |

实际数据库字段和枚举编码在数据设计阶段确定，不以本文表格代替字段字典。

### 2.3 正常流程

1. 发起人保存草稿，查询可用场地设备。草稿不占资源。
2. 系统校验时间、人数、名额、材料、主办权限及资源规则。
3. 提交时重新检查可用性，整体创建活动申请、资源审核项及临时占用。任一资源失败则整单不提交。
4. 资源审核人处理各自审核项。全部通过后进入活动审核，资源仍为临时占用。
5. 活动审核人通过时，系统再次校验期限、主办资格和资源状态，整体确认活动与关联资源。
6. 主办方发布活动，登录后的活动系统展示并开放报名。设置为公开展示的活动在官网呈现介绍，报名操作仅在工作台进行。审批通过但未发布的活动不公开。
7. 学生报名，系统检查时间、资格和剩余名额；成功生成报名与个人日程。
8. 活动开展，主办方组织签到及设备领用。
9. 主办方提交结束信息，服务人员确认设备归还；分别保留活动成果与资源使用记录。

活动结束不意味着设备已归还。未归还设备继续产生待办并影响可用数量。

### 2.4 状态与动作

审批状态与活动运营状态分别管理，避免“审批通过”等同于“已经发布”。

| 审批状态 | 允许动作 | 下一状态与影响 |
| --- | --- | --- |
| 草稿 | 编辑、删除草稿、提交 | 提交成功进入资源审核中，建立临时占用 |
| 资源审核中 | 资源审核、发起人撤回 | 全部通过进入活动审核中；任一拒绝整单拒绝；撤回释放占用 |
| 活动审核中 | 活动审核、发起人撤回 | 通过则已通过并确认资源；拒绝或撤回释放占用 |
| 已拒绝 | 查看理由、复制修订 | 新草稿重新申请，原申请保持历史 |
| 已撤回 | 查看、复制修订 | 新草稿重新申请 |
| 已过期 | 查看、复制修订 | 新申请重新竞争资源 |
| 已通过 | 查看，进入运营 | 资源正式预订；关键字段修改需另发变更申请 |

| 活动运营状态 | 允许动作 | 影响 |
| --- | --- | --- |
| 待发布 | 发布、取消、申请变更 | 不开放报名；到开始时间仍未发布则过期并释放未使用资源 |
| 已发布 | 报名、截止前取消报名、申请变更、主办方取消 | 名额与日程保持同步 |
| 进行中 | 签到、补签、异常终止 | 不能普通取消；终止留痕并通知，已领用设备仍需归还 |
| 已结束 | 成果发布、查询统计 | 不再报名和修改关键安排 |
| 已取消/已过期/已终止 | 查询历史 | 不恢复原记录；重新举办需新建活动 |

### 2.5 关键异常规则

- **资源冲突**：返回冲突资源、时间和替代查询入口，不泄露其他申请人的私有信息。
- **申请超时**：资源阶段及活动阶段共用整单期限，任何时刻过期都不能继续审批通过。
- **审核人缺失**：提交失败并说明配置问题，不产生永远无人处理的申请。
- **审核人变动**：由有权限的人员重新分配，保留原任务记录；不重置资源占用期限。
- **待审时修改**：关键字段不可原地修改，需要撤回再提交；审核材料以提交版本为准。
- **已通过关键变更**：时间、地点、人数、设备、主办方和活动内容变更另建申请。原方案在新方案通过前有效；新旧资源不能重复计数。新方案拒绝或撤回时保留原方案。
- **变更占用计算**：原占用继续保护原方案；新增资源或时段建立差异部分的临时占用，相同资源相同时间按新旧方案所需数量的较大值计算，不叠加同一申请自身占用。其他申请仍受新旧有效时段的冲突约束。新方案通过时整体确认差异、释放不再需要部分并切换活动版本。
- **非关键变更**：错别字、封面及展示格式可修改并留痕，不改变已审核内容实质。
- **取消活动**：释放未使用的预订，取消未来日程，通知报名者；已领用设备生成归还待办。
- **资源临时维护**：管理人员必须选择受影响预约的处理方式，记录原因并通知；受影响活动进入待处理状态，解决前阻止新报名。
- **报名满额**：首期不提供候补；取消后释放名额，其他用户可重新报名。
- **个人日程冲突**：展示提示，由用户决定是否继续报名；资源冲突不能通过确认忽略。
- **设备部分归还**：保留未归还数量，不能把整单当成已完成。
- **消息失败**：核心提交结果保持成功，记录待补发消息并重试。

### 2.6 联合申请验收

| 编号 | 场景与操作 | 预期结果 |
| --- | --- | --- |
| AC-A01 | 有效主办方申请空闲场地及足量设备 | 创建一份申请及一致的临时占用，资源进入不可重复申请的状态 |
| AC-A02 | 同时竞争同一场地相同时段 | 最多一份申请成功，不产生孤立活动或设备占用 |
| AC-A03 | 多份设备申请各需 2 件，总量为 3 件 | 不能两份都成功，不超额 |
| AC-A04 | 场地通过，设备拒绝 | 整单拒绝，所有临时占用释放，保存各项审核记录 |
| AC-A05 | 资源全通过，活动拒绝 | 所有占用释放，官网不出现活动 |
| AC-A06 | 待审申请被撤回 | 审核任务关闭、占用释放、通知相关人 |
| AC-A07 | 期限届满后点击审核通过 | 返回申请已过期，无正式预订 |
| AC-A08 | 所有审核通过且发布并设为公开展示 | 官网可见公开介绍；工作台开放报名；预约已确认；发起人收到结果 |
| AC-A09 | 并发竞争最后一个报名名额 | 最多一人成功，其他人收到已满；成功者只有一条日程 |
| AC-A10 | 同一用户重复点击报名 | 一条有效报名，不重复扣名额或建日程 |
| AC-A11 | 活动取消，已有报名与未领用设备 | 通知报名者，日程取消，未使用资源释放，历史保留 |
| AC-A12 | 他人或其他社团负责人修改活动 | 拒绝访问，原数据不变化 |
| AC-A13 | 新方案变更被拒绝 | 原已批准方案仍有效，新方案临时占用释放 |
| AC-A14 | 活动结束但设备未归还 | 活动可结束，设备保留未归还状态及待办 |

## 3. 独立资源预约

对应需求：RES、CAL、MSG。

1. 登录用户选择资源、时间、用途和人数。
2. 校验开放人群、提前量、最长时长、待审数量和可用性。
3. 提交成功建立临时占用并生成审核任务。
4. 审核通过转正式预订，生成日程；拒绝、撤回或过期释放占用。
5. 使用前可按规则取消；使用中涉及设备需登记归还。

状态：草稿 → 待审核 → 已确认 → 使用中 → 已完成；分支为已拒绝、已撤回、已过期、已取消、异常待处理。

活动关联预约的审批与取消由活动流程统一管理，用户不能单独取消活动的核心场地，造成活动仍正常但资源不存在。

验收重点：边界时间无误、设备数量汇总正确、维护时段不可预约、取消释放、归还部分数量受控、关联活动不能被绕过。

## 4. 社团与成员

对应需求：CLUB-01—03。

- 社团入驻：草稿 → 待审核 → 已通过/已拒绝/已撤回。拒绝后修订重新提交并保留原记录。
- 加入社团：学生申请 → 负责人审核 → 成为成员；支持申请撤回和成员退出。
- 同一用户不能对同一社团产生多个有效申请或多个有效成员关系。
- 负责人移交需要目标用户为有效成员并接受；最后一名负责人不能直接退出导致社团无人管理。
- 社团停用不删除历史。未完成活动进入待处理，按取消或移交方案解决。

验收：非负责人不能审批成员；移交后权限随角色归属更新；社团未通过不能发布活动；停用不能静默丢弃已有申请与资源。

### 5.2 状态与规则

草稿 → 待审核 → 待补交/已拒绝/已通过；待补交 → 待审核；待审核或待补交可撤回。已通过 → 办理中 → 已完成。

- 请假通过后可直接完成；在校证明需生成结果后完成。
- 补交更新材料版本与说明，保留旧版访问受限的历史。
- 完成后不允许普通编辑更换结果，纠错通过单独的留痕操作。
- 被拒绝或撤回后，修订生成新申请，不覆盖旧审批记录。
- 有效请假存在重叠时阻止重复提交；修改已批准请假走变更申请。

验收：缺材料不进入审批、无审核配置不提交、补交保留历史、结果文件只对申请人及相关办理人员开放、撤回关闭待办。

## 6. 报修

对应需求：FIX-01—05。

### 6.1 正常流程

学生提交位置、故障描述、图片和联系信息 → 分诊人员核查 → 派单 → 维修人员接单与处理 → 提交处理结果 → 用户确认 → 评价。

状态：待分诊 → 待接单 → 处理中 → 待确认 → 已完成。

分支：待分诊可要求补充或拒绝；派单前可撤回；派单后取消需处理方确认；待确认时用户可退回处理中。

### 6.2 规则与验收

- 只有分配人员可以处理；改派保留记录并通知新旧人员。
- 处理完成必须附处理说明，不能只切换状态。
- 用户退回需理由，保留上一次完成记录。
- 长期未确认产生提醒，不自动生成用户评价。
- 用户仅查看自己的工单，工作人员只查看职责范围内联系资料。
- 设备损坏报修若关联可预约资源，由资源管理人员确认后设置维护；Agent 不自行停用资源。

验收场景：正常完成、补充材料、改派、取消申请、完成后退回、越权处理和维修结果缺失。

## 7. 日程与消息

对应需求：CAL、MSG。

### 7.1 课表与日程

- 导入字段：学期、课程、教师、地点、星期、开始节次、结束节次、起止周、单双周。
- 学期起始日期及节次时间由后台统一维护。
- 导入先预览，标出错误行；第一版采用整批确认，未解决错误前不写入。
- 重复文件导入提示是否替换该学期课表，用户确认后执行；不默默叠加重复课程。
- 日程显示来源、状态和详情；取消或变更时更新原来源日程，保留可查询历史。

### 7.2 消息与待办

- 业务结果产生消息事件，通知包含对象、状态、时间及详情链接。
- 接收消息不授予详情权限；撤权后链接仍需重新鉴权。
- 同一业务事件对同一接收人只生成一条消息。
- 待办由未处理业务状态决定，读消息不等于完成审批。
- 提醒示例：审核临近超时、活动即将开始、设备逾期、报修待确认。

验收：消息补发不重复，已处理事项从待办消失，业务取消更新日程，课表周次展开正确。

## 8. Agent 详细流程

对应需求：AGT-01—07。

2026-10-09 首期实现：规则检索与本人／当前岗位查询已接入真实领域服务，结果有来源或业务链接；请假证明上下文重新鉴权且可清除。模型只规划只读工具，不展示自由生成的业务结论、不外发个人工具结果；未连接时明确使用本地关键词模式。首期未提供草稿、提交确认、执行恢复和持久会话。随后完成请假信息收集、可编辑预览与人工确认保存本人草稿；修改使确认失效，离开有未保存保护，提交仍由原页面人工完成，见[请假辅助验收](./Agent请假预览与人工确认验收-2026-10-09.md)。完整目标中的其他业务及持久会话仍待开发。验证与 DeepSeek 本地配置见[Agent 验收](./Agent只读查询与DeepSeek接入验收-2026-10-09.md)。

同日补齐“准备证明”：收集用途、读取本人登记资料，人工核对确认后保存本人草稿；登记快照变化重新确认，原页面提交与下载，见[证明辅助验收](./Agent证明预览与登记确认验收-2026-10-09.md)。

2026-10-11 首批恢复落地：本人会话与历史问题持久化，已核对请假／证明字段可恢复；原申请关联与草稿保存同一事务，恢复读取真实版本和状态。历史结果手动重查，确认清除，不自动调用模型、再保存或提交。新建、切换与具体任务恢复可用，会话删除和以下活动联合申请等完整目标仍待开发，见[会话与恢复验收](./Agent持久会话与任务恢复验收-2026-10-11.md)。

### 8.1 场景一：活动申请辅助

用户：“下周五晚上给我们社团安排一场 50 人的技术分享，需要教室和投影，帮我准备申请。”

1. 校验用户身份及主办资格。无权限时可提供指南，不能代交其他社团申请。
2. 按 Asia/Shanghai 将相对日期展开为具体日期，向用户展示；“晚上”需要明确开始和结束时间。
3. 收集主题、主办方、人数是否包含工作人员、准备时间、报名安排及缺失材料。
4. 查询有效规则、可用场地和设备，展示候选、限制及查询时间。
5. 用户选择后生成结构化草稿，明确“尚未提交，不占用资源”。
6. 展示可编辑的申请摘要和确认卡，绑定当前草稿版本。
7. 用户确认后，按联合申请规则提交。只生成一份关联申请，不能分别提交导致部分成功。
8. 成功返回申请编号、状态、关联记录和查询入口；冲突返回原因及替代选项。

### 8.2 场景二：个人事务汇总

用户：“我这周有什么事没处理？”

系统查询本人待办、课表、报名和预约，区分需要用户处理的动作与仅供查看的日程。每条事项带业务链接。已处理事项不继续列为待办，不查询其他用户材料。

### 8.3 场景三：校园知识咨询

用户：“活动教室怎么申请，需要哪些材料？”

系统检索可见且有效指南，返回步骤、材料与来源。资料冲突时说明版本和适用范围，不能擅自选择一条当成确定规则。来源撤下后，新请求不能继续引用撤下内容。

### 8.4 执行状态

任务状态建议：收集信息 → 查询中 → 草稿就绪 → 待确认 → 执行中 → 成功/失败/结果待核实/已取消。

- 用户修改关键草稿后，原确认失效。
- 确认过期或身份失效后禁止执行。
- “结果待核实”用于请求超时且业务可能已经提交，核实后转成功或失败。
- 任务成功必须依据业务服务返回或查询到的确定结果。
- 已成功提交的任务不能通过删除会话撤销业务。
- 步骤描述展示动作结果，例如“找到两处可用教室”，不展示模型内部推理。

## 10. 基础组织、身份与任务归属

- 任一提交需要有效负责岗位，无处理配置时提交失败；管理员收到配置待办。

## 11. 教师与教学班服务

任课教师选择本人教学班 → 上传资料与说明 → 保存草稿 → 预览受众 → 发布 → 学生查看或下载 → 更新或撤下。

资料状态：草稿 → 已发布 → 已撤下/已归档。更新保留版本，当前可下载版本与界面一致，旧版访问也须重新校验。

## 12. 住宿调整、入住与退宿

对应需求：DOR-01—06、FND-04/05、FLW、MSG。

### 12.1 前置条件与数据

- 申请人为有效学生，已有当前住宿，不存在另一份未结束调宿申请。
- 申请包含原住宿标识、原因、意向区域与必要材料；学生不自行占用指定床位。
- 处理顺序为负责学生事务人员审核，再由宿管在被授权楼栋安排。跨楼栋方案需要目标楼栋责任范围内的人员安排。
- 一张床位有空闲、预留、入住或维护状态；一名学生至多一条当前有效住宿关系。
- 初始住宿由宿管分配或模板导入，必须校验床位及学生唯一性。

### 12.2 正常流程

1. 学生保存并提交调宿申请，原床位保持当前入住状态。
2. 负责人员审核，可要求补交、拒绝或同意转交宿管。
3. 宿管核查入住条件，选择空闲且可分配的目标床位。
4. 确认安排时重新检查床位并发状态，预留目标，明确入住期限，通知学生。
5. 学生按安排搬迁，宿管核对后登记实际入住。
6. 一次一致的业务操作释放原床位、确认目标入住、结束原住宿记录并建立新记录，申请完成。

调宿批准不代表学生已经搬离，原床位在实际入住确认前始终保留。床位安排与入住时间线分别记录。

### 12.3 状态与异常

| 状态 | 允许动作 | 结果 |
| --- | --- | --- |
| 草稿 | 编辑、删除、提交 | 成功进入待初审，不预留床位 |
| 待初审 | 补交要求、通过、拒绝、学生撤回 | 通过进入待安排；拒绝或撤回关闭，不影响原床位 |
| 待补交 | 学生补交、撤回 | 补交回原审核步骤，保留旧材料 |
| 待安排 | 宿管安排、说明后拒绝、学生撤回 | 安排成功进入待入住并预留目标 |
| 待入住 | 宿管确认入住、处理取消、期限调整 | 确认后已完成；取消或过期释放目标并保留原床位 |
| 已完成/已拒绝/已撤回/已取消/已过期 | 查看历史、按规则提异议 | 不原地恢复；重办需新申请 |

- 目标床位被竞争占用时，安排失败且不生成预留。
- 目标进入维护时，原住宿不变，申请转待安排或按用户意愿取消，旧预留释放并通知。
- 实际入住确认时检查原住宿版本、目标预留和申请状态；任一变化导致失败且不切换部分记录。
- 操作重复或请求超时先查询原操作结果，不重复生成住宿关系。
- 学生发起取消请求后由负责宿管确认尚未实际入住；在处理前目标预留仍有效，不能同时完成取消与入住。
- 到期未入住则过期并释放目标。人工延长需要原因及具体期限，不能无限自动延期。
- 退宿是独立流程：宿管检查交接责任 → 确认实际退宿 → 结束当前住宿 → 释放床位。未完成调宿先按规则关闭，旧记录保留。
- 首期不支持多学生连锁换床或自动排床。
- 宿舍报修按当前住宿确定位置，未获授权学生不能提交其他房间故障；历史本人报修仍可查，不展示其他住户联系资料。

## 13. 校内通知与定向分发

对应需求：MSG-04—06、TCH-04、ADM。

发布人选取授权范围 → 编辑通知 → 预览接收人数与范围 → 发布 → 生成接收快照与消息 → 阅读或更新 → 撤下/归档。

- 官网公开新闻、校内定向通知、个人办理消息采用不同访问范围。私人办理结果不能选择公开发布。
- 全校通知只向全校通知岗位开放；教师范围为本人教学班，辅导员范围为负责行政班，负责人范围为所负责社团或活动。
- 接收名单在发布时形成快照，用于发送去重及阅读统计；真正读取内容仍校验当前归属与通知范围。
- 已离班或撤权的用户不能通过旧消息或旧下载链接继续读取受限正文；必要消息可保留“已失去访问权限”的状态。
- 新生或新成员加入后不自动收到所有旧消息，授权发布人可选择补发；历史内容的当前可见范围按具体通知设置。
- 修正文案保留版本；关键截止时间、地点或受众变化需发送变更提醒。用户已读状态记录版本，不能把旧版已读当成新版已读。
- 撤下后普通接收人不能读正文与附件，列表显示撤下状态；授权处理人员保留审计历史。
- 发送失败可重试，对同一事件、版本与接收人去重；读取消息与完成业务待办是不同动作。

## 14. 反馈、催办、转交与复核

对应需求：FLW-01—04、MSG-06、FND-04/05。

### 14.1 反馈与催办

本人选择业务记录 → 填写问题 → 对应岗位受理 → 回复或要求补充 → 关闭。状态为待受理、处理中、待补充、已回复、已关闭；用户可在窗口内继续追问，保留记录。

催办仅针对未完成、已有责任人的业务；达到频率限制时告知下次可催办时间。催办不替代处理，不重置申请或资源占用期限。

### 14.2 转交

授权转交人检查接收人的岗位与数据范围 → 填写原因 → 确认转交 → 原待办关闭、新待办生成 → 接收人处理。

- 转交前后的负责人、时间、原因留痕。
- 旧人员失去本任务的处理权限；仍持其他有效业务权限时，其只读范围按对应岗位判断。
- 重复处理或转交依据当前任务版本校验，最多一个有效处理结果。
- 离岗时检查所有未完成任务，有接收人则转交；无接收人则标记待配置并通知授权负责人。
- 无处理人不代表已批准，资源期限到期仍执行释放规则。
- 自审限制在接收人校验中同样生效，不能通过转交给发起人绕过。

### 14.3 结果异议与纠错

用户在窗口内对本人结果提异议 → 有复核权限的人员受理 → 核查原版本与记录 → 维持原结果或形成纠错决定 → 通知用户。

异议状态与原业务状态独立。纠错保留原记录，不直接把原拒绝状态改为通过；需要资源或新审批时，生成关联的新申请或纠错操作并重新校验。不能复活已被他人占用的资源。

## 15. 运行维护与数据恢复

对应需求：OPS-01—05、ADM-02/04/05。

- 导入：下载模板 → 校验与预览 → 修订错误 → 确认批次 → 写入 → 查看报告。首期按批次完整校验，冲突未解决不写入。
- 导出：选择允许的字段及范围 → 生成私有文件 → 限时下载 → 到期删除临时导出。下载再次鉴权，操作留痕；不默认导出联系方式或申请附件。

- 恢复验证：暂停后台自动任务及 Agent 写操作，恢复数据库与文件，核对身份、文件授权、申请占用、住宿记录和操作标识。
- 从源文档重建索引，验证撤下及私有文档过滤；过期 Agent 确认不得恢复为可执行状态。
- 核对待发消息与提醒，启用前防止批量重复通知；验证通过后才恢复任务执行。
- 运行统计区分模型、工具、业务服务和消息失败；成本可由实际费用或供应商计价估算，估算必须标记，凭据与敏感正文不写入日志。

## 16. 新增核心验收案例

以下案例结合主说明书最小演示数据，执行时固定账号、前置记录及时间。已有 AC-A、AC-G01—12、AC-W 案例继续有效。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-B01 | 教师具备授课关系但无辅导员审核岗位 | 可发布本人班级资料，不能审核该学生请假 |
| AC-B02 | 两学院同角色人员读取对方申请 | 无对应数据范围则拒绝，不泄露材料 |
| AC-B03 | 学生毕业归档且存在设备未归还 | 停止新申请，保留归还责任及历史，授权人员可跟进 |
| AC-B04 | 导入身份或初始住宿有重复标识与失效引用 | 报告错误且整批不写入，无重复身份或床位分配 |
| AC-T01 | 任课教师发布本人教学班资料 | 成员可访问，其他班级、匿名访问均拒绝 |
| AC-T02 | 学生调出教学班后使用旧文件链接 | 下载拒绝，旧消息不授予权限 |
| AC-T03 | 已发布资料撤下并更新版本 | 撤下版本不能下载，重新发布后记录新版本 |
| AC-T04 | 教师查询教学班成员 | 只返回必要成员字段，不含住宿或请假材料 |
| AC-D01 | 调宿正常审核、安排及入住 | 安排阶段原床位占用、目标预留；入住后原床位释放、新关系唯一 |
| AC-D02 | 两份调宿竞争同一目标床位 | 至多一份有效预留，失败者原床位不变 |
| AC-D03 | 待入住取消或到期 | 释放目标预留，保留原住宿，产生结果通知 |
| AC-D04 | 确认入住时原记录版本变化 | 整体失败，无部分切换和重复当前住宿 |
| AC-D05 | 宿管办理不负责楼栋或学生读取他人住宿 | 拒绝，私有住宿资料不泄露 |
| AC-D06 | 重复确认入住或退宿 | 至多执行一次，历史与空闲床位数正确 |
| AC-D07 | 当前住户报修与非住户伪造房间 | 本人位置可提交，伪造位置拒绝，工单遵循原流程 |
| AC-N01 | 辅导员给负责行政班发布通知 | 接收范围正确，其他班级不能访问 |
| AC-N02 | 发布人扩展受众到未授权学院 | 拒绝更新，无新增消息 |
| AC-N03 | 消息重试、版本变更和已读查询 | 同事件不重复；新版本有独立阅读状态和提醒 |
| AC-N04 | 通知撤下或接收人离班 | 不可读受限正文与附件，保留必要状态与审计 |
| AC-F01 | 催办次数超限 | 不重复产生催办，原业务与期限不变化 |
| AC-F02 | 转交给合资格人员后旧人处理 | 新待办生成、旧处理拒绝，历史保留 |
| AC-F03 | 转交给无范围人员或发起人本人 | 拒绝，不改变当前任务责任人 |
| AC-F04 | 被拒绝预约复核后资源已被其他人占用 | 不自动恢复预订，纠错关联新处理与资源复查 |
| AC-O01 | 越范围导出或使用过期/撤权下载链接 | 拒绝，合法导出字段与范围最小且有审计 |
| AC-O02 | 独立环境备份恢复 | 数据与私有文件关联、住宿与占用一致，过期确认不可执行，无重复通知 |
| AC-O03 | 知识重建与模型费用观测 | 撤下或无权限内容不进入回答，费用估算有标记且日志不含敏感正文 |
| AC-G13 | 从预约详情唤起并要求换教室 | 展示来源与条件，重新查询授权记录，生成待确认草稿，不直接取消原记录 |
| AC-G14 | 修改页面上下文为他人业务标识 | 服务端拒绝，工具及会话不泄露他人信息 |
| AC-G15 | 任务中断后恢复，草稿变化或确认过期 | 要求重新确认，保留可恢复任务记录，不执行旧操作 |
| AC-G16 | Agent 接到安排床位或发布课程通知请求 | 不调用未开放管理工具，提供规则与常规页面入口 |
