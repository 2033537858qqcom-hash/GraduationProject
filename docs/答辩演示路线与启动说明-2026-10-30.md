# 答辩演示路线与启动说明

日期：2026-10-30（Asia/Shanghai）。建议主线 10 分钟，演示前自行完整试跑一次。第三批探索与助手界面尚需补浏览器验收，见[待验收索引](./界面统一待验收与证据索引-2026-10-30.md)。

## 启动与数据选择

项目默认前端 `5173`、后端 `7080`。10 月 30 日界面预览使用 `18090 → 18080`，H2 库为 `artifacts/cinema-preview/campus`。这个已有预览使用以前打包的 JAR，不能据此认定包含当前全部后端源码改动。

`application-local.yml` 的默认 H2 地址为相对路径 `./data/campus`。在 `backend` 启动与在仓库根目录启动会选到不同库。日常库与演示库分开，以下冷启动命令明确使用新的 `artifacts/defense-demo/campus` 演示库，通过 Maven 运行当前后端源码；第一次启动会创建演示记录，旧验收编号不保证存在。已有库需先保留备份，不要删除或覆盖原库。

后端终端：

```powershell
cd D:\GraduationProject
$taskDemoData = Join-Path (Get-Location).Path 'artifacts/defense-demo'
New-Item -ItemType Directory -Path $taskDemoData -Force | Out-Null
$env:SPRING_PROFILES_ACTIVE = 'local'
$env:SERVER_PORT = '18080'
$env:SPRING_DATASOURCE_URL = 'jdbc:h2:file:' + (Join-Path $taskDemoData 'campus').Replace('\','/') + ';MODE=MySQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_ON_EXIT=FALSE'
$env:DEEPSEEK_ENABLED = 'false'
$env:COS_ENABLED = 'false'
$env:REPAIR_REMINDERS_ENABLED = 'false'
./scripts/Start-Backend.ps1
```

这只对当前终端设置环境。启动脚本会按已有行为检查本地加密模型凭据，但显式 `DEEPSEEK_ENABLED=false` 保持模型关闭；不需要输入或展示密钥。等待日志确认数据源路径、迁移版本和服务端口。若 18080 已被此前预览占用，先在对应终端停止旧实例，或把两侧统一换成其他空闲端口；不要停止不属于本项目的服务。

前端终端：

```powershell
cd D:\GraduationProject
$env:CAMPUS_API_TARGET = 'http://127.0.0.1:18080'
./scripts/Start-Frontend.ps1 -Port 18090
```

依赖缺失时先在 `frontend` 执行 `pnpm install --frozen-lockfile`。访问 [官网](http://127.0.0.1:18090/)，终端 Ctrl+C 停止对应服务。地图配置缺失或网络不稳定时使用 [独立校园沙盘](http://127.0.0.1:18090/campus/explore?view=model)，本地查询不依赖真实模型。

只读预检，在仓库根目录执行：

```powershell
./scripts/Test-DemoReadiness.ps1 -FrontendPort 18090 -BackendPort 18080
# 只检查本机工具、依赖与迁移文件，不访问运行服务：
./scripts/Test-DemoReadiness.ps1 -SkipServices
```

预检失败会返回非零，JSON 报告写入 `artifacts/demo-readiness/`。报告包含待人工核对事项，不记录密码或密钥，不写业务数据。接口健康不能证明浏览器、数据库迁移和所有业务均已验收。

## 十分钟主线

| 时间 | 操作与页面 | 要说明的结果 |
| --- | --- | --- |
| 0:00–1:00 | 官网九章，目录跳到校园生活；进入内容页再返回原章 | 真实校园资料、连续叙事、可访问的功能入口 |
| 1:00–2:00 | 学生登录，打开学生首页和我的日程 | 身份相关导航、本人课程和安排，不展示他人信息 |
| 2:00–4:00 | 学生新建请假，填写未来时段和演示事由，保存、核对后提交 | 草稿与提交是不同操作；材料和最终提交由本人确认 |
| 4:00–6:00 | 退出后登录辅导员，从岗位待办打开该申请，填写具体补交要求并退回 | 当前负责班级范围，处理意见、版本及待办变化 |
| 6:00–7:00 | 切回学生，查看消息和我的办事时间线，进入补交表单 | 原记录保留，意见可对照，补交不重建另一条申请 |
| 7:00–8:30 | 探索图书馆，查找关联资源；清除地点筛选，再返回原地点 | 资源由显式关系决定，无资源地点显示空结果；本段待第三批浏览器验收后正式使用 |
| 8:30–10:00 | 本地助手查询“我的预约进度”或“去图书馆怎么走”，进入有效结果 | 当前权限、本地来源与原业务入口；本段新面板待浏览器验收，不能描述成已实测完成 |

准备请假时间时使用未来日期、结束晚于开始，时长符合演示规则。填写“界面演示：核对请假、补交与办理记录”，联系方式使用演示值。不要在演示事由、截图或材料中加入真实个人信息。新建库没有旧记录时走上面的新建流程；已有隔离库中的请假 #1 是 10 月 30 日第二批留下的待补交样例，不是固定的全环境数据。

若现场不便切换多账号，可先展示学生已有记录，再用第二批工作台截图说明已验证链路；明确截图日期和证据范围。第三批未验收的交互在检查完成前只介绍实现，演示主线可改用已验收的报修或证明流程。

- 三分钟扩展：证明申请 → 学院审核 → 受控演示 PDF；或报修 → 派工 → 维修 → 本人验收。演示前准备对应岗位和有效负责范围。
