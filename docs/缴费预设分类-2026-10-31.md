# 缴费预设分类

日期：2026-10-31（V35 建立目录，同日 V36 接入财务工作流）。沿用支付宝沙箱演示缴费。分类本身仍不直接设定金额或自动生成账单，但已参与 V36 的收费标准、收费依据、账单、账单分类筛选、作废／减免／退款与只读对账预览全链路。

## 预设分类

| 编码 | 名称 | 用途 |
| --- | --- | --- |
| TUITION | 学费 | 按学年或学期收取的学习费用 |
| ACCOMMODATION | 住宿费 | 学生宿舍住宿费用 |
| WATER | 水费 | 单独结算的用水费用 |
| ELECTRICITY | 电费 | 单独结算的用电费用 |
| UTILITIES | 水电费 | 合并结算的水电费用 |
| TEXTBOOK | 教材费 | 教材及学习资料费用 |
| VENUE | 场地使用费 | 场地或活动空间使用费用 |
| OTHER | 其他费用 | 其他明确费用及原有未分类账单 |

## 页面与接口

财务经办（`finance1001`，`FINANCE_OPERATOR`）在 `/finance/payments`“财务收费”选择收费分类建单并提交复核，财务复核（`finance2001`，`FINANCE_REVIEWER`）独立复核后发布；教务、宿管、后勤等收费依据岗位在 `/payment-bases`“收费依据”按分类提交依据。旧 `/admin/payments` 仅保留前端 redirect，后端 `/api/admin/payments` 已 `denyAll`。选择分类会建议费用名称，已自行填写的名称会保留；金额始终由经办手动核定并经复核。学生在 `/portal/payments`“缴费大厅”查看分类标签，通过分类按钮筛选本人账单；没有账单的分类显示明确的空状态。

- `GET /api/finance/payments/categories`：财务分类目录，按经办/复核/依据岗位权限校验，且要求 demo 开关开放。
- `POST /api/finance/payments`：财务建单，新增 `categoryCode` 字段，必须匹配预设编码；省略时兼容为 `OTHER`。
- `POST /api/finance/payments/batch`：批量建单，同样接收并校验 `categoryCode`。
- `GET /api/payments/categories`：学生分类目录，要求 `portal:read` 且 demo 开关开放。
- 本人账单列表、账单详情及建单结果均返回 `categoryCode` 和 `categoryName`。

目录来自同一个数据库分类表，前端不另行硬编码分类。分类不改变原有账单归属、支付渠道、金额校验和付款状态确认规则。

## 历史兼容

Flyway V35 建立分类目录，并为原有账单填入 `OTHER`；V36 在收费标准、收费依据、作废／减免／退款申请与历史中继续引用同一分类表。原名称、金额、订单号、交易号、付款状态及付款时间保留，不根据自由填写的费用名称推断分类。相同请求标识重复创建仍返回同一账单；更换分类后复用请求标识会返回冲突，不能改写原账单。

## 验证范围

新增 HTTP 集成测试覆盖目录权限、八种分类的持久化与本人查询、非法分类、重复创建冲突、旧请求兼容、CSRF 和跨学生访问。迁移测试从 V34 的已付和待付账单升级，核对原账单字段并验证重复启动不会重复建立目录。V36 财务工作流测试覆盖收费标准、收费依据、作废／减免／退款与只读对账预览（含越权 403、非法 CSV 400）。财务双岗自审与 demo 门控在服务层校验（`SELF_REVIEW`、`DEMO_DISABLED`），修复前审计未见针对这两项的独立测试方法。

前端测试覆盖分类筛选、历史未分类账单及自动建议名称时保留自定义名称。支付仍为沙箱模式；V36 起分类已进入收费标准、收费依据、账单、作废／减免／退款、CSV 台账与只读对账预览链路，但尚未与宿舍计量、预约计费自动生成或学年收费标准库自动匹配联动。

本次验证结果：后端支付相关 **40 项**（payment 包 9 类；以[完整性复查修复验收](./完整性复查修复验收-2026-10-31.md)为准）与后端全量 **558 项**通过；前端全量 **227/227** 通过、类型检查及生产构建通过。修复前审计未复现历史覆盖率数字，本文不再引用具体覆盖率。Lint 无错误，保留 `ManagedPasswordReset.vue` 的一条既有换行警告。

浏览器使用 `localhost:15174 → 17081` 和独立 H2 内存库完成建单、切换分类保留自定义名称、学生分类筛选及空状态检查（历史记录，当时建单入口为“演示账单管理”）。手机视口下分类正常换行，页面无横向溢出，控制台无错误。桌面与手机证据分别保存在 `artifacts/local-runtime/payment-categories-desktop.jpg` 和 `artifacts/local-runtime/payment-categories-mobile.jpg`。两笔测试账单仅在该临时内存库中，未发起支付。

## 2026-10-31 财务口径补充

- 建单、复核、发布、作废、减免、退款与收费依据均已从旧的管理员单岗改为财务双岗：`FINANCE_OPERATOR` 经办、`FINANCE_REVIEWER` 独立复核，后端禁止自审。
- 对账已实现**只读预览**（`POST /api/finance/payments/reconciliation/preview` 与模板下载）：比较上传 CSV 与本地账单的订单号／金额／状态／交易号差异，**不落库、不入账，也没有差异处置流程**；前端会明确提示不会把账单标记为已支付。
- 分类与退款链路：退款／作废／减免申请从账单读取分类，退款金额不得超过原账单金额；对账预览使用的台账与 CSV 均包含分类或订单信息。
- 全部财务端点仍受 `app.demo.enabled` 门控，MySQL profile 默认关闭；生产收款与真实支付宝沙箱未验证。
