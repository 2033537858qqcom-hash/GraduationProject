## 2. 证明状态与资料

| 状态 | 学生可执行 | 当前授权学院学生事务人员可执行 |
| --- | --- | --- |
| 草稿 `DRAFT` | 编辑、提交、撤回 | 不可查看他人未提交草稿 |
| 待审核 `SUBMITTED` | 查看、撤回 | 核对、退回补交、拒绝或通过并生成结果 |
| 待补交 `RETURNED` | 编辑、重新确认身份信息、重新提交、撤回 | 查看资料和历史，等待重新提交 |
| 办理完成 `COMPLETED` | 只读资料、历史及结果下载 | 按当前学院权限只读查看、下载 |
| 已拒绝 `REJECTED` / 已撤回 `WITHDRAWN` | 只读查看；重新办理需新建申请 | 按当前学院权限只读查看 |

- 必填申请用途，最多 300 字；必须确认本人登记资料。当前领取方式固定为线上下载 `DIGITAL`，不提供尚未实现的纸质领取选项。
- 姓名、学号、学院、专业、行政班和校区由服务端读取当前有效学生账号与组织关系，申请人不能指定学生身份、资料快照或任意审核人员。
- 资料关系不完整时禁止建档；没有同学院其他有效学生事务人员时可保存草稿，禁止提交。本人不能提交给自己或审核自己的申请。
- 提交与生成结果再次核对当前登记资料是否与保存的快照一致。资料发生变化时要求重新保存确认或退回补交，避免静默使用过期资料。
- 创建草稿使用本人范围内唯一请求标识；一致的初次请求重试返回同一记录，不重复生成历史。内容不同或原记录已更新时返回冲突。
- 编辑、提交、撤回和处理检查当前版本；旧操作不能覆盖新状态。每次成功保存当时资料、用途、状态、操作者和意见，补交沿用原申请；最近处理意见独立保留。
- 通过操作直接完成：生成 PDF、保存唯一结果、更新 `COMPLETED`、历史和消息在同一事务中。生成失败返回可重试错误，状态、历史、文件和消息全部回滚，不出现“已完成但无结果”。
- 审核与撤回竞态只允许一个操作成功；两个审核人员不能对同一版本生成两份结果。已完成文件不因后来修改账号资料而改变，关闭记录不能普通编辑、撤回或重复审核。

## 3. 权限与组织变更

新增 `STUDENT_AFFAIRS` 岗位及 `certificate:review` 权限，学生持 `certificate:apply`。学生事务岗位按学院处理证明，与辅导员按负责行政班处理请假的权限分别校验。普通教师、通用服务人员、教务、编辑和管理员不会自动取得他人证明资料。

详情、历史、结果下载每次重新校验当前本人范围或有效学院岗位。无功能权限返回 403，越权对象返回 404；未完成且无结果的申请不能下载。审核范围只含已提交过、属于当前启用学院且不是本人申请的记录。

证明办理与账号组织修改使用已有基础管理写锁。存在待审核或待补交证明的学生，不能直接移除学生身份或改变学院、行政班归属。存在这些申请时不能撤掉其最后一名同学院、非申请人本人且有效的学生事务审核人员；如另有有效人员，可调整岗位或学院，旧账号会话按既有实时权限机制失效。移交后消息申请入口、详情、历史与下载随当前权限生效，不依赖旧待办副本。

## 4. PDF 结果

结果为 A4 中文 PDF，包含演示编号、生成时登记资料、用途、时间及演示办理人员；标题、正文、水印和页脚明确标注“毕业设计演示”与“非学校正式证明”，没有仿造校章、签名或真实证件认证。

文件保存在数据库的私有结果记录中，不放入公开静态资源目录。下载校验会话及对象范围，返回 `application/pdf`、附件文件名、`Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。生成结果按申请唯一保存，不允许后续资料编辑覆盖旧文件。

## 5. 我的办事与个人消息

“我的办事”提供已实现事项入口、本人五项概况和按种类／状态分页的记录。概况统计本人全部申请，不随列表筛选缩小；列表返回类型、编号、名称、状态、版本、时间及内部业务路径，不复制私有事由、联系方式或证明用途。请假与证明可以有相同数字 ID，前端以类型和 ID 共同标识记录。

消息按本人分页，支持全部、未读和已读筛选，返回当前筛选总数及本人全局未读数。重复标记已读不重复扣减或改写首次已读时间；不能标记别人的消息。默认 20 条、最大 100 条，每页与页码均验证，超过 20 条的消息能够继续查询，修复原检查 F06。

新的请假与证明消息使用受控来源类型、申请 ID 和本人／审核视图，不保存任意跳转 URL。每次查询消息重查来源对象权限，仅当前仍有权访问时返回申请入口；移交后的旧审核人员保留个人消息，但失去业务入口。消息内容只含申请编号和状态提示，处理意见和私有资料在受控详情查看。既有普通消息及升级前消息保留原文，不猜测或补造业务来源。

前端检查内部目标路径，拒绝外部地址、协议相对地址、路径穿越和未知栏目；登录后保留符合已知路由及当前权限的目标，业务操作仍由后端鉴权。“查看对应申请”先标记本人消息已读，再进入原记录。列表筛选、页码、记录和详情栏目写入 URL；已保存资料刷新恢复，未保存隐私输入不写入浏览器本地存储。

## 8. 当前边界与下一阶段

本轮只验证 H2，MySQL 配置及 V10 方言未联调。未接入真实学籍、校内统一身份或正式校方模板；纸质领取、证明有效期及核验、多级审核、批量办理、转交催办、附件材料策略、结果更正与撤销仍需另行设计。结果不具备学校证明效力，未实现电子签章或公开验证接口。

“我的办事”仅汇总当前已实现的请假和证明，尚无动态配置服务目录、报修住宿活动等事项或跨业务完整日历。F06 已修复，F07 学期默认选择及 F08 教务状态恢复仍待处理；未重新评分上线就绪度。Agent 尚未实现，不能把聊天入口或预设文字当作真实 Agent 交付。

下一阶段建议先接入受权限约束的规则问答、本人学习与办事进度查询，然后提供请假／证明草稿辅助。模型查询使用当前账号范围；草稿和提交分别处理，明确展示实际字段与确认结果，沿用现有版本、状态和审核规则。
