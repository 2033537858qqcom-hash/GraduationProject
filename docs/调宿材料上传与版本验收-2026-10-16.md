# 调宿材料上传与版本验收

日期：2026-10-16。工程版本 0.1.0，数据库 V22。仅用于毕业设计演示，不代表学校实际材料要求。

## 1. 办理流程

新建调宿先保存草稿，不再自动送审。学生在申请下展开“申请材料与提交版本”，上传并核对材料后亲自提交；附件可选，仍可使用材料说明办理。已有未结束申请时隐藏新建表单，继续处理现有记录。单条申请铺满内容区，避免材料区只占半页。

| 阶段 | 学生操作 | 学院可见附件 |
| --- | --- | --- |
| 草稿 | 编辑资料、上传、移出清单、核对后提交 | 不可读草稿 |
| 待初审 | 查看、下载，不能增删 | 已提交版本 |
| 待补交 | 编辑并保存说明，替换附件，核对后补交 | 仍只显示已提交版本；不开放未补交的新附件 |
| 待安排、待入住、已结束 | 查看当前清单及已提交版本，不能增删 | 按当前学院权限查看已提交版本 |

提交、补交与冻结材料清单在同一事务内完成，冻结原因、意向、材料说明、申请版本及文件引用；补交产生新的材料版本，旧文件和说明不被覆盖。V22 以前的历史记录不补造提交快照。

选择文件后须上传或清除选择，才可提交、补交或刷新整份申请。上传过程中锁定冲突操作；离开页面或刷新有未上传文件时提示。文件选择只保存在内存，不存入浏览器草稿，不自动提交到助手。

## 2. 文件与访问规则

- 支持可读取的 PDF、JPEG、PNG，每份 1 字节至 2 MB，当前清单最多 3 份。PDF 最多 20 页且不加密；图片最多 2000 万像素、单边不超过 8000。
- 后端检查实际内容，不信任文件扩展名和浏览器 MIME；保存名称去除路径及控制字符，并使用检测出的格式后缀。
- 每份申请累计留存最多 60 个文件、40 MB，包含移出清单及历史文件，避免反复替换造成无界存储。
- 文件保存在私有数据库表，不使用公开静态路径。下载校验账号、岗位、申请归属和当前学院；普通教师、管理员及宿管不因岗位身份获得附件访问权。
- 学院下载旧附件须指定该申请真实留存的提交版本；不指定版本时仅开放最新提交中的附件。不能跨申请拼接文件或提交编号。
- 下载使用附件响应、`no-store`、`nosniff` 和沙盒 CSP。文件内容与名称不接入模型工具；住宿指南更新到 V2，既有助手预览继续按指南版本重新核对。

“移出清单”仅修改当前清单，已提交引用及文件保留；未被任何提交引用且已移出的文件不再开放下载。删除未提交草稿时清理其私有文件，保留原有操作重复保护。提交和补交之后不能通过材料接口修改已冻结内容。

每次上传、移出都推进申请版本，旧版本操作返回 409。重复的相同请求不增加文件、版本或快照；同一操作标识对应不同内容或混用不同接口时返回冲突。文件、操作记录、版本和提交快照失败时一同回滚。

## 3. 数据与接口

V22 新增 `housing_material`、`housing_material_submission`、`housing_material_snapshot`。文件和提交引用使用申请范围内的复合外键，防止跨申请关联。只在新提交或补交时冻结快照，不回填历史材料。

主要接口位于 `/api/housing/transfers`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /mine/{id}/materials` | 本人当前清单和提交版本，分页 |
| `POST /mine/{id}/materials` | 带申请版本及操作标识的单文件上传 |
| `POST /mine/{id}/materials/{file}/remove` | 移出当前清单 |
| `GET /review/{id}/materials` | 当前学院范围内已提交版本，分页 |
| `GET /{mine或review}/{id}/materials/{file}?submission={提交编号}` | 下载当前有权读取的文件 |

版本列表每页最多 20 条，不返回文件二进制；文件内容只由受限下载接口返回。

- 实际格式识别、文件名及私有下载响应头。

- 草稿、其他学生、普通岗位、学院及权限变化后的隔离。

- 删除草稿、文件及操作写入失败、消息失败时提交快照回滚。
- 历史记录不补造快照、有效指南包含新材料规则。

## 5. 浏览器验收

独立内存库 18081、前端 18091，DeepSeek 关闭。API 仅准备演示楼栋、床位及当前入住，随后浏览器实际完成：

1. 学生填写调宿草稿，确认没有自动送审。
2. 选择第一版合成 PDF，提交按钮禁用；上传后从清单下载，再手动提交。
3. 学院从消息进入，读取第一版快照并退回补交。
4. 学生保存新说明、移出第一版、上传第二版；历史第一版仍保留。
5. 显式 API 验证此时学院仍只有第一版，第二版下载返回 404，证据 `before-supplement.json`。
6. 学生重新补交，学院从补交消息进入，查看第二版和第一版，实际下载历史第一版。

`ui-results.json` 验证申请待初审、提交版本共 2 版、新版文件和旧版文件各自对应正确快照，旧说明未被覆盖。学生首次下载和学院历史下载的 SHA256 均与原合成文件一致。

学院版本详情在 1440 / 1024 / 768 / 390 宽度下无页面横向溢出，文件链接无越界；视口已恢复，控制台无错误。证据 `responsive.json`、`review-material-mobile.png`。其他截图为 `student-before-supplement.png`、`student-material-versions.png`、`review-material-versions.png`。
