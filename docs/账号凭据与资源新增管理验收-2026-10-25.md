# 账号凭据与资源新增管理验收

日期：2026-10-25，Asia/Shanghai。承接[功能完整性复评](D:/GraduationProject/docs/项目功能完整性复评与优化建议-2026-10-25.md)中账号日常管理、预约资源新增的缺口。此次没有操作日常数据库或修改真实账号凭据。

## 1. 已交付功能

| 使用者 | 新增能力 | 约束 |
|---|---|---|
| 已登录用户 | 在个人资料中验证当前密码并修改密码 | 新密码至少十位、包含字母和数字、最多 72 个 UTF-8 字节；不能与当前密码相同；连续错误尝试限流 |
| 账号管理员 | 为其他启用账号重置临时密码并填写核验原因 | 需要 `foundation:manage`、当前账号记录版本；不能走管理员重置接口修改自己；不回显新密码 |
| 新建或重置账号 | 登录后进入独立首次改密页 | 未修改前，服务端拒绝业务接口，前端将受保护业务页面引回改密页；仍可读取本人身份、获取 CSRF、退出与浏览公开信息 |
| 资源管理人员 | 新增东/西校区场地或整套设备资源 | 配置编号、校区、地图地点、建筑或区域、位置、容量、设施说明、守则、办理人员及开放状态 |
| 资源管理人员 | 先保存待开放资源，配置后再开放 | 立即开放和后续开启均需要有效办理人员；新建与负责关系一起提交，失败回滚 |

凭据变化时同时递增账号版本与安全版本：当前及其他设备的旧会话失效，原密码不能再次登录。密码仅以 BCrypt 哈希保存，不写入业务操作摘要；审计保留操作人、对象、时间、动作和原因。

个人资料保留原资料展示，并增加独立的密码区域；账号管理列表增加“重置密码”入口与“下次登录须改密”提示。登录页提供联系账号管理员核验重置的指引。本批没有接入短信或邮件找回。

## 2. 数据与接口

### V32 迁移

`app_user.must_change_password BOOLEAN NOT NULL DEFAULT FALSE`。

- 旧账号默认不强制改密，避免升级使所有既有账号突然进入限制状态。
- 管理员新建账号或重置密码后设为 TRUE。
- 本人验证当前密码、成功修改后设为 FALSE，并要求重新登录。
- 停用账号、角色与安全版本的既有检查继续生效。

### 凭据接口

| 接口 | 输入与结果 |
|---|---|
| `POST /api/auth/password` | `currentPassword`、`newPassword`；成功 204，当前会话退出 |
| `POST /api/admin/foundation/users/{id}/password` | `version`、`newPassword`、`reason`；返回账号 ID、更新后版本与改密要求标志，不返回密码 |

改密失败不清理正常会话；错误旧密码不更改哈希。管理员使用过时账号版本重置返回 409，防止覆盖未重新核对的人员资料变化。审计动作分别是 `USER_PASSWORD_CHANGE`、`USER_PASSWORD_RESET`。

### 资源建档接口

- `GET /api/reservations/venues/catalog`：供资源管理人员读取校区与可关联地点。
- `POST /api/reservations/venues`：资源资料、`managerUserIds` 和 `enabled`。
- 既有 `PUT /api/reservations/venues/{id}` 增加开放前负责人检查。

管理权限继续使用 `reservation:manage`，没有给普通学生或系统管理员额外授予该权限。办理人员必须存在、启用且具有 `reservation:review`，不接受重复或无效人员。资源编号在校区内不区分大小写检查重复，跨校区允许同编号。

新增资源返回 `campusId`、`campusName`，目录明确显示所属校区。建档产生 `VENUE_CREATE` 审计，可由账号管理员在修改记录按“预约资源”查询。

## 3. 地点目录与边界

地点目录来自现有东校区 `campusPlaceDefinitions` 与西校区 `westPlanDefinitions`，共 **69 个命名地点**，只复用名称与标识，不推断房间、容量或设施。

后端校验地点与校区一致，拒绝未知地点；也可以不绑定地图地点，由管理人员录入实际建筑与位置。下拉选项随校区变化，切换校区清理旧选择。新增地点若需进入三维模型，仍须另行维护场景资料。

浏览器检查发现目录生成曾把西校区 4 个道路绘图对象也当成可选地点，造成重复道路名称；随后以具名地点数组为边界复现并修正。前端契约测试校对两校区目录的 ID、名称与所属校区，避免再次把绘图几何对象加入地点目录。

本批完成资源新增，不包含既有资源迁移位置、结构化开放时段、维护窗口、设备逐件库存、跨课程/考试/预约的统一占用或三维建筑预约按钮精确回跳。场地守则目前仍为说明文字。

### 独立浏览器验证

1. 管理员账号列表可定位到演示账号、打开受控重置表单，显示对象、临时密码确认、核验原因及旧会话失效说明。
2. 独立 HTTP 流程重置演示账号后，浏览器使用该临时凭据登录，进入首次改密页；直接访问 `/portal` 仍被引回 `/account/password`。
3. 通过独立 HTTP 接口完成改密后，使用新凭据登录，可进入门户及个人资料，日常改密区域正常显示。
4. 资源管理人员在页面选择西校区、图书馆，录入演示位置与 36 人容量、配置负责人并立即开放；列表显示正确校区、地点及 1 名有效办理人员。

实际密码修改与重置写入由隔离 HTTP 集成流程验证，浏览器仅检查凭据表单、登录和访问引导，没有在浏览器执行密码变更提交。资源建档在浏览器中实际提交并验证成功。

浏览器使用独立 H2 内存库 `account-resource-ui-20261025`；演示资料均通过业务 API 创建。临时服务和页面验收后已关闭，日常数据未迁移或改写。最终地点目录的 69 项成员由单独契约测试与最终打包核对，浏览器建档时选择的 `west-library` 在修正前后均有效。

## 5. 本地使用与后续

前后端同步更新后，重启后端会执行 V32。已有账号不要求统一改密；新建/重置的账号先改密。资源管理人员从“场地资源配置 → 新增资源”建档，未配置办理人员时可先保存待开放。

后续建议先完善岗位交接和教学/预约资源关联，再推进统一日程、知识管理与 Agent 预约辅助；此次不应宣称所有账号生命周期或资源管理需求均已完成。
