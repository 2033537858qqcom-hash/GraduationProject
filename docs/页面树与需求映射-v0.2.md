## 1. 导航原则

- 官网、个人工作台、工作人员工作台、后台使用不同导航与页面布局，共享校园品牌。
- 官网首页只精选学校内容；登录入口不是业务卡片墙，登录后默认进入本人工作台。
- 工作台按身份与授权显示菜单，不用界面隐藏替代后端鉴权。
- 用户在主界面切换多角色工作视图，账号、消息和业务记录保持同一身份。
- 任一列表详情、私有附件及 Agent 上下文重新校验归属。
- 不提供未实现的图书、奖项、支付等可办理入口。

## 7. 关键交互规范

### 7.1 申请详情

详情包含申请编号、类型、发起人允许显示的信息、当前状态与责任岗位、材料版本、处理时间线、关联资源、结果及可执行动作。

按钮根据状态与权限决定；提交时重新校验。拒绝与取消说明原因；异议入口独立于原结果。

### 7.2 Agent

2026-10-09 实际页面：登录后右下角动态角色及紧凑对话；`/assistant/guides/:slug` 展示有效版本原文，登录回跳仅接受已知内部路径；请假和证明详情可带清晰的本人／岗位上下文。首期只读查询对应 AGT 的部分范围；第二阶段学生对话增加“准备请假”，支持补问、可编辑预览、人工确认保存草稿及原详情跳转，见[请假辅助验收](./Agent请假预览与人工确认验收-2026-10-09.md)。其他业务及持久会话页面尚未完成，见[Agent 验收](./Agent只读查询与DeepSeek接入验收-2026-10-09.md)。

同日补齐“准备证明”：收集用途、读取本人登记资料，人工核对确认后保存本人草稿；登记快照变化重新确认，原页面提交与下载，见[证明辅助验收](./Agent证明预览与登记确认验收-2026-10-09.md)。

从详情唤起时显示当前上下文卡，用户可清除或切换。服务端只信任业务标识并重新加载授权数据，不信任前端提供的用户身份和原状态。

展示四类信息：查询来源、执行步骤摘要、可编辑草稿、明确结果。写操作展示确认卡，时间和资源改变后重新确认，结果未知时提供核实状态而非重复提交按钮。

### 7.3 操作与异常

所有核心页面设计加载、空数据、失败、无权限、记录已取消/撤下及版本冲突状态。重复点击不产生重复记录；修改未保存时有退出提示；上传失败保留表单内容。

不将内部错误堆栈、模型原始工具参数或数据库字段当作面向用户的说明。

## 8. 原型优先顺序

1. P-W01 官网首页与 P-W03/P-W09 等典型二级页，先确定学校官网视觉方向。
2. P-U01、P-U02、P-U03，确定工作台和服务办理的统一结构。
3. P-U06 + P-S02/P-S03 + P-U15，验证活动联合申请及 Agent 流程。
4. P-T03/P-T04 与 P-U10/P-S06，验证资料权限、通知和调宿。
5. 其余页面复用已确定的交互模式，逐项完善数据与错误状态。

原型不需要把所有页面一次画完，但每个已纳入需求都必须能定位到页面入口或明确的后台运行流程。
