### F01：后加成员可以绕过原有排课／考试检查

复现步骤：建立 A、B 两个教学班，教师、原有学生和教室各不相同；安排两班在相同时间上课，并发布相同时间的考试；随后把 A 班学生加入 B 班。

实际结果：成员关联返回 HTTP 200；该学生查到 **2 条重叠课程、2 场同时考试**。安排分别使用演示日期 2026-11-15 和 2026-12-20，均在演示学期内。

证据：[AcademicService.relation](../backend/src/main/java/cn/zzuit/campus/teaching/AcademicService.java#L80)、[复现结果 JSON](../artifacts/audit-2026-10-06/backend-probes.json)、[复现脚本](../artifacts/audit-2026-10-06/backend-probes.ps1)。

### F02：上课与考试可以占用相同时间、场地和学生

在 A、B 班考试已发布的情况下，新建 C 班；C 班学生已有 B 班考试，同时在 A 班考场添加 C 班课程。

实际结果：课程新增返回 HTTP 200。课程与考试时间均为演示日期 2026-12-20 08:00—10:00，学生和考场占用均发生冲突。

原因：新增课程只查询 `teaching_lesson`；发布考试只查询 `academic_exam`。应结合两种安排判断资源占用，并沿用事务内的并发控制。

证据：[课程检查](../backend/src/main/java/cn/zzuit/campus/teaching/AcademicService.java#L100)、[考试检查](../backend/src/main/java/cn/zzuit/campus/teaching/AcademicService.java#L199)、[复现结果](../artifacts/audit-2026-10-06/backend-probes.json)。

## 3. 工程方面的不足

- **MySQL 尚未验证。** 本次重跑测试仍是 H2。Docker 引擎接口当前不可连接；还没有证明 MySQL 迁移、并发锁和字符排序行为一致。
- **浏览器回归未自动化。** 后端已有 20 项 HTTP 集成测试，前端有 lint 和类型／构建检查；没有独立前端业务测试及浏览器 E2E 流水线。本次发现的跨安排冲突和草稿丢失未被现有检查覆盖。
- **版本恢复基础不足。** 当前 main 没有提交记录，工程文件均未跟踪；尚无可用代码版本基线。数据库备份、恢复演练和部署回退也未形成可重复流程。
- **数据量增长后的容量需要验证。** 学期课表一次取全，部分列表没有分页；教学写操作共同锁一行，资料每个版本还会复制附件字节。这些设计适合当前小规模演示，扩大后需要测量并调整。
- **Three.js 构建警告仍在。** 已按路由独立加载，场景分块约 626 KB（gzip 约 163 KB）；警告本身不代表首屏无法使用，但移动设备帧率、内存和加载性能尚未测量。
- **运行观测仍薄。** 已有连接数据库的健康接口与服务错误日志，但没有统一请求跟踪、业务故障统计、告警和审计查询界面。
