### 1.3 Top 风险（完整列表见第六节）

**P0 阻断：0 项。** 当前源码可全量构建、测试全绿、主流程可演示。

**P1（建议交付/答辩前处理；第六节共 9 项，此处列 7 组重点）**

1. **交付文档系统性落后于代码**：README 写"V34 / 后端 522 / 前端 205"，交付总览写"V33 / 507 / 201"，实测为 **V36 / 547 / 211**；交付总览完全没有财务模块行；财务文档仍在描述已 `denyAll` 的 `/api/admin/payments` 与"管理员创建账单"。
2. **财务/缴费全链路被 `app.demo.enabled` 门控**：MySQL profile 默认 `DEMO_SEED_ENABLED=false`，此时全部财务端点返回 `DEMO_DISABLED`；建单只接受 `demo=TRUE` 学生。该模块只能称为"演示级闭环"，不能称为生产可用。
3. **MySQL 只验收到 V24**：V25–V36（含全部财务表、角色与约束）从未在 MySQL 执行；`backend/data/campus.mv.db` 仍停留在 10-12（约 V18），按 `Start-Backend.ps1` 启动会一次性补齐约 18 个版本，升级路径无自动化覆盖。
4. **备份/恢复未实现**（需求 AC-O02 未关闭）：无脚本、无接口、无独立环境恢复演练。
5. **角色分工缺口**：内容编辑/审核岗位无工作台空间、无交接与责任异常覆盖；`SERVICE_STAFF` 仅有 `workbench:read`+`agent:query`，需求文档给它的职责在代码中未落地。
6. **数据暴露风险**：`GET /api/reservations/venues`、`/venues/{id}`、`/venues/{id}/schedule`、`POST /api/reservations/check-conflict` 无 URL 与服务层权限校验，任意登录账号可读取全量资源目录及他人已批准/使用中预约的活动主题与时段。
7. **交付证据缺口**：浏览器实机、真实支付宝沙箱、真实 DeepSeek 评测、MySQL 当前版本均未在本次复验范围内；第三批界面浏览器验收仍为空白。

### 3.4 新增范围：缴费与财务（V34–V36，超出需求 v0.2 原范围）

需求规格 v0.2 第 12 节明确把"支付"列为范围外/扩展项；当前代码已新增演示缴费与财务工作流，属于**主动扩展范围**，需要在论文/答辩中单列说明。

**已实现（演示级闭环，40 项后端测试）**

- 数据与权限：V34 账单、V35 八类收费分类、V36 收费标准/收费依据/作废减免退款申请/历史/提醒/对账预览，新增 7 张财务表、2 个财务角色、3 个财务权限。
- 角色分工：`FINANCE_OPERATOR` 经办（标准/账单/催缴/查单/统计），`FINANCE_REVIEWER` 独立复核（标准/账单/作废/减免/退款），禁止自审，禁止无其他有效复核人时提交，财务经办与业务收费依据岗位（教务/宿管/后勤）分离。
- 学生侧：`/portal/payments` 缴费大厅、分类筛选、账单详情、发起支付；双通道（ijpay 进程内电脑网站支付 / remote 独立 pay-service 扫码）；回调 RSA2 验签 + 金额/单号/状态匹配 + 幂等确认；refund 申请、收据 PDF、3 秒轮询。
- 财务侧：`/finance/payments` 台账、建单/批量建单、提交/复核/发布、作废/减免/退款申请与执行、CSV 导出、对账预览。
- pay-service：独立 Spring Boot 3.5 服务，HMAC-SHA256 内部鉴权、幂等建单、查单/关单/退款、异步通知验签；15 项测试通过。

**限制与缺口（不能宣称"生产可用"）**

1. **demo 门控**：全部财务接口经 `PaymentService.requireDemo()`，`app.demo.enabled=false`（mysql profile 默认）时返回 403 `DEMO_DISABLED`；建单/收费依据还要求目标学生 `demo=TRUE`。
2. **对账仅只读预览**：`POST /api/finance/payments/reconciliation/preview` 比较 CSV 与本地账单，返回差异统计与明细，不落库、不入账、无差异处置流程；前端明确提示"不会把账单标记为已支付"。文档称"对账未实现"已属过时，但"对账闭环"仍未完成。
3. **ijpay 通道限制**：已发起支付的账单不能关单，不能走作废/减免，只能退款；remote 通道支持 close。
4. **无独立财务报表**：仅台账 summary + CSV 导出，无按分类/账期/月份的报表。
5. **MySQL 未验证**：V34–V36 的建表、外键、约束、角色种子从未在 MySQL 执行。
6. **真实沙箱未验**：支付宝沙箱账号、真实下单/收银/异步通知、pay-service 线上域名（文档声称已部署）均不在本次可验证范围。

### 4.6 角色分工完整性结论

**成立的部分**

1. **动作权限与数据范围分离**：14 角色、27 权限、4 张范围关系表 + 组织归属，业务判断遵循"有效账号 ∧ 有效岗位 ∧ 动作权限 ∧ 范围 ∧ 状态 ∧ 不自审"。
2. **自审禁止 7 类业务后端均有拦截**，不是仅靠前端隐藏按钮。
3. **交接与责任异常已从"逐业务散点"收敛为统一服务**，覆盖 8 类岗位，普通停用/撤权有影响预览，紧急停用立即失效。
4. **工作台任务与业务队列同源**：10 个来源、来源失败可见、任务可跳详情，避免"菜单有入口但没有任务"。
5. **财务双岗（经办/复核）引入后仍保持"财务不继承 ADMIN、ADMIN 不能操作财务"**，符合职责分离方向。
