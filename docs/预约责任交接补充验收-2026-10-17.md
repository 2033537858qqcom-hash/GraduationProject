# 预约责任交接补充验收

日期：2026-10-17。对应[角色职责与任务流转审查](./角色职责与任务流转审查及整改方案-2026-10-17.md)中的预约审批、兼岗待办和责任移交问题。

## 本次范围

当前工程已包含场地负责关系、禁止自审、资源配置页面、多工作空间及统一待办。本次检查这些改动的边界，继续修复预约申请的流转缺口。未更改已执行的迁移文件，未修改主业务数据库，也未调整真实账号授权。

| 检查点 | 现在的处理方式 |
| --- | --- |
| 只有申请人本人具备该资源审批资格 | 提交返回 `NO_VENUE_REVIEWER`，草稿、版本及历史保留；需配置其他有效审批人 |
| 兼岗人员本人提交申请 | 从审批列表的 SQL 条件中排除本人，数量、分页、工作台和复用该查询的统计保持同一范围；仍禁止自审 |
| 同一个审批人通过多个角色取得相同权限 | 每位负责人仅路由一份通知，不按角色重复发送 |
| 解除负责人会留下无人可审的待审申请 | 返回 `REVIEWER_HANDOFF_REQUIRED`，保留原关系；先添加接任人员，再解除原负责人。其他候选人必须启用、具有审批权限且不是申请人 |
| 添加接任人员 | 将该资源已有待审申请通知给新负责人，排除其本人申请；重复添加不重复通知 |
| 审批通过后用原请求标识重新提交、改时间 | 返回 `RESERVATION_IMMUTABLE`，不覆盖已批准记录与处理历史；草稿和退回申请可继续提交 |
| 申请权限已被撤销后取消申请 | 后端重新校验取消动作权限，不因“曾经是申请人”继续放行动作；写操作等待锁后再检查有效权限 |
| 审批人账号停用或岗位权限撤销 | 撤权继续有效；资源配置页显示失效负责人、有效人数、待审数及无人可审数，业务管理人员可添加接任者。该配置页不因此获得申请详情权限 |
| 重启本地演示环境 | 不恢复已解除的负责关系；仅在首次创建演示事务账号时初始化示例负责关系 |

初次创建的演示批准记录由演示事务人员署名，既有历史记录不改写。资源负责人配置错误直接显示在当前弹层中，方便用户完成接任配置。

同时修正管理页登录回跳的标签优先级，以及修改资料时先读取目标详情再打开表单，避免沿用上一个选中申请。审批动作按当前申请归属和业务标签展示。修复了通用选择控件和工作台响应的已有 `any` 类型检查错误，保持选择值类型约束。

## 后续仍需解决

1. 资源岗位仍复用既有权限组合，尚未新增独立的资源管理任职模板；工作空间切换也不等于独立的后端授权身份。
2. 账号紧急停用后的无人可审问题目前由资源配置页展示和接任通知处理，尚无全域异常责任队列、自动代办或到期移交。
3. 设备的实际发放、归还、验收，以及教学教室与预约资源的物理空间映射，尚未形成完整闭环。
4. 教务跨学院授权、教师录分与教务复核等深化事项继续按原整改方案推进，不能据此宣布所有角色分工问题已完成。

上述分工是毕业设计的实现方案，不代表学校已确认的实际业务制度。
