# 高校官网调研与栏目建议 v0.1

调研日期：2026-09-30。

目的：依据实际高校官网，修正此前偏重新闻、校园风采和服务入口的官网定位。本文区分观察事实与项目建议；建议尚未全部纳入正式功能编号。

## 1. 调研来源与实际观察

### 清华大学

主站围绕学校介绍、院系、人才培养、学术研究、招生及就业、合作和校园生活组织导航。首页还展示科研动态、专题和校园活动；辅助入口指向访客、校友、内网、邮箱等不同内容或系统。

来源：[清华大学官网](https://www.tsinghua.edu.cn/)。

学校介绍进一步细分历史、领导、机构与统计；人才培养栏目覆盖师资和不同教育层次；招生栏目区分不同学生群体。

来源：[学校概况](https://www.tsinghua.edu.cn/xxgk.htm)、[教育教学](https://www.tsinghua.edu.cn/jyjx.htm)、[招生就业](https://www.tsinghua.edu.cn/zsjy.htm)。

### 北京大学

主站提供学校、招生、院系、教学、科研、交流及校园生活相关栏目，另设学生、教职工、校友和访客等入口。主站导航中的“门户”指向独立的门户地址。

来源：[北京大学官网](https://www.pku.edu.cn/)。

“学生”入口本身是一页公开的信息导航，把学习、通知和工具分类组织；选课及成绩单申办等工具通过链接进入门户。说明面向某类人群的公开介绍页，与需要身份验证的业务系统可以分开。

来源：[北京大学学生入口](https://www.pku.edu.cn/home/student.html)。

### 深圳大学

官网组织了学校介绍、院系机构、师资、培养、研究、交流、招生就业和校园生活内容。另设学生、教工、校友、考生、访客入口，以及内部网、图书馆、办事大厅等链接。首页有新闻、公告、媒体报道、研究动态及校园生活内容。

来源：[深圳大学官网](https://www.szu.edu.cn/)。

### 调研限制

本次根据上述官方网页的公开内容与链接结构分析栏目和访问入口，没有登录其内部系统，也没有核验其内部权限实现。浙江大学主站未返回可供本次分析的正文，上海交通大学主站抓取超时，二者不作为结论依据。

## 2. 对现有方案的判断

以下为基于调研的设计判断：

1. 现有官网缺少院系、专业、教学、师资、科研、招生和交流信息，难以完整呈现大学的办学体系。
2. 仅提供首页、资讯、活动和场景探索，容易成为校园宣传页面，缺少可持续访问的二级栏目。
3. 人群入口有价值：考生关注专业和报考资料，访客关注地址与校园，师生关注系统入口，信息需求不同。
4. 完整栏目与精简首页可以同时成立。首页精选内容，主要导航和二级页面承担完整信息。
5. 公开校历、校园地图、办事说明可以是公共信息；个人课表、申请记录、预约库存等属于登录后业务数据。公开信息与个人事务应分别定义。
6. 有科研介绍不等于建设科研项目管理系统；有招生信息不等于建设录取系统。展示范围和业务办理范围分别确定。

## 3. 官网导航建议

主导航建议为以下八类，新闻通过首页专区及栏目入口进入。具体导航密度在桌面与移动端原型中验证。

| 一级栏目 | 二级内容建议 | 项目实现深度 |
| --- | --- | --- |
| 学校概况 | 学校简介、历史沿革、校训与标识、现任领导、机构、基本数据 | 独立页面与后台内容维护 |
| 院系与专业 | 学院目录、学院简介、本科专业、专业培养方向 | 结构化学院及专业目录，不建设独立学院站群 |
| 教育教学 | 人才培养、本科教育、师资风采、教学成果与特色课程 | 教育介绍与公开资料，不扩展选课成绩业务 |
| 科学研究 | 研究方向、实验室、成果、学术讲座 | 公开研究内容与专题，不扩展科研经费审批 |
| 招生与就业 | 招生介绍、报考指南、专业资料、公开招生通知、就业服务介绍 | 可发布查询的演示资料，不开展真实录取与招聘交易 |
| 合作交流 | 校企合作、交流项目、合作动态 | 介绍与内容列表，不扩展出国审批 |
| 校园生活 | 校园风光、社团文化、体育艺术、图书馆、生活设施、3D 探索 | 展示与导航，报名预约仍进入登录系统 |
| 信息公开 | 学校章程、公开规章、公开报告、联系方式 | 标注的演示文档与内容发布，不使用真实学校文件冒充本校制度 |

公共新闻体系建议区分校园要闻、通知公告、教学动态、科研动态、人物故事和专题。内容分类与导航栏目可以关联，避免一篇内容重复录入。

## 4. 首页建议

首页保持选择性展示，不把八类栏目内容全部展开。

1. 顶部身份与工具导航：考生、学生、教职工、校友、访客，搜索及校园服务。
2. 学校标识与主导航：统一学校视觉与二级菜单。
3. 主视觉：校园景观、重要专题或学校故事。
4. 校园要闻：一条重点新闻和少量其他新闻。
5. 通知与学术信息：精选公开通知、近期讲座或展览。
6. 办学特色专区：教学或研究内容精选，可按内容运营切换。
7. 校园生活：人物与文化内容，校园探索入口。
8. 页脚：地址、联系渠道、版权、校历、地图、公开信息及有效链接。

首页不要求独立展示大段学校简介，简介放到学校概况页；首页可用简短定位文案与少量公开办学数据辅助表达。数字必须来自明确的虚构校园设定并标明演示性质。

可用同一内容模型支持不同列表、专题和首页精选，后台管理发布范围与推荐位置。不要将“首页模块多”作为官网完整性的验收指标。

## 5. 人群入口与业务系统

| 人群入口 | 可公开展示 | 登录后的功能 |
| --- | --- | --- |
| 考生 | 学校、学院专业、报考指南与公开通知 | 首期不建设考生账号及招生办理 |
| 学生 | 学习资源介绍、校园生活、常用服务说明 | 学生工作台、报名、预约、办事、报修、个人日程、Agent |
| 教职工 | 教学科研介绍、学校公开制度、服务说明 | 教师工作台及授权管理任务 |
| 校友 | 校友故事、校友活动、联络介绍 | 首期不建设校友认证与捐赠业务 |
| 访客 | 校园地址、交通、地图、公开开放说明 | 首期不建设访客入校审批 |

人群入口是信息组织方式，不表示点击后必须取得对应身份。进入业务页面与调用接口必须经过真实登录及权限判断；不提供匿名 Agent。

官网与工作台可以共享建筑、学院及公开活动标识，但返回不同的公开视图和业务视图。例如公开建筑介绍不包含实时预约库存，公开活动介绍不包含报名者名单。

## 6. Three.js 定位

Three.js 是项目的设计选择，不是上述高校官网必备能力。

- 在“校园生活 / 校园探索”提供完整的风格化校园场景，建筑点击关联介绍、学院或场馆资料。
- 首页是否使用轻量 3D 主视觉由原型和性能验证决定，保留图片展示方案。
- 不使浏览学校信息依赖 3D 操作；提供对应文字目录、移动端回退和低画质模式。
- 官网场景只展示校园信息，预约等办理行为进入登录后的系统。

## 7. 对后台需求的补充建议

目前后台不能仅管理新闻与首页推荐，还应支持：

- 栏目、菜单、静态页面、内容分类与专题。
- 学校介绍、领导与机构资料、学院与专业目录。
- 师资、实验室、教学科研成果等公开展示资料。
- 招生就业与合作交流资料、公开文档及有效链接。
- 首页推荐、排序、发布时间、撤下、内容版本及操作记录。
- 文字与图片的替代说明、链接有效性、未发布内容预览。

后台无需分别为每个栏目建设复杂审批流程，可共用内容草稿、审核发布和撤下能力；结构化目录单独维护其关系。

## 8. 后续需求修订

建议以本文为依据扩展官网需求，保留现有登录后业务与 Agent 主线：

1. 完整官网信息架构及页面树。
2. 明确公开内容与内部信息的字段级展示规则。
3. 新增内容运营及学院专业等目录维护需求。
4. 制定虚构校园资料设定，防止不同页面的数据相互矛盾。
5. 官网首页与关键二级页原型，再进入实体与接口设计。

本文中的招生、科研、校友等栏目建议只增加信息展示和内容管理，并不自动将相应完整业务系统纳入项目范围。
